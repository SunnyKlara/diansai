# 适配 · RoboMaster 机甲大师赛

> RM 是工程量最大、子系统最多的比赛之一。本框架对 RM 的价值在于"把整支战队的资产沉淀下来"，避免每年换届就清零。

---

## 1. 与电赛的核心差异

| 维度 | 电赛 | RoboMaster |
|---|---|---|
| 周期 | 4 天 | 全年（联盟赛 + 区域赛 + 总决赛） |
| 输出物 | 1 个原型 | 7 类兵种 × N 套迭代 |
| 队伍 | 2~3 人 | 30~80 人，细分多组 |
| 代码量 | 几千行 | 几十万行（含视觉算法） |
| 战略 | 单一指标 | 多兵种协同 + 资金运营 |

但底层规律完全一致：**每个兵种 = 一道"赛题"，每年规则更新 = 新一届赛题**，所以六件套结构完全适用。

## 4. 量化指标（RM 特化）

| 指标 | 目标 | 测量方法 |
|---|---|---|
| 自瞄命中率 @5m | > 80% | 静靶 100 发 |
| 自瞄延迟（图像→开火） | < 80ms | 时间戳差 |
| 云台跟随误差 | < 0.3° | IMU 数据 |
| 底盘最大速度 | > 3 m/s | 编码器实测 |
| 能量机关激活时间 | < 5s | 视频打点 |
| 裁判系统通信丢包率 | < 0.1% | UART 监听 |

## 5. RM 特有的"传承件"

电赛仓库没有的、RM 必须加的：

- **战队 Wiki**：`C_通用能力/战队管理与传承/` 下放新人入门、历届心得
- **维修手册**：每个兵种 `04_调试记录/维修手册.md`，含常见故障树
- **赛场视频归档**：每场比赛录像 + 复盘标注（git lfs 或对象存储）
- **零件库存系统**：`D_物资准备/库存.csv`（建议接 Notion / 飞书表格）

## 6. AI 协作的 RM 特化指令

加到 steering 末尾：

```markdown
## RM 特化规则

- 视觉算法所有改动必须附带"测试视频前后对比"，存到 `04_调试记录/视觉对比/`
- 弹道相关参数（射速、补偿系数）改动必须 commit message 带 `[ballistic]` 标签
- 裁判系统协议解析代码改动必须双人 review（PR 标签 `referee-system`）
- 跨兵种修改（影响多个机器人）禁止直接合 main，必须开 RFC 文档放 `备赛系统/RFC/`
```
