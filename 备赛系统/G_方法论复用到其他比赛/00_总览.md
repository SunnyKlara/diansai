# 方法论复用到其他比赛 · 总览

> 这一套打法不是电赛专属。本目录把电赛备赛仓库沉淀下来的"工程化刷题 + AI 协作 + 必备六件套"抽成与赛题无关的通用框架，复制即可移植到智能车、RoboMaster、ICPC、数学建模、Kaggle、嵌入式邀请赛、机器人创新赛等任何"以队伍为单位、以赛题为单元"的比赛。

---

## 0. 一句话定位

**任何"以题目/任务为单元的比赛"都可以套这个壳：**

```
比赛仓库/
├── 赛题/                # 官方原题（只读）
├── 24/ 23/ 22/ ...      # 历史工程参考（只读）
└── 备赛系统/            # 你和队伍真正干活的地方
    ├── A_方向训练/      # 按"技术方向"组织的能力建设
    ├── B_历年真题实战/  # 按"年份/赛题"组织的实战训练
    ├── C_通用能力/      # 跨方向都要掌握的基础能力
    ├── D_物资准备/      # 硬件/环境/账号清单（软件比赛可裁剪）
    ├── E_赛场实战/      # 比赛当天的流程、模板、检查清单
    ├── F_刷题网页/      # 可视化看板与题目浏览器（可选）
    └── G_方法论复用到其他比赛/   # 你正在看的元资产
```

只要你的比赛符合下面任意一条，就能套：

- 多年真题、官方公布过题目
- 队伍 2~5 人、赛程数天到数月
- 输出物里有"代码 + 报告/答辩 PPT + 实物/答案"任意组合
- 经常出现"赛前不知道考啥，赛后才发现踩坑"

## 1. 五条不可妥协的核心原则

这五条是把"乱糟糟的备赛"变成"可继承资产"的关键：

| # | 原则 | 翻译 |
|---|---|---|
| 1 | **结构先于内容** | 先把空骨架挖好（六件套占位文件），再往里灌内容 |
| 2 | **审题先于动手** | 任何新赛题先产出 `00_深度审题与方案论证.md`，禁止跳过 |
| 3 | **代码分层** | Core / Drivers / Algorithm（或对应抽象层）严格分离，可平移 |
| 4 | **量化指标驱动** | 每题都要有"指标 → 测试方法 → 实测数据"三件套，不能只描述功能 |
| 5 | **AI 自主执行** | 给 AI 一份 steering（强制规则），让它自己干，不问就是默认继续 |

第 5 条看似奇怪，但实测下来是把"备赛"做成"批处理"的关键：你定一次规矩，AI 把 N 道题一次性铺完。

## 2. 必备六件套（任何赛题都补齐这六个文件就算"完成"）

```
<赛题目录>/
├── 00_深度审题与方案论证.md   ← 审题 + 多方案对比 + 评审打分
├── 01_代码/                   ← 工程代码（含 README.md）
│   ├── Core/                    # 业务/主循环（或软件比赛的入口）
│   ├── Drivers/                 # 硬件抽象 / I/O 适配
│   ├── Algorithm/               # 与硬件无关的纯算法
│   └── README.md                # 编译/运行/烧录说明
├── 02_硬件/                   ← 原理图、PCB、BOM（软件比赛改名为"环境/依赖"）
│   └── 材料清单_BOM.md
├── 03_报告/                   ← 设计报告（八段式）/ 答辩稿 / 论文
│   └── 设计报告.md
├── 04_调试记录/               ← 调试检查清单 + 独到经验总结
│   ├── 调试检查清单.md
│   └── 独到经验总结.md
└── 00_题目原件.md             ← 官方原题文本（去除版权敏感图）
```

**完成的判定标准（验收契约）**：

- 六件套文件都存在，不是空的
- `01_代码/` 能编译通过，`getDiagnostics` 0 错误（或对应语言的等价静态检查）
- `00_深度审题与方案论证.md` 有≥2 个候选方案 + 量化打分表
- `04_调试记录/独到经验总结.md` 至少 3 条具体的、别人能用的踩坑

**为啥强制六件套**：
- 比赛实物会带回学校，但**没人看得懂当年是怎么调通的**——经验总结就是给学弟学妹的火种
- 评审报告占总分 15%~25%（电赛 20/120、智能车技术报告 15%、数模论文 100%），不能临时写
- 上岸的队伍和炮灰的队伍差距，不是赛场那 4 天，是赛前 100 天的"沉淀习惯"

## 4. 30 秒快速上手新比赛

```text
1. 复制本仓库 → 改名为 "<比赛名>备赛仓库"
2. 删除 24/ 和 备赛系统/B_历年真题实战/ 里的电赛内容（保留目录骨架）
3. 把 G_方法论复用到其他比赛/02_通用steering模板.md 复制到
   .kiro/steering/<比赛名>仓库规范.md，按提示替换 6 处占位
4. 跑 scaffold/init_repo.bat --year 2024 --problem A_xxx
   → 自动生成空的六件套
5. 把官方真题 PDF 转 markdown 塞到 00_题目原件.md
6. 跟 AI 说："开始做 2024 A 题" → AI 会自动按六件套铺开
```

完事。

## 5. 为什么这套能复用

电赛、智能车、RoboMaster 表面差异巨大（4 天 vs 半年、单板 vs 整车、嵌入式 vs 视觉），但深层结构完全一致：

| 共通要素 | 电赛 | 智能车 | RoboMaster | ICPC | 数模 |
|---|---|---|---|---|---|
| 题目文本 | ✅ PDF | ✅ 规则手册 | ✅ 规则书 | ✅ 题面 | ✅ 题目 |
| 多年真题 | ✅ | ✅ | ✅ | ✅ | ✅ |
| 量化指标 | 误差/精度 | 圈速/通过率 | 击打数/血量 | AC/WA | 评分公式 |
| 报告产出 | 设计报告 | 技术报告 | 答辩 PPT | 题解 | 论文 |
| 队伍协作 | 2~3 人 | 5~10 人 | 兵种小组 | 3 人 | 3 人 |
| AI 协作机会 | 高 | 高 | 中 | 中（受限） | 极高 |

只要承认"题目—方案—代码—测试—报告—复盘"是普适闭环，本框架就成立。
