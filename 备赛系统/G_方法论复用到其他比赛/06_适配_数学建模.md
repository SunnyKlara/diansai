# 适配 · 数学建模（国赛 / 美赛）

> 数学建模是本框架"最容易复用"的场景：周期短、有题、有论文、有 AI 协作空间，几乎和电赛 1:1 对应。

---

## 1. 与电赛的核心差异

| 维度 | 电赛 | 数模 |
|---|---|---|
| 周期 | 4 天 3 夜 | 国赛 3 天 / 美赛 4 天 |
| 输出物 | 实物 + 报告 | **论文（唯一交付）** |
| 工具 | 电烙铁 + IDE | LaTeX + Python/MATLAB |
| 评分 | 完赛 + 创新 + 报告 | 全在论文里 |
| 队伍 | 2~3 人（硬件/软件/报告） | 3 人（建模/编程/写作） |

数模的"硬件 BOM"几乎不存在，但"环境 + 数据集"必须严格管理，所以六件套依然成立。

## 4. 量化指标（数模特化）

数模没有 OJ，但论文评分有非常明确的量化项：

| 指标 | 目标 | 自检方法 |
|---|---|---|
| 摘要含数字结论 | ≥ 4 个具体数字 | 自查 |
| 模型公式数量 | ≥ 10 个有意义的公式 | 自查 |
| 图表数量 | 15~25 张（多反而扣分） | 自查 |
| 灵敏度分析章节 | 必有 | checklist |
| 模型优缺点章节 | 必有 | checklist |
| 论文页数 | 国赛 ≤ 25 页正文 / 美赛 25 页 | 自查 |
| 代码可复现性 | 一键跑出论文中所有数字 | 队友盲跑 |

## 5. AI 协作的数模特化指令

加到 steering：

```markdown
## 数模特化规则

- 任何模型都必须有"理论依据"（参考文献链接）+ "代码实现" + "结果验证"三件套
- 论文中出现的每一张图表必须能用代码重新生成（保证可复现）
- AI 写代码时强制使用 `numpy + pandas + matplotlib + scipy + sklearn` 优先，避免冷门包
- LaTeX 编译报错 AI 自己修，不停下等问
- 摘要必须包含至少 4 个具体数字结论，否则论文不算完成
- 灵敏度分析必须做（每个关键参数 ±10% 的影响）
```

## 6. 时间分配模板（3 天国赛）

```
Day 1 (24h)
  0-2h    选题（A/B/C 至少花 2 小时讨论再定）
  2-6h    深度审题，写 00_深度审题与方案论证.md
  6-12h   小问 1 建模 + 编码
  12-24h  小问 1 完整跑通 + 出图

Day 2 (24h)
  0-12h   小问 2、3 建模与求解
  12-20h  灵敏度 + 稳健性
  20-24h  论文初稿框架 + 摘要 v1

Day 3 (24h)
  0-12h   论文写作（队友盲读、提意见、改）
  12-20h  补创新点 + 优缺点 + 推广
  20-22h  终稿 + 摘要 v3
  22-24h  PDF 检查 + 提交（提前 2 小时锁稿）
```
