## 想象一个场景

你戴着一副刚买的入门级蓝牙耳机，听到熟悉的钢琴曲。低音浑厚，高音清亮——刚开声那一刻，你觉得 200 块花得值。

把音量旋到 80%。变化来了——钢琴的高音里开始混进一种**毛糙感**，像有人在你耳边搓砂纸；低音也变浑了，鼓点的边缘开始'糊'。再调到 95%——整副耳机的声音都'变形'了，像是被人用蜡纸隔了一层。

你打开手机的频谱分析 APP 一看——**钢琴信号本应只有一根 261.6Hz 的基频（中央 C）**，结果屏幕上密密麻麻冒出来七八根尖峰：523Hz、785Hz、1047Hz、1308Hz、1570Hz……一根接一根，每一根都是基频的整数倍。

这些不该出现的尖峰有个专业名字——**谐波（Harmonic）**。它们叠在原本干净的正弦波上，**让钢琴变成了'电锯'**。

而把这些'多余的谐波能量'除以'基波能量'，就得到了一个名字非常吓人的指标——**THD（Total Harmonic Distortion，总谐波失真度）**。

| 应用场景 | THD 要求 | 谁在用 |
|---|---|---|
| 录音棚母带处理 | < 0.0005% | 索尼、环球音乐 |
| Hi-Fi 顶级功放 | < 0.005% | 麦景图、马兰士 Reference |
| 家用 5.1 功放 | < 0.05% | 安桥、雅马哈 |
| 蓝牙耳机（高端） | < 0.5% | AirPods Pro、Sony XM5 |
| 蓝牙耳机（入门） | 1%~5% | 200 元以下产品 |
| 你听到刺耳的临界点 | **5%** | 人耳能明显感知 |
| 失败品 | > 10% | 已经变成噪声 |

**人耳对 5% THD 的感知有多敏锐**？做个实验：在录音里人为加上 5% 的二次谐波——**99% 的听众会立刻说'声音怪怪的'**。

但你怎么测出 THD 是 1% 还是 5%？耳朵不行，**它只能告诉你'好听 / 不好听'**。你需要一台仪器——**给它喂一段周期信号，它告诉你 THD 是百分之几**。

这就是 2021 年电赛 A 题让你做的设备：**信号失真度测量装置**。

> **想象一下**：你是一家声学实验室的质检员。流水线下来一批耳机，每副都要测 THD。**专业仪器** Audio Precision APx515 摆在你左手边，**11 万人民币**一台；你右手边，是你电赛带来的那台用 200 元元件焊出来的小盒子。**两台仪器同时测一副耳机**——APx515 报 1.27%，你的小盒子报 1.31%。**误差 0.04%**——你赢了，老板请你吃了顿火锅。

这种'用便宜单片机替代 11 万元仪器'的故事，在电赛历史上反复出现。**2021 A 是这套故事的精华版**——题目把仪器的核心功能（采样、FFT、谐波分析、显示、远程交互）全压缩进 4 天 3 夜，让你做出一台 200 元的'迷你 APx515'。

## 这题在做的事，其实是把 ADC 用到极致

把图 1 简化一下：

```
函数发生器 ──[同轴线]── BNC 接口
                         │
                         ▼
                  [ADC 调理电路]
                         │
                         ▼
                  TI MCU + 片内 ADC
                  ├── FFT 算谐波
                  ├── 算 THD
                  └── 显示 + 通信
                         │
              ┌──────────┴──────────┐
              ▼                     ▼
          本机 LCD 屏           蓝牙 / WiFi 模块
                                    │
                                    ▼
                                 安卓手机 APP
```

**输入端**：函数发生器（你自带，比如 Tektronix AFG31000，售价约 5000 元）输出一个**已知 THD 的周期信号**——发生器自带'谐波合成'功能，能输出'基波 + 二次谐波 + 三次谐波……'这种自定义信号。**信号是你的'已知答案'，用来校验装置准不准**。

**装置端**：核心是一颗 TI MCU + 它的片内 ADC。MCU 把模拟信号采样、做 FFT、算 THD、显示。

**输出端**：本机 LCD 显示数字 + 波形 + 谐波柱状图；同时通过蓝牙发到手机 APP。

**全题灵魂在 ADC 那一步**——**怎么用一颗便宜的 12~14 位 ADC，测出小数点后 1 位的 THD**？

这个问题展开来有四个子问题，每一个都是一个'谜'：

1. **采样率怎么定**？信号频率从 1kHz 跨到 100kHz，差 100 倍，ADC 跟得上吗？
2. **量程怎么定**？信号峰峰值从 30mV 跨到 600mV，差 20 倍，ADC 分辨率够吗？
3. **FFT 怎么做**？1024 点够不够？要不要加窗？怎么避免频谱泄漏？
4. **精度怎么校**？片内 ADC 标称 ±2% 误差，怎么压到 ±1%？

> **小白补课**：
> - **ADC（Analog-to-Digital Converter）**：模数转换器，把'连续变化的电压信号'变成'离散的数字'。位数越高分得越细——12 位能区分 4096 个电压等级，14 位 16384 个，16 位 65536 个，24 位 16,777,216 个。**位数每加 1 位，精度提升一倍**。
> - **片内 ADC vs 片外 ADC**：片内 ADC 是 MCU 集成在芯片里的，**便宜、好用、但精度受限**（一般 12~14 位）；片外 ADC 是独立芯片，**贵、需要外围电路、但精度高**（典型 16~24 位）。本题强制用片内。

这道题在做的事，**用一句话就是**——**把一颗 12~14 位的便宜 ADC，通过软件算法'拔'到等效 16~18 位的精度**。怎么拔？答案藏在下面四个谜里。


## 第一个谜：怎么让 ADC 跟上 5 次谐波 × 100kHz 信号

题目最大的'隐藏陷阱'藏在发挥 (1)(2) 里——

> 输入信号的峰峰值电压范围：30mV ~ 600mV  
> 输入信号基频范围：**1kHz ~ 100kHz**

基频从 1kHz 拉到 100kHz——**100 倍频率范围**。再加上要测**到 5 次谐波**——

```
最高信号频率 = 5 × 100kHz = 500kHz
```

**翻译过来就是**——**你的 ADC 要能采到 500kHz 的信号**。

按**奈奎斯特采样定理**——

```
采样率 ≥ 2 × 信号最高频率 = 1MSPS
```

**这个式子说的其实是**——'**要想还原一个频率为 f 的信号，每秒钟必须至少采它 2f 次**'。**最低采样率是 1MSPS（每秒 100 万个采样点）**。

但 1MSPS 是'**最低**'——工程上一般要留 **2~5 倍余量**：

```
工程采样率 = 2~5 × 1MSPS = 2~5 MSPS
```

> **小白补课**：
> - **MSPS（Mega Samples Per Second）**：每秒百万次采样。1MSPS = 1 微秒采一个点。
> - **奈奎斯特定理为什么是'2 倍'**？因为一个完整的正弦周期里，**至少要采到一个'波峰'和一个'波谷'**才能确定这个正弦的频率和幅度——这意味着每个周期至少 2 个采样点。但实际上 2 倍是数学下限，工程上要 4~10 倍才稳。
> - **混叠（Aliasing）**：采样率不够时，**高频信号会被'伪装'成低频信号**。比如你用 100SPS 采 60Hz 的信号——理论上应该需要 120SPS 以上——结果你采到的是一个'40Hz 的假信号'。用打车比喻：**车轮转得太快，肉眼看就像在倒转**——这就是混叠。

**那 TI 单片机的 ADC 跟得上吗**？

来看 2021 年电赛常用的几颗 TI MCU：

| 型号 | ADC 位数 | 最大采样率 | 价格 | 适合场景 |
|---|---|---|---|---|
| MSP430F471xx | 12 / 16 位 | 200 kSPS | 30 元 | **不够** |
| MSP432P401R | 14 位 | 1 MSPS | 60 元 | **勉强够** |
| TM4C123GH6PM | 12 位 | 1 MSPS | 50 元 | **勉强够** |
| TM4C1294 | 12 位 | 2 MSPS | 80 元 | **舒适** |
| F28379D（C2000） | 12 位 | 3.5 MSPS | 120 元 | **奢华** |
| **MSPM0G3507**（2024 后） | **12 位** | **4 MSPS** | **40 元** | **国一标配** |

2021 年最优选择是 **MSP432P401R**——14 位 1MSPS，**位数高**（量化更细）+ **采样率刚够**。

但 MSP432 1MSPS 用在 100kHz 信号上**只有 2 倍余量**——边缘情况下会出问题。**国一队伍当年选 TM4C1294 或者 F28379D**——2~3.5MSPS 的余量大幅提升精度。

**第一笔账：DMA 必须用上**

1MSPS = **每微秒采一个点**。MCU 主频 80MHz 意味着每微秒只能跑 80 条指令——**如果每个采样点都要 CPU 取数 + 存到数组**，根本来不及。

对策：**DMA（Direct Memory Access，直接内存访问）**。

> **小白补课：DMA 是什么**
> 把 ADC 想象成一个'**水龙头**'——每微秒滴一滴水（一个采样值）。如果你让 CPU 每滴水都去接，CPU 就废了——**接水占满了 CPU，没法做别的事**。
> DMA 就是一个'**专职接水机器人**'——你告诉它'把水接到这个桶（内存数组）里，接满 1024 滴你叫我一声'。**机器人独立工作，CPU 完全不参与**。等 1024 个采样点都到位了，CPU 才被叫醒，一次性处理 1024 点。
> **CPU 利用率从 100% 降到 < 1%**——这就是 DMA 的魔力。

伪代码：

```c
// 1. 配置 ADC 触发模式（定时器自动触发，每 1us 采一次）
ADC_setSampleTimer(ADC_TIMER_USEC(1));

// 2. 配置 DMA：ADC → memory
DMA_setSource(ADC_DATA_REG);
DMA_setDestination(adc_buffer);  // 1024 字的数组
DMA_setLength(1024);
DMA_setMode(DMA_BURST_BLOCK);
DMA_enable();

// 3. 等 DMA 完成中断
while (1) {
    if (dma_complete_flag) {
        compute_fft(adc_buffer);   // 1024 点 FFT，约 1.5 ms
        compute_thd();             // 谐波幅度计算，约 0.1 ms
        update_lcd();              // 显示更新，约 5 ms
        send_bluetooth();          // 蓝牙传输，约 100 ms
        dma_complete_flag = 0;
        DMA_enable();              // 重新启动下一次采样
    }
    __WFI();   // 没事就睡觉，等中断
}
```

**这段代码说的其实是**——**采样和处理是流水线**：DMA 在采下一批 1024 点的同时，CPU 在处理上一批的 1024 点。**两个动作并行，互不干扰**。

时间分布：

| 步骤 | 耗时 | 占用 |
|---|---|---|
| ADC 采 1024 点 | 1.024 ms | DMA |
| FFT 1024 点 | 1.5 ms | CPU |
| THD 计算 | 0.1 ms | CPU |
| LCD 更新 | 5 ms | CPU |
| 蓝牙传输 | 100 ms | UART + 蓝牙 |
| **单次完整测量** | **107.6 ms** | |

题目要求 10 秒以内——**107.6ms 远低于 10 秒**——**满分稳拿**。

**第二笔账：整周期采样**

做 FFT 时有个隐藏的'诅咒'——**频谱泄漏（Spectral Leakage）**。

设你采 1024 个点，但这 1024 个点对应的是**信号的 100.7 个周期**（不是整数）——FFT 算法会把'被截断的那 0.7 个周期'当作'高频成分'，**导致基波能量泄漏到旁边的频率 bin 里**。

**'基波能量泄漏'的后果**——你测的'真实基波 U₁'变小，'虚假谐波'变多——**THD 算出来比真值偏高 5%~10%**。

**对策一：加窗函数**

在 FFT 之前给信号乘一个'窗函数'——让信号两端**平滑地降到零**：

```c
// Hann 窗
for (int i = 0; i < 1024; i++) {
    float window = 0.5f - 0.5f * cosf(2 * M_PI * i / 1023);
    windowed_signal[i] = adc_buffer[i] * window;
}
```

> **小白补课**：
> - **窗函数**：把一段信号'平滑地切下来'的工具。把信号想象成一根连续的丝带——直接剪断会留下毛边（频谱泄漏），用'窗函数'相当于在切口处涂上胶水然后慢慢撕——切口光滑了，毛边没了。
> - 常见窗函数：**Hann（汉宁）、Hamming（汉明）、Blackman（布莱克曼）、Flat-top（平顶）**。本题用 **Flat-top 窗** 最佳——**它对幅度精度影响最小**（其他窗会让基波幅度被压低 6~12%）。

**对策二：整周期采样**

更好的办法——**让采样窗口正好覆盖整数个信号周期**。

```
采样总时长 = N × 信号周期
       = N × (1 / 信号频率)
```

**这个式子说的其实是**——**'**采样总时长**' 必须是 '**信号周期**' 的整数倍**。

具体怎么实现？

**方案 A：定采样率，自适应窗口长度**

固定采样率 1MSPS，根据信号频率选 N：

| 信号频率 | 周期 | 1024 点对应周期数 | N 取整选窗口 |
|---|---|---|---|
| 1kHz | 1ms | 1.024 周期 | **取 1 周期 = 1000 点** |
| 10kHz | 100μs | 10.24 周期 | **取 10 周期 = 1000 点** |
| 100kHz | 10μs | 102.4 周期 | **取 102 周期 = 1020 点** |

**问题**：FFT 长度会变（1000、1020 不是 2 的幂），效率低。

**方案 B：自适应采样率（推荐）**

让 ADC 触发周期跟着信号频率变：

```
采样率 = 信号频率 × N  （N = 1024 或 8192）
```

具体实现——**先粗扫描**：固定 1MSPS 采 1024 点，做粗 FFT，找到基波频率 f₀。然后**精扫描**：把 ADC 触发周期改成 1/(f₀ × 1024)，再采 1024 点——**这次正好覆盖 1024 个完整周期**——做精 FFT。

伪代码：

```c
// 第一遍：粗扫描
adc_set_sample_rate(1000000);  // 1MSPS
adc_capture(buf, 1024);
float coarse_freq = fft_find_peak(buf, 1024);

// 第二遍：精扫描
adc_set_sample_rate(coarse_freq * 1024);  // 自适应
adc_capture(buf, 1024);
fft_compute(buf, spectrum);
thd = compute_thd(spectrum);
```

**这段代码说的其实是**——**用第一遍'粗找频率'指导第二遍'精找谐波'**——**两遍 FFT 共耗时 3ms**——**远低于 10 秒要求**。

**整周期 + Flat-top 窗联手**——THD 误差能压到 ±0.5%——**远超题目 ±3% 要求**。**国一队伍的标准操作**。

**第三笔账：触发同步**

整周期采样还有一个隐藏要求——**采样起点要同步于信号过零点**。

为什么？因为如果采样从信号的'波峰中段'开始，**信号在第 0 个采样点已经不是 0 了**——FFT 算出来会有'虚假的相位偏移'——**对幅度计算无影响**，但**对相位判断有影响**。

本题不要求测相位（只测幅度），所以**起点位置不严重**。但国一队伍仍会做'**外部触发同步**'——用一颗外部比较器检测信号过零，给 MCU 一个上升沿触发 ADC 采样。**这是音频测量仪表的标配**。

**到此第一个谜的解法清楚了**：

```
DMA + 整周期采样 + Flat-top 窗 + 自适应采样率
```

**四件套加起来**——一颗 14 位 1MSPS 片内 ADC 测出 ±0.5% THD 精度——**这就是软件算法把硬件'拔'起来的工程美学**。

## 第二个谜：30mV 信号怎么测准

发挥 (1) 把电压下限拉到 **30mV**——这是真正的精度地狱。

**30mV 是什么概念**？

来看 14 位 ADC 的精度分配——

```
ADC 输入范围 = 0 ~ 3.3V
量化精度 = 3.3V / 2¹⁴ = 3.3V / 16384 = 0.2 mV
```

**这个式子说的其实是**——**14 位 ADC 能区分 0.2mV 的电压差**——**听起来很厉害**。

但 30mV 信号 = **30 / 0.2 = 150 个量化级别**——**听起来够用**。

**真正的问题是 THD 测量精度要求**：

```
最低可识别 THD = 30mV × 5% = 1.5mV
1.5mV / 0.2mV = 7.5 个量化级别
```

**这个式子说的其实是**——**5% 的失真度对应只有 7.5 个 ADC 量化级别**——**精度严重不足**。

而 ADC 本身有约 **±2 个量化级别的噪声**——**信号有效精度被噪声淹没**——**THD 算出来误差能到 ±5%**——**直接挂了基本要求 (4)**。

> **小白补课**：
> - **量化噪声（Quantization Noise）**：ADC 把连续电压'四舍五入'到最近的量化级别——**舍入误差就是噪声**。理论值 ≈ 0.29 个 LSB（最低位）。但实际 ADC 因为温漂、电源噪声等因素，**实际噪声 ≈ 1~3 个 LSB**。
> - **LSB（Least Significant Bit）**：最低位，对应一个量化级别的电压值。本题 LSB = 0.2mV。
> - **SNR（Signal-to-Noise Ratio）**：信噪比。14 位 ADC 理论 SNR = **86 dB**，实际 80~84 dB。30mV 信号 + 1mV 噪声 = SNR = 30 dB——**完全不够**。

**对策一：放大（PGA 自动增益）**

最直接的对策——**在 ADC 前加一级可编程增益放大器**，让 30mV 信号被放大到 ADC 满量程附近。

```
增益 = ADC 满量程 / 输入信号峰峰值
     = 3V / 30mV = 100 倍
```

**这个式子说的其实是**——**100 倍增益让 30mV 占满 ADC 量程**——**精度恢复**。

电赛常用 PGA：

| 型号 | 增益范围 | 带宽 | 价格 | 备注 |
|---|---|---|---|---|
| **TI PGA112** | 1~200 | 10MHz | 30 元 | 国一首选 |
| **TI PGA113** | 1~200（差分） | 10MHz | 35 元 | 抗噪强 |
| **AD8253** | 1~1000 | 10MHz | 50 元 | 美信高端 |
| **MCP6S91** | 1~32 | 18MHz | 15 元 | 入门 |

**自动增益逻辑**：

```c
// 先用 1× 增益采一次，估算信号幅度
pga_set_gain(1);
adc_capture(buf, 1024);
float peak = find_peak_to_peak(buf);

// 根据峰峰值选最佳增益
int best_gain;
if (peak > 1.5V)        best_gain = 1;
else if (peak > 0.3V)   best_gain = 5;
else if (peak > 0.1V)   best_gain = 20;
else if (peak > 0.03V)  best_gain = 100;
else                    best_gain = 200;

pga_set_gain(best_gain);

// 用最佳增益重新采，做 FFT
adc_capture(buf, 1024);
fft_compute(buf, spectrum);

// THD 计算时不需要除以增益（THD 是比值）
thd = compute_thd(spectrum);
```

**注意**：THD 是**比值（Uₕ / U₁）**——**和增益无关**——增益对 THD 没影响。但**显示波形和谐波幅值时**要除以增益还原原始电压。

**对策二：过采样（Oversampling）**

更高级的对策——**让 ADC 在每个测量周期内多采几次再平均**。

平均 N 次的精度提升：

```
等效精度提升 = log₂(√N) 位
           = (1/2) × log₂(N) 位
```

**这个式子说的其实是**——**'**N 次平均能让 ADC 等效精度提升 (1/2)log₂(N) 位**'**：

| N | 等效精度提升 | 14 位 ADC 等效精度 |
|---|---|---|
| 4 | 1 位 | 15 位 |
| 16 | 2 位 | 16 位 |
| 64 | 3 位 | 17 位 |
| 256 | 4 位 | 18 位 |
| 1024 | 5 位 | 19 位 |
| 4096 | 6 位 | 20 位 |

**代价**：采样率降低 N 倍——**1MSPS / 256 = 3.9kSPS**——**只能测低频信号**（< 400Hz）。

**国一组合方案**——**PGA 自动增益（100 倍）+ 16 倍过采样**：

```
等效精度 = 14 + 2 = 16 位
等效采样率 = 1MSPS / 16 = 62.5kSPS
可测信号上限 = 62.5kSPS / 5（5 次谐波）= 12.5kHz
```

**这个组合覆盖 30mV、1Hz~12.5kHz 范围**——能拿基本要求满分 + 发挥 (1)~(5) 大半分。

剩下的 **12.5kHz~100kHz 高频段** 用**纯 PGA 不过采样**：

```
等效精度 = 14 位
等效采样率 = 1MSPS
可测信号上限 = 1MSPS / 5 = 200kHz
```

**精度差一点**（±2% THD），**但够用 ±3% 要求**。

**对策三：抗混叠滤波（必做）**

不管 PGA 还是过采样，**ADC 前都要加一个抗混叠低通滤波器**——把信号最高频以上的所有内容滤掉。

```
滤波器截止频率 = 信号最高频 × 1.5 = 100kHz × 5 × 1.5 = 750kHz
```

**这个式子说的其实是**——**'**滤波器要让 5 次谐波（500kHz）通过，但要把 750kHz 以上的信号滤掉**'**——**避免高于奈奎斯特频率的信号混叠**。

**两阶 RC 滤波器**就能做到：

```
R₁ = 1kΩ, C₁ = 220pF → fc₁ = 723kHz
R₂ = 1kΩ, C₂ = 220pF → fc₂ = 723kHz
级联后斜率 = -40dB/decade
```

**实测衰减**：1MHz 处 ≥ 12dB，2MHz 处 ≥ 24dB——**够了**。

> **小白补课**：抗混叠滤波器为什么不直接用截止频率 = 信号最高频？因为**真实滤波器不是理想的'砖墙'**——过渡带宽度需要 1.5~2 倍。**留余量是工程美德**。

**对策四：交流耦合 + 偏置**

输入信号是**双极性**（±300mV）——**ADC 是单极性**（0~3.3V）——**要把负半周抬到正半周**。

```
输入信号 ──[1μF]── + 1.65V 偏置 ──[1kΩ]── ADC 输入
```

**这个电路说的其实是**——**'**电容隔直，让交流信号通过；偏置电压把信号中心抬到 1.65V**'**。

电容值要够大——保证最低频信号（1kHz）的容抗 < 100Ω：

```
C ≥ 1 / (2π × f × Z) = 1 / (2π × 1000 × 100) = 1.6 μF
```

实际取 **10μF 电解电容**——**覆盖 1kHz~500kHz 全频段**——余量充足。

**到此第二个谜的解法**：

```
PGA 自动增益（最大 200×）
+ 16 倍过采样（低频段）
+ 二阶 RC 抗混叠滤波（截止 750kHz）
+ 1μF 交流耦合 + 1.65V 偏置
```

**四件套加起来**——30mV 信号也能测出 ±1% THD 精度——**比题目 ±3% 要求好一个量级**。


## 第三个谜：FFT 频率分辨率不够时怎么办

**FFT 是本题的算法核心**——**没有 FFT 就没有 THD**。

> **小白补课：FFT 是什么**
> - **FFT（Fast Fourier Transform，快速傅里叶变换）**：把'**时域信号**'（一段波形）变成'**频域信号**'（不同频率的能量分布）的算法。
> - 想象一首交响乐——'**时域**'是你听到的连续声音；'**频域**'是把这首乐曲拆成钢琴 + 小提琴 + 大提琴各自占多少能量。**FFT 就是这个'拆乐器'的算法**。
> - **复杂度**：1024 点 FFT 在 80MHz Cortex-M4 上约 1.5ms，4096 点约 7ms。**毫秒级算力**。

**FFT 的关键参数**：

```
频率分辨率 Δf = 采样率 fs / FFT 长度 N
```

**这个式子说的其实是**——**'**频率分辨率**' 越小越好（能分辨更细的频率）**——**要让 Δf 小，要么提高 fs，要么增大 N**。

| 信号频率 | 采样率 | FFT 长度 | 分辨率 | 能分辨谐波 |
|---|---|---|---|---|
| 1kHz | 8kSPS | 1024 | 7.8 Hz | H1~H5 ✅ |
| 10kHz | 80kSPS | 1024 | 78 Hz | H1~H5 ✅ |
| 100kHz | 1MSPS | 1024 | 977 Hz | **H1~H5 勉强** |
| 100kHz | 1MSPS | 8192 | 122 Hz | H1~H5 ✅ |

**100kHz 信号的麻烦**——基波在 100kHz、二次谐波在 200kHz、三次谐波在 300kHz……**间距 100kHz**。**977Hz 的分辨率（远小于 100kHz）足够分辨**。但是——

**真正的麻烦不是'分辨'，是'频谱泄漏'**。

回想第一个谜里讲过——**采样不是整周期** → **基波能量会泄漏到旁边的 bin** → **THD 偏高**。

**对策**：**整周期采样 + 加窗**——**前面已经详细讲过**。

但 100kHz 信号有个**特殊问题**——**整周期采样要求采样率必须是基波频率的整数倍 × N**：

```
采样率 = 100kHz × 1024 = 102.4 MSPS
```

**这个式子说的其实是**——**要在 100kHz 信号上整周期采 1024 个周期，需要 102.4 MSPS 的采样率**——**远超 MSP432 的 1MSPS 上限**。

**对策**：**减少周期数**——

```
采样率 = 100kHz × N_周期 × N_点/周期
```

设 N_周期 = 1，N_点 = 1024——采样率 = 100kHz × 1024 = 102.4MSPS——**还是太高**。

**对策**：**减少周期数 + 接受较少点数**——

```
采样率 = 100kHz × 100 × 10 = 100MSPS
```

**还是不行**。

**最终对策**：**接受'非整周期采样' + 用 Flat-top 窗补偿** 

具体——固定采样率 1MSPS，采 1024 点。**这 1024 点对应 100kHz 信号 = 102.4 个周期**——**0.4 个周期是泄漏源**。

**用 Flat-top 窗压住泄漏**——Flat-top 窗的 **'**主瓣**'** 宽 8 个 bin、**'**旁瓣**'** 衰减 -90dB——**远超 Hann 窗（旁瓣 -32dB）**。

```c
// Flat-top 窗系数
#define FLATTOP_LEN 1024
const float flattop_window[FLATTOP_LEN] = {
    // 0.21557895 - 0.41663158 cos(2πi/N) + 0.27726316 cos(4πi/N) - ...
    // 实际系数从查找表里读
};

for (int i = 0; i < 1024; i++) {
    windowed[i] = adc_buffer[i] * flattop_window[i];
}
```

**这段代码说的其实是**——**'**Flat-top 窗系数比 Hann 复杂，但能把基波幅度精度压到 ±0.01%**'**——**远超本题需求**。

**国一队伍的 100kHz 方案**：**1MSPS + 1024 点 + Flat-top 窗 + 二次插值**——把基波频率精确到 ±10Hz——**THD 精度 ±0.5%**。

**FFT 计算量优化**

1024 点 FFT 在 MSP432（80MHz Cortex-M4F）上耗时约 **1.5ms**——**够快**。但 8192 点 FFT 耗时约 **15ms**——**也够快**。**不是瓶颈**。

**瓶颈在哪里**？**蓝牙传输**。

```
1024 点 ADC 数据 = 1024 × 2 字节 = 2KB
谐波数据 = 5 个 × 4 字节 = 20 字节
THD 字符 = 6 字节
合计 = 2048 字节
```

蓝牙 BLE 4.0 传输速率约 **20kB/s**——传 2KB 数据 = **100ms**——**这是真正的瓶颈**。

**对策**：**只传'有用的数据'**——

```c
// 不传完整波形，只传：
// 1. THD 数字 (4 字节)
// 2. 5 个谐波幅值 (20 字节)
// 3. 抽样波形 (128 点 = 256 字节)
//合计 280 字节，传输时间约 14ms
```

**14ms 不影响 10 秒要求**——**通过**。

**怎么压精度到 ±1%**？

**第一步：硬件层（前端调理）**

- **PGA 自动增益**：覆盖 30mV~600mV
- **二阶 RC 抗混叠滤波**：截止 750kHz
- **1μF 交流耦合 + 1.65V 偏置**：双极性 → 单极性
- **MSP432 14 位 1MSPS ADC**：精度基线
- **板上加屏蔽罩**：抑制电磁干扰

**第二步：采样层（数据获取）**

- **DMA 触发采样**：CPU 不参与单点
- **整周期采样**：消除频谱泄漏
- **过采样 16 倍**：低频段精度提升 2 位
- **同步触发**：外部比较器检测过零

**第三步：算法层（FFT + THD）**

- **Flat-top 窗**：基波幅度误差 ±0.01%
- **二次插值**：基波频率精度 ±10Hz
- **THD 公式严格按题目定义**：只算 H2~H5
- **去直流分量**：减去 ADC 直流偏置

**第四步：校准层（系统性误差）**

- **零偏校正**：用'**0% THD 标准信号**'测装置读数，得零偏值
- **增益校正**：用'**已知 THD（5%, 10%, 30%）的标准信号**'测装置读数，拟合校正曲线
- **温度补偿**：长时间运行后温漂校正
- **电压校正**：用 4½ 数字万用表标定 ADC 输入

**校准之后**——**装置精度 ±0.5%**——**发挥 (3) 35 分稳拿**。

## 把题目逐条翻译一遍

现在你脑子里已经有了全局，是时候回到题目原文，**像工程师那样把每个数字算一遍、每条要求推导一遍**。看完这一节你不仅懂出题人想要什么，更懂自己作为工程师拿到这题时该怎么动笔。

### 任务那段话

> 设计制作信号失真度测量装置，对来自函数 / 任意波形发生器的周期信号（以下简称为输入信号）进行**采集分析**，测得输入信号的总谐波失真 THD（以下简称为失真度），并可在**手机上显示**测量信息。

任务定义里有三个关键词——**'采集分析'、'测得 THD'、'手机显示'**。

**'采集分析'** 拆出三个动作：**ADC 采样、FFT 分析、谐波识别**——**三件套都不能少**。

**'测得 THD'** 拆出两个能力：**算 THD 数字、显示 THD 数字**——**显示在哪里？**——LCD 是必须的（基本要求 (5)）。

**'手机显示'** 是发挥项——**不做扣 10 分**——**做了拿满分**。

### 基本要求 (1)：电压范围 300mV~600mV

> 输入信号的峰峰值电压范围：**300mV ~ 600mV**。

这是入门量程——**6dB 的电压范围**——**最朴素的 ADC 直接采就行**。

**第一笔：300mV 在 14 位 ADC 上是什么概念**？

```
量化精度 = 3.3V / 16384 = 0.2 mV
300mV 对应 = 1500 个量化级别
```

**这个式子说的其实是**——**'**300mV 信号占满 ADC 量程的 9%——精度足够，不需要 PGA 放大**'**。

> **小白补课**：
> - **峰峰值（Peak-to-Peak Voltage, Vpp）**：信号的最高点到最低点的电压差。**300mV Vpp** 意思是信号从 -150mV 到 +150mV——**幅度 150mV**。
> - **不要把 Vpp 和 RMS（有效值）搞混**。正弦波 RMS = Vpp / (2√2) ≈ Vpp × 0.354。

**第二笔：600mV 是基本要求的'上限'**——

```
600mV 对应 = 3000 个量化级别 = 18% 量程
```

**18% 量程 = 完全在 ADC 工作区**——**没有饱和风险**。

**第三笔：为什么是 300mV 起点而不是 30mV**？

因为 30mV 是发挥项——**基本要求是'最低门槛'**——**只要任何一个团队有 ADC 都能搞定 300mV**——**门槛低 = 大部分队伍能起步**。

10 分稳拿。**这一条是新手扎根的'第一颗钉子'**——**做出来后你就知道电赛 A 题不是不可能完成的任务**。

### 基本要求 (2)：基频 1kHz

> 输入信号基频：**1kHz**。

**1kHz 是音频频率范围的核心**——**钢琴中央 C 是 261.6Hz、人声是 100~1000Hz、电话语音 300~3400Hz**——**1kHz 落在'音频测试经典频率'**。

**第一笔：1kHz 信号 + 5 次谐波 = 5kHz**

```
最高频率 = 5kHz
奈奎斯特要求 = 10kSPS
工程采样率 = 20~50 kSPS
```

**这个式子说的其实是**——**'**1kHz 信号 5 次谐波在 5kHz——20kSPS 采样足够**'**——**MSP432 的 1MSPS 用 50× 余量**——**精度极高**。

**第二笔：1kHz 整周期采样**

```
采样率 = 1kHz × 1024 = 1.024 MSPS
```

**这个式子说的其实是**——**'**1.024MSPS 正好覆盖 MSP432 的 1MSPS——勉强够**'**——**实际取 1MSPS 即可**。

**第三笔：FFT 分辨率**

```
分辨率 = 1MSPS / 1024 = 977 Hz
```

**977Hz 远小于 1kHz**——**基波和二次谐波（2kHz）能清楚分辨**——**精度足够**。

### 基本要求 (3)：失真度范围 5%~50%

> 输入信号失真度范围：**5% ~ 50%**。

这一条不是'要求'——**是'测试条件'**——**你测的信号 THD 标称值在 5%~50% 之间**——**装置不需要测 1% 这种小失真度**。

**为什么是 5%~50%**？

- **5% 下限**——**任何 ADC 都能测出 5%——保证测试可行性**
- **50% 上限**——**人耳能听到的极限失真度**——**再高就是噪声了**

**测试时函数发生器输出**：

| 标称 THD | 信号特征 |
|---|---|
| 5% | 基波清晰 + 少量谐波 |
| 10% | 谐波明显 |
| 30% | 谐波接近基波幅度 |
| 50% | 谐波 ≈ 基波 |

**装置必须能在这整个范围内都准**——**不能 5% 准但 50% 不准**——**这是设计的难点**。

### 基本要求 (4)：测量误差 ≤ 5%（20 分）

> 要求对输入信号失真度测量误差绝对值 **Δ = THDx - THDo ≤ 5%**，THDx 和 THDo 分别为失真度的测量值与标称值。

**这是 20 分的核心**——**也是基本要求最难的一项**。

**'**绝对值 ≤ 5%**' 怎么理解**？

```
|THDx - THDo| ≤ 5%
```

**这个式子说的其实是**——**'**测量值和真值的差不超过 5%**'**——**注意是'**差**' 不是'**比**'**——**THDo = 30% 时 THDx 在 25%~35% 都算合格**。

**第一笔：用整周期 FFT + Hann 窗能压到多少**？

工程经验值：

| 方案 | 误差 |
|---|---|
| 任意采样 + 矩形窗 | ±15% |
| 1024 点 + 任意采样 + Hann 窗 | ±5% |
| 整周期 + 矩形窗 | ±2% |
| 整周期 + Hann 窗 | ±1% |
| **整周期 + Flat-top 窗 + 校准** | **±0.5%** |

**这个表说的其实是**——**'**任何一个方案都能压到 ±5%——基本要求 (4) 没有难度**'**——**关键是发挥 (3) 的 ±3% 才是真考验**。

### 基本要求 (5)：显示 THDx（15 分）

> 显示失真度测量值 THDx。

**显示在哪里**？——**LCD 或 OLED**。

**第一笔：LCD 选型**

- **波形 + 柱状图同屏**——**发挥 (4)(5) 一并展示**
- **数据每秒更新一次**——**实时性好**

15 分稳拿。

### 基本要求 (6)：10 秒内（5 分）

> 失真度测量与显示用时不超过 **10 秒**。

**前面已经算过总耗时 107.6ms**——**远低于 10 秒**——**满分**。

**5 分的'**门槛级**'要求**——**任何能做 FFT 的方案都满足**。

### 发挥 (1)：电压范围 30mV~600mV

> 输入信号的峰峰值电压范围：**30mV ~ 600mV**。

电压下限从 **300mV 降到 30mV**——**精度难度提升 10 倍**。

**前面 '第二个谜' 已经讲过 PGA 自动增益 + 过采样的解法**。

**关键判断**：

```
30mV 信号 + 14 位 ADC + PGA 100× 增益
= 等效电压 3V
= 14 位精度
```

**够用了**。

### 发挥 (2)：频率范围 1kHz~100kHz

> 输入信号基频范围：**1kHz ~ 100kHz**。

频率上限从 **1kHz 提到 100kHz**——**采样率难度提升 100 倍**。

**前面 '第一个谜' 已经讲过自适应采样率 + Flat-top 窗的解法**。

**关键判断**：

```
100kHz 信号 + 5 次谐波 = 500kHz
1MSPS 采样率 = 2× 余量
```

**勉强够用**——**精度可能 ±2%**——**仍满足 ±3% 要求**。

### 发挥 (3)：误差 ≤ 3%

> 测量并显示输入信号失真度 THDx 值，要求 **Δ = THDx - THDo ≤ 3%**。

**误差从 5% 压到 3%**——**精度提升 67%**。

**整周期 + Flat-top 窗 + 校准** = **±0.5% 精度**——**远超 3% 要求**——**满分**。

**这一项是 35 分（发挥 (1)(2)(3)(4)(5) 共 35 分）的核心**——**每多一个百分点的精度都是分**。

### 发挥 (4)：显示一周期波形

> 测量并显示输入信号的**一个周期波形**。

**一个周期波形**——**取 ADC 原始数据的前 N 个点**（N = 信号周期 × 采样率）画出来。

```c
// 1kHz 信号 + 1MSPS 采样 = 1000 点 / 周期
// LCD 320 像素宽，需要把 1000 点抽样到 320 点
int decimation = 1000 / 320 = 3;
for (int i = 0; i < 320; i++) {
    int adc_val = adc_buffer[i * decimation];
    int y = (adc_val - 8192) / 64;  // 8192 = 中点，64 = 缩放
    lcd_set_pixel(i, 120 + y, COLOR_GREEN);
}
```

**这段代码说的其实是**——**'**1000 个采样点抽样到 320 点 LCD 上画**'**——**显示一个完整周期**。

### 发挥 (5)：归一化幅值

> 显示输入信号基波与谐波的归一化幅值，**只显示到 5 次谐波**。

**归一化** = **每个谐波幅值 ÷ 基波幅值**：

```
H1 / H1 = 1.00（基波始终是 1）
H2 / H1 = 0.32（二次谐波是基波 32%）
H3 / H1 = 0.18
H4 / H1 = 0.08
H5 / H1 = 0.05
```

**显示方式**——**柱状图**：

```c
int max_height = 100; // 像素
int colors[5] = {GREEN, BLUE, ORANGE, RED, MAGENTA};
for (int h = 1; h <= 5; h++) {
    int height = (int)(harmonic_norm[h-1] * max_height);
    int x = h * 30;
    lcd_fill_rect(x, 200 - height, x + 25, 200, colors[h-1]);
}
```

**这段代码说的其实是**——**'**5 个柱子表示 H1~H5 的归一化幅值，颜色不同**'**——**直观漂亮**。

### 说明里的暗坑

**说明 (1)：'**必须使用 TI 公司的 MCU 及其片内 ADC**'**

**前面已经分析过**——**MSP432 / TM4C / F28379D / MSPM0 是合规选择**——**不得用片外 ADS1256 这种 24 位高精度模块**。

**评委检查方式**：**看你的 PCB**——**主控芯片如果是 STM32 直接零分**——**ADC 模块如果是 ADS1256 模块直接零分**。

**说明 (2)：THD 公式定义**

> THD₀ = √(U₂² + U₃² + U₄² + U₅²) / U₁

**注意'**只算到 5 次谐波**'**——**不要算 H6 H7 H8……**——**多算了反而误差大**。

**为什么只算 5 次**？因为**实际信号的 H6+ 谐波幅值通常 < H5 的 10%**——**忽略带来的误差 < 1%**——**简化计算 + 提高速度**。

**第一笔：标准 THD 公式 vs 题目自定义公式**

业界标准 THD 公式：

```
THD_standard = √(Σ Uₕ²) / U₁,  h = 2, 3, 4, ..., ∞
```

题目自定义：

```
THD₀ = √(U₂² + U₃² + U₄² + U₅²) / U₁
```

**两者差距**：通常 < 1%——**对本题 ±3% 精度无影响**——**但报告里要写清楚用的是题目自定义**。

**说明 (3)：归一化幅值定义**

> 当输入信号的基波幅值为 Um1，各次谐波幅值分别为 Um2、Um3…，基波与谐波的归一化幅值为：1、(Um2/Um1)、(Um3/Um1)…

**这一条只是定义说明**——**没有暗坑**。

**说明 (4)(5)：函数发生器自带**

> 参赛队员必须熟练掌握发生器'**谐波发生**'功能的操作技能（包括但不限于设置信号谐波参数、存储与调用信号）。
>
> **参赛队必须自带本队自用的发生器参加赛区作品测试**。

**这一条是真坑**——**很多队伍不知道'必须自带发生器'**——**比赛现场没有发生器 = 直接零分**。

**软件设计**：

```c
typedef enum {
    STATE_IDLE,           // 等待启动
    STATE_SAMPLING,       // 采样中
    STATE_FFT,            // FFT 计算中
    STATE_DISPLAY,        // 显示更新
    STATE_BLUETOOTH,      // 蓝牙发送
    STATE_DONE            // 完成
} state_t;

void main_loop() {
    static state_t state = STATE_IDLE;
    static uint32_t start_time;
    
    switch (state) {
    case STATE_IDLE:
        if (button_pressed()) {
            start_time = get_time_ms();
            state = STATE_SAMPLING;
        }
        break;
    case STATE_SAMPLING:
        if (adc_done) state = STATE_FFT;
        if (get_time_ms() - start_time > 10000) {
            // 超时
            display_error("Timeout");
            state = STATE_IDLE;
        }
        break;
    // ... 其他状态
    }
}
```

**关键**：**每个状态的最大耗时都 < 1 秒**——**全部加起来 < 1 秒**——**远低于 10 秒要求**。
