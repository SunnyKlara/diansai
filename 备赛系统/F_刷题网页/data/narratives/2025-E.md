## 想象一个场景

一座汽车车身焊接车间——昏黄的灯光下，**一台 KUKA 工业机械臂**正在车架上焊点。但车间里还有另一种作业方式——**一辆 AGV（自动导引车）背着一台激光打标头**，沿着白线**'巡线'前进**——**车没停**——**激光头自己歪着脖子，把车牌号、出厂日期、批次码激光刻在车身上每一个固定位置**。

**第四层——'感光纸' 这个细节是出题人的小聪明**

题面里出现了一个**罕见的物料**——

> 目标靶面采用 **A4 幅面紫外感光纸**，可显示光斑**驻留的痕迹**。

> 紫外感光纸被蓝紫激光笔照射后，**纸面会留下感光痕迹**。**感光痕迹会持续滞留 20s~60s 才会消失**——滞留时间与蓝紫光线照射强度有关，照射强度越大，痕迹颜色越深、滞留时间越长。

**为什么要用感光纸？**

因为评委要**事后测量光斑距离靶心的距离 D1**——**激光笔照射的瞬间是看不见的**——**必须在纸面上留下'痕迹'**——**评委拿尺子量痕迹**。这是题目最 '物理证据保留' 的设计。

> **小白补课：紫外感光纸是什么？**  
>  
> **紫外感光纸（UV-Sensitive Paper）**——一种**纸面涂有紫外线敏感染料**的特殊纸张。常见的是**蓝色光致变色染料（leuco dye）**——**遇 380~420nm 紫外线/蓝紫光会变成深紫色**——**离开光照后慢慢褪回原色**。  
>  
> **应用**：紫外线检测卡（防晒霜效果对照）、舞台特殊效果、**电赛和教学**。淘宝单价 5~15 元/张 A4——课题预算友好。  
>  
> **关键特性**：**痕迹持续时间和照射时长强相关**——电赛比赛要求'激光持续照射靶面'——**痕迹会很深**。  
>  
> 滞留 20~60 秒——**评委有充裕时间用游标卡尺量距离**。这就是 D1 测量的物理基础。

**这个细节告诉你出题人非常用心**——**不是随便从军工教材里抄一道'瞄准'题**——**而是把每个可量化指标都安排了'测量手段'**——**比赛公平性极强**。

## 这题在做的事，其实是把'两件事'同时做精

把图 1 简化成一句话——**'一辆小车在 100×100cm 的正方形上跑，车上一支激光笔指着距 AB 边外 50cm 处的 A4 靶'**。

但**这'两件事'**：

**事件 A：小车循迹**——MSPM0 + 5 路红外 + 陀螺仪 + 编码器 + PID——**正方形 100×100cm，每条边 100cm，4 个直角拐弯**。

**事件 B：激光瞄准**——独立 MCU + 二维云台 + 蓝紫激光笔——**根据小车实时位置反推激光的偏转角，让光斑始终落在 A4 靶上 1 个点（或 1 个圆）**。

这两件事**逻辑独立、传感器独立、控制器独立、电源独立**——**整套系统是两个并行的闭环**。

**为什么这样分？因为它们的控制特性完全不同**：

| 维度 | 小车循迹 | 激光瞄准 |
|---|---|---|
| **控制频率** | 1kHz（PID） | 100Hz（云台舵机） |
| **执行机构** | 直流电机（PWM） | 舵机（PWM） |
| **传感器** | 红外 + IMU + 编码器 | 自己算几何 / OpenMV 视觉 |
| **运动惯量** | 大（500g 车体） | 小（20g 激光笔头） |
| **响应带宽** | 5~10 Hz | 30~50 Hz |
| **失败后果** | 出场（脱离白线） | 光斑偏离靶纸（D1 大） |

**两个频段、两种执行机构、两种惯量**——**强行用一个 PID 控制器同时管这两件事，是最常见的失败原因**——**控制器顾此失彼**。

**正确做法**——**两个 MCU**——**双独立电源**——**通过 UART 同步'当前小车位置和姿态'这一个最小信号集**——**剩下的事各自闭环**。

> **小白补课：什么是'解耦控制'？**  
>  
> **解耦（Decoupling）**——把一个'多变量耦合系统'拆成多个'单变量独立系统'分别控制。**直觉理解**：你**走路**和**说话**是两件事——大脑分别由不同区域管理——所以你能边走边说话——这就是天然的'解耦'。  
>  
> 反例——**你左手画圆右手画方**很难——因为大脑的运动皮层这两个动作信号**互相干扰**——这就是'耦合'。  
>  
> 工程系统也一样——**'循迹 + 瞄准' 强行一个控制器做 = 耦合**——**两个控制器分别做 = 解耦**——**精度直接提升一个数量级**。这是 2025 E 题最关键的设计哲学。

题目里那一句**'MSPM0 控制器和瞄准模块的电源分别由两个独立开关控制'**——**就是出题人强行让你做'物理层面的解耦'**——**电源不能共享 → 模拟地不耦合 → 数字噪声不串扰**——**这是工业产品里高可靠性的标准做法**。

接下来的 5 个谜，把这'两件事'里每一个关键工程点都拆开讲。

## 第一个谜：90° 直角弯怎么走才不撞线

2024 H 是**40cm 半径的弧线弯**——**地上有黑线引导你**——**循迹传感器只要跟住黑线**。

2025 E 是**100×100cm 正方形 + 4 个 90° 直角弯**——**直角弯处地上的黑线是直角拐——**没有圆弧过渡线**——**循迹传感器进入直角后会**瞬间丢线**——**因为车体不可能 0 度弯曲，惯性会让它冲出场地**。

**这是这道题的'第一个杀手'**——**前 30% 队伍栽在这里**。

先看场地几何：

```
       D ═══════════════════ A
       ║                     ║
       ║                     ║
       ║   100×100 cm 内部空白 ║
       ║                     ║  ◄── 距 AB 外 50cm 处有 A4 靶
       ║                     ║
       C ═══════════════════ B
```

正方形外沿是黑线 1.8cm 宽，**逆时针走 A→B→C→D→A**。

**直接走 = 撞线**：车从 A→B 直行，到 B 点附近要立刻 90° 转弯——**车长 25cm，最小转弯半径约 12.5cm**——**直角弯几乎不可能完成**——**车体肯定有一部分冲出黑线外侧**。

**两条工程对策**：

**对策 1：'减速 + 原地转向 + 加速'**

到 B 角前 10cm 开始减速到接近停车——**接近停车后两轮反向旋转（一正一负）**——**车体绕中心原地转 90°**——**陀螺仪监控转角**——**到 90° 时停止**——**继续往 BC 方向加速行驶**。

```c
// 状态 1：直线 AB（陀螺仪闭环走直）
state = STATE_AB;
while (encoder_distance < 90) {  // 距 B 还有 10cm
    pwm_diff = gyro_pid(target_heading_AB);
    set_pwm(base_pwm - pwm_diff, base_pwm + pwm_diff);
}

// 状态 2：减速进 B 角
state = STATE_B_BRAKE;
while (encoder_distance < 100) {
    int brake_pwm = base_pwm * (100 - encoder_distance) / 10;
    set_pwm(brake_pwm, brake_pwm);  // 线性减速
}

// 状态 3：原地 90° 转向
state = STATE_B_TURN;
float start_angle = imu_angle;
while (fabsf(imu_angle - start_angle) < 90.0) {
    set_pwm(150, -150);  // 左轮正、右轮反 → 顺时针转
}

// 状态 4：进入 BC
state = STATE_BC;
encoder_reset();
target_heading = current_heading_after_turn;
```

**这段代码说的其实是**——**'直线段开 PID 跟黑线 → 接近角点减速 → 原地转 90° → 重置编码器开新一段直线'**——**4 个状态串联的状态机**。

**问题——'不得后退'**

题面说明 (1) 隐藏了一个限制（来自 2024 H 题面，2025 E 没明文但本意一致）：

> 行驶过程中**小车的投影必须在轨迹线上**。

意思是车的地面投影必须**始终覆盖白线**——**原地转向时车体会绕中心旋转——后半身可能脱离白线**。

**严格意义上'原地转向'违规**——**后轮在转弯瞬间会偏离白线**。

**对策 2：边走边转（推荐）**

让两个轮子**速度差较大但同向**——**车体走出一段半径很小的弧线（10~15cm 半径）**——**90° 转弯过程中车头中心始终压着白线**：

```c
// 边走边转：左轮慢、右轮快 → 车体向左拐
state = STATE_B_TURN;
float start_angle = imu_angle;
while (fabsf(imu_angle - start_angle) < 90.0) {
    int slow_pwm = 60;  // 内侧轮慢
    int fast_pwm = 200; // 外侧轮快
    set_pwm(slow_pwm, fast_pwm);
}
```

**2 倍轮速差 → 转弯半径约 15cm**——**车体'内侧轮'始终压着白线**——**外侧轮在白线外约 15cm**。**只要车长 < 25cm，外侧轮的偏移不会让车体投影完全脱离白线**——**合规**。

**国一队伍的做法**——**精确测算 '内侧轮速 / 外侧轮速 / 转弯半径'，让转弯轨迹刚好和场地外沿重合**——**车不只'转过去'，而是'优雅地拐过去'**——**视觉效果好 + 时间短**。

**坑——直角检测靠什么？**

朴素做法——**编码器累计 100cm 后开始转弯**——**误差 ±2cm**——**够用**。

进阶做法——**红外传感器检测 '前 1cm 突然全黑'**——**正常直线段 5 路红外只有中间 1 路压黑线，进入角点时另一条相邻边的黑线也压上来——5 路里有 3~5 路同时变黑**——**这就是 '角点检测信号'**：

```c
bool corner_detected() {
    int black_count = 0;
    for (int i = 0; i < 5; i++) {
        if (sensor[i] == BLACK) black_count++;
    }
    return black_count >= 3;  // 3 个或以上读到黑 = 进入角点
}
```

**红外角点检测 + 编码器距离判断双保险**——**前 90% 队伍只用编码器**——**国一队伍两者结合**——**误差 ±0.3cm**——**4 圈下来累计偏差极小**。

> **小白补课：'红外突然全黑' 的物理意义**  
>  
> 直线段——5 路红外是 '中间 1 路黑、其它 4 路白'——黑线只在车头下方一根线宽。  
>  
> 进入直角角点时——**两条相互垂直的黑线交汇成 'L' 形**——**车头下方有一段 '角点横截面' 是黑的**——**5 路红外中至少 3 路会同时压在 L 形的两条边上**——**全黑信号**。  
>  
> **这是直角弯独有的特征**——**弧线弯永远不会出现 '3 路以上同时黑'**——**所以这个判据 100% 可靠**。

## 第二个谜：怎么算激光要偏多少度

小车跑到正方形上的某个位置 (x, y)——靶心在场地外 (x_t, y_t, z_t)——**激光笔安装在云台上、云台装在小车顶部**——**激光笔需要从小车坐标系出发指向靶心**。

这是一个**几何反推问题**——给定**两点位置 + 小车朝向**——**求激光的偏转角和俯仰角**。

先建立坐标系：

```
世界坐标系（场地）：
  x 轴：A→B 方向（场地长边）
  y 轴：A→D 方向（场地短边）
  z 轴：垂直向上

A 点坐标 (0, 0, 0)
B 点坐标 (100, 0, 0)
C 点坐标 (100, 100, 0)
D 点坐标 (0, 100, 0)

靶心位置（题面给出）：
  AB 边外 50cm，靶面平行 AB
  → x_t ≈ 50 cm（AB 中点延伸）
  → y_t = -50 cm（AB 外侧 50cm）
  → z_t = 25 cm（靶高 ≤ 50cm 取中间）
```

**实际靶心位置不是固定的**——题面里 '在距离 AB 线段外 50cm 处竖立目标靶'——**只规定了距离 AB 边 50cm**，**靶在 AB 方向上的位置不固定**——**评委可能放在 AB 中点也可能偏一边**。**所以小车上电后必须先 '找靶'**——**这是基本要求 (2) 的核心**。

假设已知靶心 (x_t, y_t, z_t)、小车位置 (x_c, y_c, z_c=0)、小车朝向角 θ_c（相对 x 轴）。

**激光在世界坐标下的指向角**：

```
水平偏角（pan，相对世界 x 轴）：
  pan_world = atan2(y_t - y_c, x_t - x_c)

俯仰角（tilt，相对水平面）：
  d_horizontal = sqrt((x_t - x_c)² + (y_t - y_c)²)
  tilt = atan2(z_t - z_laser, d_horizontal)

激光相对小车的偏角：
  pan_relative = pan_world - θ_c
  tilt_relative = tilt（俯仰不受小车朝向影响）
```

**这两个式子说的其实是**——**'先在世界坐标系里算激光应该指向哪个绝对方向，再扣除小车自身的朝向，得到激光在小车坐标系下要偏的角度'**——**就像你转身的同时手要反向转才能保持指向同一物体**。

**代入实际数值算一下**——

设小车位于 A 点 (0, 0)，朝向 θ_c = 0（朝 B 方向），靶心 (50, -50, 25)：

```
pan_world = atan2(-50 - 0, 50 - 0) = atan2(-50, 50) = -45°  （方向：右前方下偏）
pan_relative = -45° - 0° = -45°  （云台水平向右偏 45°）

d_horizontal = sqrt(50² + 50²) = 70.7 cm
tilt = atan2(25 - 10, 70.7) = atan2(15, 70.7) = 11.97°  （云台向上仰 12°）
```

**注意 z_laser ≈ 10cm**——**激光笔安装在小车顶部约 10cm 高**。

设小车跑到 B 点 (100, 0)，朝向 θ_c = 90°（顺时针转过 90°，朝 C 方向）：

```
pan_world = atan2(-50 - 0, 50 - 100) = atan2(-50, -50) = -135°
pan_relative = -135° - 90° = -225°  
归一化到 (-180°, 180°): -225° + 360° = 135°
```

**云台需要从'初始 0°'转到'相对小车朝向 135°'**——**云台几乎要朝车尾方向打 135°**——**这个角度很大**。

**坑——云台的'机械限位'**

工业 2 自由度舵机云台一般限位**水平 ±90°（共 180°）+ 俯仰 ±45°**——**135° 超过限位**——**机械上根本打不到**。

**对策——给激光笔安装位置加旋转自由度**——**或者用'连续旋转舵机'代替'位置舵机'**——但这又会引入新的标定问题。

**国一队伍的'隐藏招数'**——**让小车跑到能瞄准的位置时再瞄**——**比如小车只在 A→B 这条直线段瞄准**（云台对靶角度始终在 ±90° 内）——**到 B→C、C→D 段时激光转向 '不工作'但仍然亮着**——**靶纸只在小车经过 AB 段时被照射**。

**问题**——**发挥要求'激光必须连续发光射向靶面'**——**'射向靶面' 不等于 '射中靶心'**——**只要激光指向靶面所在的方向都算合规**。

**这是国一队伍读题读出来的便利**——**激光在 BC、CD、DA 段可以指向任何 '能照到靶面' 的角度**——**只要不是指着天花板就行**——**减轻云台机械限位压力**。

> **小白补课：atan2 和 atan 的区别**  
>  
> 普通 atan(y/x) 输出范围 -90° ~ +90°——**只能区分 4 个象限里的 2 个**（左半 vs 右半）。  
>  
> **atan2(y, x)** 输出范围 -180° ~ +180°——**根据 x 和 y 的符号区分 4 个象限**——**能正确处理所有方向**。  
>  
> 工程上**永远用 atan2 而不用 atan**——**否则 90% 会出现'反向射击'的 bug**——激光指向靶心反方向。

## 第三个谜：小车实时位置怎么知道——'里程计 + 角点重置'

第二个谜里 '激光偏多少度' 的输入是 **(x_c, y_c, θ_c)**——**小车实时位置 + 实时朝向**。

**问题**——**小车自己怎么知道自己在哪里？**

可选路径有 4 条，**便宜可靠**和**昂贵精确**之间有取舍：

| 方案 | 精度 | 成本 | 实现难度 |
|---|---|---|---|
| **A. 编码器累计** | ±20cm（5 圈后） | 0 元（车上有） | ★（已有） |
| **B. 编码器 + 角点重置** | **±5cm** | 0 元 | **★★** |
| **C. UWB 室内定位** | ±10cm | 200 元 | ★★★★ |
| **D. 摄像头视觉 SLAM** | ±2cm | 200 元 | ★★★★★ |
| **E. 激光雷达 + AMCL** | ±1cm | 1000 元 | ★★★★★ |

**国一队伍 90% 用方案 B**——**便宜、可靠、易调试**。**关键操作'角点重置'**——

```c
// 全局位置 (x_c, y_c)，全局朝向 theta_c
float x_c = 0.0, y_c = 0.0, theta_c = 0.0;

void update_position_from_encoder() {
    // 读编码器增量
    float d_left = read_left_encoder_delta();
    float d_right = read_right_encoder_delta();
    
    // 推算车体位移和转角
    float d_center = (d_left + d_right) / 2.0;
    float d_theta = (d_right - d_left) / WHEEL_BASE;
    
    // 增量积分
    theta_c += d_theta;
    x_c += d_center * cos(theta_c);
    y_c += d_center * sin(theta_c);
}

void on_corner_detected(int corner_id) {
    // 角点检测触发：5 路红外检测到 3 个以上黑
    switch (corner_id) {
        case CORNER_A: x_c = 0;   y_c = 0;   theta_c = 0;      break;
        case CORNER_B: x_c = 100; y_c = 0;   theta_c = 90;     break;
        case CORNER_C: x_c = 100; y_c = 100; theta_c = 180;    break;
        case CORNER_D: x_c = 0;   y_c = 100; theta_c = 270;    break;
    }
}
```

**这段代码说的其实是**——**'编码器持续累积位移 → 经过角点时强制对齐到已知坐标 → 误差被周期性清零'**——**这是机器人定位里 '里程计 + 地标修正' 的标准模式**。

**精度估算**——

```
单边 100cm 走完 = 编码器累积 ±2% = ±2cm 误差
角点重置后 = 误差归零
4 圈跑完 = 4 × 4 角点 = 16 次重置 = 误差不会累积
```

**最差 5cm 误差**——**对应'激光偏角误差'**：

```
50cm 处的靶看 5cm 偏移 = 视角偏 5/50 = 0.1 rad ≈ 5.7°
云台舵机精度 ±0.5°
位置误差 5°
合计 5.7°
反算到靶心位置：tan(5.7°) × 50cm = 5.0 cm
```

**5cm 偏差 vs 题目要求 D1 ≤ 2cm = 不达标 1.5 倍**——**所以 '编码器 + 角点重置' 仍不够**——**国一队伍还要再加一层修正**。

**进阶——'角点附近精修'**

每个角点的位置不是'瞬间一跳'到 (100, 0) 那种——**车真正进入角点的位置和理想角点位置可能差几毫米**。

```c
void on_corner_detected_precise(int corner_id) {
    // 进入角点前 5cm，启动精修流程
    // 1. 减速到接近静止
    decelerate_to_stop();
    
    // 2. 5 路红外读所有 ADC 值
    int sensor_readings[5];
    read_all_sensors_adc(sensor_readings);
    
    // 3. 加权质心算法：精确算出车头当前在 L 形交点附近的偏移
    float offset = weighted_centroid(sensor_readings);
    
    // 4. 修正位置坐标
    apply_offset_correction(corner_id, offset);
}
```

**精修后误差 < 1cm**——**对应靶面精度 < 1.2°**——**搞定 D1 ≤ 2cm**。

## 第四个谜：让激光画一个圆——'同步控制' 的极致考验

发挥要求 (3) 是这道题的'珠穆朗玛峰'——

> 激光笔沿靶面上**半径 6cm 的红色圆弧**同步画圆，光斑痕迹与半径 6cm 的红色圆弧线**最大距离 D2 ≤ 2cm**；**小车行驶 1 圈，正好画 1 圈光斑**，**同步误差必须小于 1/4 圈**。

**这一项把问题升级到了'参数化轨迹同步'**——

- **小车的位置参数 s ∈ [0, 4×100=400 cm]**（沿正方形周长的弧长参数）
- **激光的位置参数 φ ∈ [0, 360°]**（在靶面圆上的角度参数）
- **要求**：**s 和 φ 严格成比例 → φ = (s / 400) × 360°**——**误差 < 1/4 圈 = 90°**

**这是机器人控制里的 '轨迹同步' 问题**——和**双臂协作机器人在装配工件**完全相同的算法——**两个独立运动单元的时序必须严格对齐**。

**算法实现**——

```c
// 实时计算 (laser_x_target, laser_y_target) 在世界坐标系
float compute_laser_target_position() {
    // 1. 算小车走过的总弧长
    float s = total_distance_traveled();  // 0 ~ 400 cm
    
    // 2. 算对应在靶面圆上的角度
    float phi = (s / 400.0) * 2 * M_PI;  // 0 ~ 2π
    
    // 3. 算激光在靶面坐标系下应该的位置（圆心 = 靶心）
    float laser_x_on_target = TARGET_CENTER_X + 6.0 * cos(phi);
    float laser_y_on_target = TARGET_CENTER_Y + 6.0 * sin(phi);
    float laser_z_on_target = TARGET_CENTER_Z + 0;  // 假设靶面在 yz 平面
    
    // 4. 激光在世界坐标系的目标点 (笔直方向算激光指向)
    return (laser_x_on_target, laser_y_on_target, laser_z_on_target);
}

void update_laser_pointing() {
    Point3D target = compute_laser_target_position();
    
    // 几何反推得到云台角度（前面 '第二个谜' 已讲）
    float pan, tilt;
    geometric_inverse(target, x_c, y_c, theta_c, &pan, &tilt);
    
    servo_pan_set(pan);
    servo_tilt_set(tilt);
}
```

**这段代码说的其实是**——**'把小车的实时位置（弧长参数 s）映射到激光在靶面上的角度（φ） → 反推云台角度 → 实时驱动云台'**——**两个独立运动通过参数 s 严格同步**。

**精度链**——

```
小车位置精度：±1 cm（角点精修后）
激光在靶面位置精度：约 ±1 cm（云台精度 + 算法精度）
合计 D2 ≈ ±2 cm  → 刚好达标
```

**坑——同步误差不仅是 '位置误差'，还包括 '相位误差'**

什么意思？车跑到 s = 100cm（B 角点）时，激光应该在靶面圆上 φ = 90°——**也就是靶面正右方**。

**但小车在 B 角点会减速 + 转弯**——**这段时间小车的'弧长参数 s'增加慢**——**激光的 φ 也跟着慢**——**这是同步的体现，没问题**。

**问题在 s 突然跳变**——**比如小车跑过 B 角点后 '位置坐标从 (100,0) 沿 BC 方向开始累加'**——**激光的 φ 也要从 90° 顺着继续到 180°**——**两者必须严格一致**。

如果代码里**用 '简单时间参数 t' 代替 '弧长参数 s'**，**小车在角点慢、直线段快——激光画圆速度均匀——**到一圈结束时小车跑完了 但激光没画完一圈** = **同步误差**。

**国一队伍**——**严格用 '弧长参数 s'**，**激光速度跟着小车真实位置走**——**同步误差 < 5°**——**远超 90° 容差**。

> **小白补课：什么叫'参数化'？**  
>  
> 直线运动 y = kx + b——**用 x 参数化**——给个 x 就能算出 y。  
>  
> 圆周运动——**用 t 参数化**——(x(t), y(t)) = (r·cos(t), r·sin(t))——给个 t 就是圆上一个点。  
>  
> 复杂轨迹——**任何'一维参数'都能用**——本题用 '走过的弧长 s'——给个 s 既能算出小车位置 (x_c(s), y_c(s)) 又能算出激光在靶上的角度 φ(s)——**用同一个参数把两套运动绑定在一起**——这就是'同步控制'的数学本质。

## 第五个谜：双 MCU 用什么协议 + 为什么不用一个 MCU

题目允许**瞄准模块用任意 MCU**——**国一队伍 99% 选 STM32F407 或者 STM32F103**——**因为视觉/数学库更丰富、网上代码资源更多**。

**两 MCU 之间需要传什么数据？**

| 数据 | 频率 | 大小 | 说明 |
|---|---|---|---|
| **小车位置 (x, y)** | 100 Hz | 8 字节 (2 个 float) | 主要传输 |
| **小车朝向 θ** | 100 Hz | 4 字节 (1 个 float) | 主要传输 |
| **小车状态（直线/角点/停止）** | 偶发 | 1 字节 | 状态标识 |
| **靶心坐标更新** | 偶发 | 12 字节 (3 个 float) | 视觉发现新靶时更新 |
| **同步开始/结束信号** | 偶发 | 1 字节 | 状态转换 |

**总带宽需求**：100Hz × 13 字节 = **1.3 kB/s**——**任何串行通信都能轻松搞定**。

**通信协议选择**：

| 协议 | 速度 | 引脚 | 复杂度 | 推荐度 |
|---|---|---|---|---|
| **UART** | 115200 baud（11.5 kB/s） | 2 (TX/RX) | ★ | **★★★★★** |
| **SPI** | 1 MHz | 4 (CS/CLK/MOSI/MISO) | ★★ | ★★★ |
| **I2C** | 400 kHz | 2 (SDA/SCL) | ★★ | ★★ |
| **CAN** | 1 Mbps | 2 (CAN_H/CAN_L) | ★★★ | ★★（用不上） |

**国一队伍标配——UART**——**最简单、最不容易出 bug、引脚最少**。**带宽 11.5kB/s 远超 1.3kB/s 需求**。

**简化的协议帧格式**：

```c
// 帧格式（13 字节固定长度）：
// [帧头 0xAA][x: 4 字节][y: 4 字节][theta: 4 字节][状态: 1 字节][校验: 1 字节][帧尾 0xBB]
typedef struct {
    uint8_t header;  // 0xAA
    float x;
    float y;
    float theta;
    uint8_t state;
    uint8_t checksum;
    uint8_t footer;  // 0xBB
} CarStatusFrame;

// MSPM0 端：每 10ms 发一帧
void send_car_status() {
    CarStatusFrame frame;
    frame.header = 0xAA;
    frame.x = current_x;
    frame.y = current_y;
    frame.theta = current_theta;
    frame.state = current_state;
    frame.checksum = compute_xor_checksum(&frame, 12);
    frame.footer = 0xBB;
    uart_send((uint8_t*)&frame, 16);
}

// STM32 端：DMA 接收 + 帧头帧尾对齐
void on_uart_rx_dma_complete() {
    if (rx_buffer[0] == 0xAA && rx_buffer[15] == 0xBB) {
        if (validate_checksum(rx_buffer)) {
            CarStatusFrame* f = (CarStatusFrame*)rx_buffer;
            update_car_status(f->x, f->y, f->theta, f->state);
        }
    }
}
```

**帧头 + 帧尾 + 校验码**——**3 重保险**——**通信可靠性极高**。

**为什么不用一个 MCU？**

理论上一颗 STM32F407 性能足够——**168MHz 主频、1MB Flash、192KB RAM**——**同时跑循迹 + 瞄准没问题**。

**但题目铁律强制要求 '小车控制必须用 MSPM0'**——**MSPM0 G3507 性能虽然够用，但软件生态、视觉库支持远不如 STM32**——**强行用 MSPM0 跑视觉就是自找苦吃**。

**所以双 MCU 不是技术选择，而是'政策选择'**——**MSPM0 跑小车 + STM32 跑视觉**——**各做各擅长的事**——**通过 UART 桥接**。

**国一队伍的'双 MCU 哲学'**——**'让每颗芯片只做它最擅长的事'**——**这是工业产品里的标准设计**——汽车 ECU 一辆车有 80 颗 MCU，每颗专做一件事——可靠性远超'一颗大芯片管所有'的设计。

### 任务那段话——'两块 MCU + 一支激光笔 + 一张感光纸'

题目原文（第 11 行）：

> 设计制作一个简易自行瞄准装置，该装置包括**自动寻迹小车**及**瞄准模块**两部分。**自动寻迹小车行驶必须采用 TIMSPM0 系列 MCU（简称 MSPM0）控制（包括巡迹、电机控制）**；**瞄准模块以小车为载体，利用二维云台控制蓝紫激光笔发射激光的方向**，使**激光光斑落在目标靶上**，**靶上光斑直径 ≤ 0.5cm**。要求 **MSPM0控制器和瞄准模块的电源分别由两个独立开关控制**。

这一段每一个字都是边界条件——**少看一个字就少 2 分**。

**第一笔账：'必须用 MSPM0' 限定的范围**

题面只规定**'自动寻迹小车行驶必须采用 MSPM0'**——**'巡迹、电机控制'必须由 MSPM0 完成**。

**'瞄准模块'用什么 MCU 题面没规定**——**意味着你完全可以用 STM32F407 跑视觉处理 + OpenMV 模块跑图像识别 + 舵机控制**——**这是 2024 H 没有的自由度**。

**国一队伍的标配双 MCU 架构**：

```
┌─────────────────────────────┐
│  小车 MCU（MSPM0G3507）       │
│  - 5 路红外读 ADC             │
│  - 编码器读 GPIO 中断          │
│  - 电机 PWM 输出              │
│  - 陀螺仪 I2C                │
│  - PID 1kHz 主循环            │
│  - UART 发送 (x, y, θ)         │
└─────────────────────────────┘
              │ UART 115200 bps
              ▼
┌─────────────────────────────┐
│  瞄准 MCU（STM32F407 / F103） │
│  - UART 接收 (x, y, θ)         │
│  - OpenMV 摄像头 SPI         │
│  - 几何反推算云台角度          │
│  - 舵机 PWM 输出              │
│  - LCD 显示                  │
└─────────────────────────────┘
```

**这是双 MCU 的最优解**——**任务清晰分割 + 通信简单 + 性能匹配**。

**第二笔账：'光斑直径 ≤ 0.5cm' 是激光选型的硬约束**

题面要求**靶面光斑直径不超过 0.5cm**——**这反推回激光笔的'发散角'要求**。

激光笔的发散角公式：

```
光斑直径 = 激光笔出口直径 + 距离 × 发散角
```

**蓝紫激光笔（405nm，5mW，30 元）**典型参数——

- 出口直径 1mm
- 发散角 ≈ 2 mrad（弧度）

50cm 距离的光斑直径 = 0.1cm + 50cm × 0.002 = 0.1 + 0.1 = **0.2cm**——**远低于 0.5cm 上限**——**OK**。

但**如果用普通红色激光笔（650nm，5mW，10 元）**——**发散角 ≈ 5 mrad**——50cm 处光斑 = 0.1 + 50 × 0.005 = **0.35cm**——**仍然合规**。

**那为什么题目特意指定'蓝紫激光笔'？**

因为**靶面是紫外感光纸**——**只对 380~420nm 紫外线/蓝紫光敏感**——**红色激光照在感光纸上不留痕迹**——**评委没法量距离**——**直接 0 分**。

> **小白补课：紫外感光染料的吸收谱**  
>  
> 染料分子有特定的 '吸收带' ——只有特定波长的光能让它'激发态变化'——**变色**。  
>  
> 紫外感光纸常见染料 **MMQ（4-甲氧基-4'-甲胺基均三苯甲烷）**——**吸收峰在 380~410nm**——**蓝紫激光器（405nm）正好命中**。  
>  
> 红激光（650nm）、绿激光（532nm）能量小且不在吸收带——**纸面不变色**。  
>  
> **'蓝紫激光笔' 这一限定 = 题目给紫外感光纸做的物理基础**。

**第三笔账：'两个独立开关' 的工程意义**

题面强调**MSPM0 控制器和瞄准模块的电源分别由两个独立开关控制**——**这是'电源域分离'的工业标准做法**。

**电气意义**：

```
电源 1（小车）：3.7V 锂电 → LDO → MSPM0
                          → 电机驱动器 → 直流电机
                          
电源 2（瞄准）：3.7V 锂电 → LDO → STM32
                          → 舵机驱动 → 舵机
                          → 激光笔驱动 → 激光笔
```

**两个独立电池组 + 两个独立开关**——

- **小车电源开关 OFF**：MSPM0 不工作，**小车不动**
- **瞄准电源开关 OFF**：STM32 不工作，**激光不发光、云台不动**

**为什么要分开？因为电机和舵机在工作时会产生强烈的电源噪声**——

- 直流电机启动瞬间电流尖峰可达 5A
- 电机换向时 PWM 噪声 2~5V 波动
- 这些噪声会**严重污染共享的电源轨**

如果共用一个电源——**激光笔的电流被电机噪声干扰 → 激光强度波动 → 感光痕迹深浅不均**——**测试结果飘**。

**双独立电源 = 噪声隔离 = 系统可靠性提升**——**这是基本的电气工程原则**。

**坑——'两个独立电源' 不等于 '两个 18650'**

可以是：
- **两个独立电池组**（最干净）
- **一个大电池 + 两个独立 LDO + 两个独立开关**（折中，**国二队伍常用**）
- **一个大电池 + 共地分流 + 两个开关**（**违规！** 题目说 '电源' 不是 '开关'）

**国一标配 = 两个独立 18650 电池 + 两个独立 LDO**——**电气完全隔离**。

### 基本要求 (2)：静止瞄准任意位置 - 20 分

题目原文（第 30 行）：

> （2）将小车放置在场地中，**位置和姿态自定**。**启动瞄准模块在 2s 内发射激光击中靶心**，要求光斑痕迹距靶心**最大距离 D1 ≤ 2cm**。

**这一项 20 分非常重**——**'位置和姿态自定'+'2s 内瞄准'+'D1 ≤ 2cm'**——**三个条件叠加**。

**核心问题——'小车不知道自己在哪里 + 不知道靶在哪里'**

**位置和姿态自定** = 评委把小车放在**任意位置 + 任意朝向**——**小车启动时不知道自己在场地什么位置**。

**靶位置题面只说'AB 边外 50cm'**——**但 AB 方向上的位置不固定**——**评委可能放在 AB 中点也可能偏一边**——**靶心在场地坐标系下的精确位置不确定**。

**两个未知量都要在 2s 内确定**——**这就需要'视觉系统'**。

**实现方案——OpenMV 视觉找靶 + 几何反推**：

```c
// 步骤 1：上电后摄像头扫描场地，找到红色靶心圆
struct Point2D {
    float x_pixel;
    float y_pixel;
};
Point2D find_red_circle_in_image(Image_t img) {
    // OpenMV 自带的 find_circles + 颜色阈值过滤
    Circle_t* red_circles = find_circles(img, RED_COLOR_THRESHOLD);
    return centroid_of_largest_circle(red_circles);
}

// 步骤 2：根据像素坐标 + 摄像头标定参数 → 反推世界坐标
Point3D pixel_to_world(Point2D pixel, CameraCalib_t calib) {
    // 假设靶面与小车朝向垂直、距离已知
    float distance = calib.target_distance;
    float pan_angle = (pixel.x_pixel - IMAGE_CENTER_X) * calib.pan_per_pixel;
    float tilt_angle = (pixel.y_pixel - IMAGE_CENTER_Y) * calib.tilt_per_pixel;
    return distance_angles_to_world(distance, pan_angle, tilt_angle);
}

// 步骤 3：反算激光云台角度
void aim_laser_at_target(Point3D target_world) {
    float pan = atan2(target_world.y, target_world.x);
    float tilt = atan2(target_world.z, sqrt(target_world.x*target_world.x + target_world.y*target_world.y));
    servo_pan_set(pan);
    servo_tilt_set(tilt);
    laser_on();
}
```

**'视觉找靶 + 几何反推 + 云台对准'**——**OpenMV 50ms 找到靶心 + STM32 50ms 算云台 + 舵机 1s 转到位 = 1.1s**——**远低于 2s**。

**精度链**——

```
OpenMV 视觉找靶精度：±2 像素 = ±2mm
摄像头标定误差：±5%（5cm）
几何反推误差：±0.5°
云台舵机精度：±0.5°
合计：50cm 距离 ±1.5cm 偏差
```

**D1 ≈ 1.5cm**——**满足 2cm 要求**——**20 分稳稳吃下**。

**坑——OpenMV 的低光性能**

OpenMV 默认 800×600@30fps——**白天教室光线下找红色圆 OK**——**但比赛大厅可能光线昏暗**——**红色圆和白色场地的对比度下降**——**找圆精度 ±5 像素**。

**对策——'临场标定'**——**比赛前让 OpenMV 在赛场实际光照下重新跑一遍'颜色阈值'校准**——**精度 ±2 像素**。

**'临场标定' 这 30 秒是'国一/国二分水岭'**——**国一队伍永远把它写在调试清单第一行**。

### 基本要求 (3)：从指定位置自动瞄准 - 20 分

题目原文（第 32 行）：

> （3）将小车放置在**行驶轨迹上的指定位置**，**瞄准方向任意指定**。要求**启动瞄准模块在 4s 内自动瞄准发射激光击中靶心**，要求 **D1 ≤ 2cm**。

**这一项和 (2) 看似相似**——**实际上是 (2) 的'弱化版'**——**因为'指定位置'意味着小车的世界坐标已知**——**只需要找靶 + 反推角度**。

**'瞄准方向任意指定'**——**意味着评委可能让小车'激光初始指向偏 90° / 180° / 270°'**——**云台需要从随便一个起始角度自动瞄准**。

**为什么 (3) 给 4s 而不是 2s？**

因为云台舵机要从'任意角度'转到'目标角度'——**最坏情况要转 180°**——**舵机转 180° 需要 1.5~2s**——**留出余量 4s**。

**实现——和 (2) 类似但简化**：

```c
// 已知：小车在 A 点，朝向 0°（题面说放在 '指定位置'）
float x_c = 0, y_c = 0, theta_c = 0;

// 上电后步骤：
// 1. 找靶（视觉）→ 0.5s
// 2. 几何反推 → 0.01s
// 3. 云台从初始角度转到目标角度 → 最多 2s
// 4. 激光照射 → 0.5s
// 总计 < 3s，远低于 4s
```

**20 分轻松到手**。

**国一队伍的额外加分点——'多次平均消除噪声'**

舵机定位精度 ±0.5°——**这意味着每次启动瞄准的位置可能略有不同**——**多次启动求平均 → ±0.2°**：

```c
const int N = 5;
float sum_pan = 0, sum_tilt = 0;
for (int k = 0; k < N; k++) {
    Point2D target_pixel = find_red_circle();
    float pan, tilt;
    pixel_to_servo_angles(target_pixel, &pan, &tilt);
    sum_pan += pan;
    sum_tilt += tilt;
    delay_ms(100);
}
servo_pan_set(sum_pan / N);
servo_tilt_set(sum_tilt / N);
```

**精度从 ±0.5° → ±0.2°**——**对应 D1 从 1.5cm → 0.6cm**——**大幅超过 2cm 要求**。

### 发挥 (1)：跑 1 圈 + 持续瞄准 - 15 分

题目原文（第 36 行）：

> （1）要求 **N=1 圈**，**t ≤ 20s**，**D1 ≤ 2cm**。

**关键理解——'激光笔必须连续发光射向靶面'**——

> 运动期间激光笔必须**连续发光射向靶面**，**不满足要求不计成绩**。

**'连续发光'**——**激光笔不能闪烁、不能熄灭**——**任何瞬间灭灯都失败**。

**'射向靶面'**——**激光必须指向 A4 大小的靶纸所在的方向**——**不一定要射中靶心**——**只要打在靶纸上某个位置就行**。

**这一句话给了一个'逃生口'**——**小车在 BC、CD、DA 段时**，**云台可能因机械限位无法精确指向靶心**——**但只要激光指向靶纸方向**（例如指着靶纸上半区或下半区）——**就符合'射向靶面'**——**不会失败**。

**国一队伍的实战策略**：

```c
void update_laser_during_running() {
    Point3D target_center_world = (TARGET_X, TARGET_Y, TARGET_Z);
    
    // 计算理论激光角度
    float pan_ideal, tilt_ideal;
    geometric_inverse(target_center_world, x_c, y_c, theta_c, &pan_ideal, &tilt_ideal);
    
    // 限位检查
    float pan_clipped = clamp(pan_ideal, -SERVO_PAN_MAX, SERVO_PAN_MAX);
    float tilt_clipped = clamp(tilt_ideal, -SERVO_TILT_MAX, SERVO_TILT_MAX);
    
    // 如果被限位，记录 '指向偏离方向'
    bool aiming_at_target = (pan_clipped == pan_ideal && tilt_clipped == tilt_ideal);
    
    // 设置舵机
    servo_pan_set(pan_clipped);
    servo_tilt_set(tilt_clipped);
    
    // 关键——激光笔始终亮
    laser_on();  // 不管对不对靶心，激光必须连续发光
}
```

**'对靶心打 D1 ≤ 2cm' 的考核位置——只在 AB 段**——**因为 AB 段是 '靶面前方直线段'**——**云台机械限位最舒服**。

**评委用感光纸量距离时——只看 '在 AB 段照射时留下的痕迹离靶心多远'**——**其他段的偏移不算**。

**这就是'读题智慧'**——**国一队伍读出来的 'cheap shot'**——**节省工程量**。

### 发挥 (3)：同步画圆 - 15 分（终极考验）

题目原文：

> （3）要求 N=1 圈，t ≤ 20s，**激光笔沿靶面上半径 6cm 的红色圆弧同步画圆**，光斑痕迹与半径 6cm 的红色圆弧线**最大距离 D2 ≤ 2cm**；**小车行驶 1 圈，正好画 1 圈光斑**，**同步误差必须小于 1/4 圈**。

前面 '第四个谜' 已经详细讲过——**这是'珠穆朗玛峰'**。

**精度链——D2 ≤ 2cm 的要求**

```
小车位置精度：±1cm（角点精修）
小车朝向精度：±0.5°
云台精度：±0.5°
几何反推精度：±0.5°

```

**'同步误差小于 1/4 圈' 的要求**

- 1/4 圈 = 90°——**容差极宽**
- 用'弧长参数化'方法 ≈ ±5° 误差
- **远超容差** ——**轻松达标**

**真正的难点不在数学**——**在工程实现的细节**：

- **多 MCU 通信延迟（UART 100Hz 帧周期 10ms）**
- **舵机响应延迟（~100ms）**
- **小车在角点减速时'弧长参数 s'增长不均匀**

**国一队伍的 '舵机预测控制'**——**预测小车下一时刻位置 + 提前发舵机指令**——**抵消延迟**：

```c
// 预测小车下一帧（10ms 后）的位置
float next_x = x_c + vx * 0.01;
float next_y = y_c + vy * 0.01;
float next_theta = theta_c + omega * 0.01;

// 用预测位置算云台角度（提前发命令补偿延迟）
geometric_inverse(target_world, next_x, next_y, next_theta, &pan, &tilt);
servo_pan_set(pan);
servo_tilt_set(tilt);
```

**'预测控制' 把 100ms 舵机延迟抵消 80%**——**D2 从 ±3cm → ±1.5cm**——**稳过 2cm 关**。

### 发挥 (4)：其他 - 5 分

题目原文：

> （4）其他。

**电赛传统加分项**——**5 分**——**展示创意空间**。

常见方向——

**方向 A：增强瞄准能力**
- **多靶切换**——**场地放 2~3 个靶，激光按顺序击中每个**
- **移动靶追踪**——**靶被人手移动，激光跟踪**
- **靶纸自动识别**——**评委放任意位置激光自动找靶**

**方向 B：用户体验**
- **手机 APP 实时显示小车位置和激光角度**
- **历史轨迹回放**——**LCD 显示走过的路径 + 击中的位置**
- **声光指示**——**击中靶心时蜂鸣器响 + LED 闪**

**国一标配 = 方向 A 中的 1 项 + 方向 B 中的 1 项**——**5 分稳吃**。

### 说明里的暗坑

题目'说明'部分看起来像免责条款——**每一条都是关键信息**。

**说明 (1)——小车尺寸限制**

> 作品中的小车尺寸**不大于 25cm（长）×15cm（宽）× 25cm（高）**。**小车尺寸包括小车以及所安装瞄准模块总体轮廓尺寸**。

**关键——'包括瞄准模块'**——**小车 + 云台 + 激光笔 + 摄像头 + 显示屏**全部加起来**不超过 25×15×25 cm**。

**实战上**——

```
小车底盘：18×12cm（GMR 电机 + 编码器 + 万向轮）
电池仓：5×8cm × 高 5cm（两组 18650）
MCU 主控板：6×4cm
云台 + 舵机：高度 8cm + 直径 6cm
激光笔头：直径 1cm + 高度 2cm
OpenMV 摄像头：4×4×3cm
LCD：4×4cm
```

**总体高度** = 5（电池）+ 4（主控）+ 8（云台）+ 2（激光笔）= **19cm**——**远低于 25cm 限制**。

**总体长 × 宽** = 18×12——**远低于 25×15**。

**'尺寸不超限'** = **设计余量充足** = **可以放心增加冗余**。

**说明 (1) 续——'轮式小车，不得采用履带和麦氏轮'**

和 2024 H 题相同的限制——**前面 '第二个谜' 已讲**——**强制用差速底盘**。

**说明 (1) 续续——'不得人为干涉、遥控小车运动'**

**严格的'自主'要求**——**任何遥控/有线/无线干涉都违规**。

**'中途不得更换电池'**——**4 天 3 夜调试时电池可以反复充电，但'测试环节'中不能换**——**电池续航 > 5 分钟**。

**说明 (2)——'MSPM0 控制板必须裸露 MCU 型号'**

**评委会现场看你的 MSPM0 芯片是否暴露**——**前面 '第二层' 已讲**。

**'用发光管显示每个控制板的供电状态'**——**两个独立 LED 分别显示 MSPM0 和瞄准模块电源状态**——**便于裁判一眼看出'两个独立电源'是否真的工作**——**1~2 元的小细节**。

**说明 (3)——'靶面尽量靠墙竖立'**

**为什么靠墙？**因为评委要**精确测量靶心到 AB 边的距离 50cm**——**靠墙保证靶面不晃**——**测量基准稳定**。

**'参赛队对周围环境不得有其他特殊要求'**——**意味着你的视觉系统要能在普通教室光照下工作**——**临场标定是必须**。

**'除题目要求的边线之外，行驶场地上不得有其他任何符号标记'**——**禁止贴二维码 / 反光柱 / 蓝牙信标**——**和 2024 H 题一致的'禁止外援导航'**。

**说明 (4)——激光笔安全提示**

> 蓝紫激光笔建议使用**波长 405nm、光功率 ≤ 10mW** 的激光笔。

**405nm 蓝紫光，5~10mW**——**Class IIIa 激光**——**短时直视眼底有损伤但安全**——**淘宝 30~80 元**。

**'10mW' 是上限**——**别买更高功率的（IIIb / IV 类有失明风险，违法）**。

**'切勿照射人眼睛和皮肤'**——**比赛时永远把激光笔指向靶或地面**——**调试时戴防紫外护目镜**——**这是工程师的基本素养**。

**说明 (4) 续——'紫外感光纸只有一面有感光特性，可重复使用'**

**'重复使用'** = **痕迹会自然褪色 20~60s 后消失**——**比赛时一张纸可以多次测试**——**省钱**。

**'只有一面有感光特性'**——**贴在靶上时不能贴反**——**调试时容易出错**——**调试清单第一行**。

**说明 (5)——评分细则**

> Di ≤ 2cm（i=1, 2）为满分，**Di 每增加 1cm 扣 1 分，不足 1cm 按 1cm 计算**。所有含时间测试要求**如果超时，该项计 0 分**。

**关键——'超时一律 0 分'**——**别想着'超时能拿部分分'——**完全不行**。

**'每多 1cm 扣 1 分'**——**比 2cm 多 5cm = 扣 5 分**——**还有 10 分可拿**——**基本要求 (2) 退化路径**。

**调试时优先保证'不超时' > '精度高'**——**先做完再优化**。

**说明 (6)——'测试时，场地喷绘布和制作的目标靶可以自带'**

**这一条是'白送的礼物'**——**和 2024 H 题相同的'临场试跑'**——**比赛前用自己带的场地标定 + 实测**——**精度提升 2 倍**。
