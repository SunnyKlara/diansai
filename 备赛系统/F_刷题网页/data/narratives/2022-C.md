**核心物理模型**——**两车间距像"一根弹簧"**：

- **太近**（< 14cm）→ **跟随车减速 / 后退**——**怕撞**
- **太远**（> 26cm）→ **跟随车加速**——**怕掉队**

**这就是"恒间距跟随（Constant-Distance Following）"** 控制——**自动驾驶 ACC 的核心算法**。

## 第一个谜：跟随车怎么知道前车有多远

**测距是跟随系统的"眼睛"** —— **测得不准 → 跟随失败**。

**4 种主流测距方案**：

**方案 A：超声波测距（HC-SR04）**

```
价格：5 元 / 个
量程：2cm ~ 4m
精度：±3mm
更新率：10Hz（100ms / 次）
缺点：方向性弱、易受环境噪声干扰
```

**优点**：**便宜、便宜、便宜**。  
**缺点**：**100ms 更新率太慢**——**车以 1m/s 速度跑** = **每 100ms 走 10cm**——**跟随精度 ±10cm 起步**。

**方案 B：红外距离传感器（VL53L0X / GP2Y0A21）**

```
VL53L0X：激光测距，量程 0~120cm，精度 ±3%，更新率 50Hz
GP2Y0A21：红外三角，量程 10~80cm，精度 ±5cm，更新率 25Hz
```

**优点**：**激光精度高 + 50Hz 够快**。  
**缺点**：**VL53L0X 在阳光下精度下降**——**电赛室内场地通常没问题**。

**国二常用**：**VL53L0X**——**100 元搞定**——**精度 ±3cm**。

**方案 C：UWB 双向测距（DW1000）**

```
UWB（Ultra-Wideband）：超宽带无线测距
精度：±10cm
更新率：100Hz
范围：0~50m
```

**优点**：**远距 + 高速更新 + 无视觉遮挡**。  
**缺点**：**贵（150 元 / 套）+ 需要双车都装**。

**方案 D：摄像头视觉测距（OpenMV）**

**OpenMV 看后车贴的"色块标签"** —— **算面积反推距离**：

```python
# OpenMV 代码
img = sensor.snapshot()
blobs = img.find_blobs([(50, 100, 0, 100, 0, 100)])  # 找绿色块
if blobs:
    largest = max(blobs, key=lambda b: b.area())
    # 距离反推：area 越大距离越近
    distance = SCALE_FACTOR / largest.area()
```

**优点**：**抗干扰强 + 能识别"是不是前车"** **。  
**缺点**：**OpenMV 帧率 0.3s/帧 = 3Hz**——**响应慢**——**只适合静态跟随**。

**国一选择**：**UWB DW1000**——**双车互测距 + 100Hz 更新 + ±10cm 精度**——**完美**。  
**国二**：**VL53L0X 激光测距**——**单向测，跟随车看前车**——**够用**。  
**国三**：**HC-SR04 超声**——**勉强**。

**第一笔账：测距精度对成绩影响**

题目要求 **20cm ± 6cm**——**意味着测距精度必须 ≤ 6cm**。

| 方案 | 精度 | 满足要求 |
|---|---|---|
| HC-SR04 | ±3mm（理论）但受噪声影响 ±20mm | ✓ |
| VL53L0X | ±3cm | ✓ 余量大 |
| UWB | ±10cm | **✗ 边缘** |
| OpenMV 视觉 | ±5cm（取决于标签大小）| ✓ |

**注意**：**UWB 的 ±10cm 精度刚好等于容差上限 ±6cm 的 1.7 倍——满足任务 1 的"6cm 误差"** 边缘——**UWB 单独用风险大**。

**对策**：**UWB + VL53L0X 融合**——**UWB 测远距（追上阶段）+ VL53L0X 测近距（紧跟阶段）**——**双传感器互补**。

**国一队伍**：**双传感器融合**——**精度 ±2cm**——**远超要求**。

## 第二个谜：跟随车的"恒间距控制"** 怎么做

**核心控制目标**：**让 d_actual = 20cm**——**用 PID 调速度**：

```c
// 控制循环 100Hz
float distance_error = 20 - distance_measured;  // 期望距离 - 实际距离
                                                 // > 0：太近，需减速
                                                 // < 0：太远，需加速

// 跟随车速度参考
float v_follower = v_leader + Kp * distance_error + Kd * d_error_rate;
```

**这段代码说的其实是**——**'**跟随车速度 = 领头车速度 + 距离误差修正**'**——**距离短就减速，距离长就加速**。

**第一笔账：Kp 太大 vs 太小**

```
Kp 太大 → 距离短就猛减速、长就猛加速 → 车头一冲一冲（振荡）
Kp 太小 → 反应慢 → 距离误差大
Kp 刚好 → 平稳跟随
```

**经验值**：**Kp = 0.05 ~ 0.1（速度单位 m/s，距离单位 cm）**——**意味着"距离差 10cm 时速度修正 0.5 m/s"**。

**第二笔账：跟随车怎么知道领头车速度**

**方案 A：通信告诉**

```c
// 领头车每 50ms 发一次速度
uart_send_packet(my_speed, my_state);

// 跟随车收到
v_leader = received_speed;
```

**优点**：**精确** + **无延迟（< 5ms）**。  
**缺点**：**通信丢包 → 跟随车不知道当前 v_leader → 用上一次的值**。

**方案 B：测距推算**

```
v_leader_est = v_follower + (d_now - d_prev) / dt
```

**这个式子说的其实是**——**'**领头车速度 = 跟随车速度 + 距离变化率**'**——**'**测距数据求导**' = 速度推算**。

**优点**：**不依赖通信**。  
**缺点**：**测距噪声放大** = **速度估计抖动**——**需要滤波**。

**国一方案**：**通信 + 测距互验**——**双重保险**。

**第三笔账：双 PID 嵌套（速度 + 距离）**

```c
// 外环：距离 PID
float v_target = v_leader + Kp_d * (d_target - d_actual);

// 内环：速度 PID
float pwm_diff = Kp_v * (v_target - v_actual) + Ki_v * v_integral;
left_pwm += pwm_diff;
right_pwm += pwm_diff;
```

**两层 PID**：**外环管"距离对不对"** + **内环管"速度跟得上不"** ——**两层带宽分离**：

- **外环带宽**：**5~10 Hz**（**距离慢变**）
- **内环带宽**：**50~100 Hz**（**速度快响应**）

**和 2024 H 题、2021 B 题一样的"级联 PID"** 思想——**这是控制工程的通用结构**。

## 第三个谜：怎么"超车"** 而不撞车

**任务 3** 是真正的难点——**两车在同一跑道上 2 次超车 + 不撞车**：

```
第 1 圈：领头跑外圈，跟随跑外圈
第 2 圈：领头跑外圈，跟随跑内圈（超车）
第 3 圈：领头跑内圈，跟随跑外圈（反超）
```

**'**内圈**'** 是"近路"** —— **走 BFD 短直线**——**比外圈短 30%**——**所以跑内圈的车速度优势 → 自然超车**。

**第一笔账：路径选择的物理原理**

```
外圈 ABCDE 总长 ≈ 12 m
内圈 ABFDE 总长 ≈ 8 m
内圈短 33%
```

**'**领头跑内圈、跟随跑外圈**'** = **跟随车跑得远 + 领头车跑得近**——**跟随车自然落后**——**不会追尾**。

**'**领头跑外圈、跟随跑内圈**'** = **跟随车跑得近**——**追上 + 超过领头**——**实现超车**。

**这个题目设计很巧妙**——**用"路径长度差"** 自然实现超车——**不需要精确碰撞控制**——**只要"切对岔路"** 即可**。

**第二笔账：怎么"切岔路"**

外圈和内圈在 B 点和 D 点分叉——**车体到达分叉点时要决定走哪条**。

**对策**：**循迹算法识别"岔路"** + **状态机决定方向**

```c
case STATE_FOLLOWING_LINE:
    if (intersection_detected()) {
        // 根据状态机决定走哪条
        if (current_lap == 2 && am_i_follower) {
            turn_to_inner_loop();  // 跟随车走内圈
        } else {
            continue_outer_loop();  // 默认外圈
        }
    }
    break;
```

**'**岔路识别**'** 怎么实现？——**5 路红外传感器同时读到黑线 → 是岔路**：

```c
bool intersection_detected() {
    int black_count = 0;
    for (int i = 0; i < 5; i++) {
        if (ir_sensor[i] == BLACK) black_count++;
    }
    return (black_count >= 4);  // 至少 4 路读到黑 = 岔路
}
```

**精度**：**5 路传感器宽 5cm**——**岔路宽度也是几厘米**——**精度 ±1cm**。

**第三笔账：超车时的"防撞"**

超车瞬间——**两车可能并排行驶**——**距离从"前后 20cm"** 变成"侧向 5cm"** —— **测距传感器（前向单点）** 测不出**。

**对策**：**领头车主动"通知"** 跟随车正在超车 + **跟随车降低距离阈值**：

```c
// 领头车
if (entering_superpass_zone()) {
    send_msg("SUPERPASS_START");
    set_safety_distance(10);  // 临时把安全距离从 20 降到 10
}

// 跟随车收到
if (received_msg == "SUPERPASS_START") {
    set_safety_distance(10);  // 同步降低
    // 同时降低速度防侧撞
    set_speed(0.5);
}
```

**国一队伍**：**实现完美超车（< 5cm 间距且不碰撞）+ 大速度差**——**满分 30**。  
**国二**：**勉强超车（10~20cm 间距）+ 速度均匀**——**20 分**。  
**国三**：**超车失败 / 撞车**——**0 分**。

## 第四个谜：怎么"同时停"——1 秒误差不超过

**任务 1~4 都要求**：**领头停车 → 跟随车 1 秒内停 + 距离 20±6cm**。

**'**1 秒**'** 是什么概念？

```
0.3 m/s × 1 秒 = 30 cm
1 m/s × 1 秒 = 100 cm
```

**意味着**：**领头停车后 1 秒内，跟随车不能多走 30~100cm**——**否则会撞**。

**对策**：**领头车提前发"准备停车"** 信号 + **跟随车同步减速**：

```c
// 领头车
if (distance_to_A_point < 20cm) {
    send_msg("PREPARE_STOP");
    decelerate_smoothly();
}
if (at_A_point) {
    send_msg("STOP_NOW");
    motor_stop();
}

// 跟随车
case "PREPARE_STOP":
    decelerate_smoothly();  // 跟着减速
    break;
case "STOP_NOW":
    if (distance_to_leader > 14cm) {  // 还没到 20cm 容差
        slow_creep_forward();  // 缓慢爬到位
    } else {
        motor_stop();
    }
    break;
```

**这段代码说的其实是**——**'**领头预报 + 跟随同步减速 + 末端微调**'**——**典型的"前馈 + 反馈"** 控制。

**第一笔账：通信延迟的影响**

通信延迟 5ms（NRF24）——**跟随车收到信号时已经"晚 5ms"** ——**1m/s 速度下多走 5mm**——**对 6cm 容差几乎无影响**。

但如果用蓝牙 BLE（30ms 延迟）——**多走 30mm = 3cm**——**6cm 容差里耗掉一半**——**风险大**。

**这就是为什么 NRF24 / ESP-NOW 是首选**——**通信延迟是任务 1 ~ 4 的隐形杀手**。

**第二笔账：末端微调**

**场景**：**领头停在 A 点 → 跟随车此时距离 30cm（远了 10cm）**——**跟随车需要"爬"** 10cm 才能到 20cm**。

```c
// 末端慢爬
while (fabs(distance - 20) > 3) {
    if (distance > 20) {
        set_speed(0.05);  // 慢速前进
    } else {
        motor_stop();
    }
}
```

**'**末端微调**' 速度 0.05 m/s = 5 cm/秒**——**爬 10cm 用 2 秒**——**会超过"1 秒同步停"** 要求！

**对策**：**领头车在停车前 0.5 秒就发"PREPARE_STOP"** ——**让跟随车有时间预先减速**——**到达时距离已经是 20cm**——**直接停**——**不需要末端微调**。

**国一队伍**：**预报 + 同步减速 + 0 末端微调**——**1 秒误差 < 0.3 秒**——**距离误差 < 2cm**——**满分**。  
**国二**：**有末端微调 + 1 秒误差 = 0.8~1.0 秒**——**勉强**——**18 分**。  
**国三**：**超时 1 秒**——**0 分**。

## 第五个谜：等停标识的识别

**任务 4** 要求：**领头车遇到"等停指示"** 立即停车 + **停车位置准确（误差 ≤ 5cm）+ 停 5 秒（误差 ≤ 1 秒）**。

**'**等停指示**'** 是**两条间隔 5cm 的黑色平行线**——**循迹时 5 路传感器会"读到 2 条黑线"**——**和"普通引导线（1 条）"** 不同。

**识别算法**：

```c
case STATE_FOLLOWING_LINE:
    if (detect_double_line()) {
        // 等停标识
        motor_stop();
        wait_5_seconds();
        resume_following();
    }
    break;

bool detect_double_line() {
    // 时间窗口 100ms 内检测到 2 次黑线
    static int line_count = 0;
    static uint32_t last_time = 0;
    
    if (any_sensor_black() && (now - last_time > 50)) {
        line_count++;
        last_time = now;
    }
    if (now - last_time > 200) {
        line_count = 0;  // 重置
    }
    
    return (line_count == 2);
}
```

**这段代码说的其实是**——**'**100ms 内连续读到 2 次黑线 = 等停标识**'**——**简单稳定**。

**第一笔账：停车位置精度**

题目要求 **5cm**——**车体长 25cm**——**意味着车头 ± 5cm 落在第二条黑线之内**。

**1m/s 速度下的"刹车距离"**：

```
v² / (2 × a) = (1)² / (2 × 5) = 0.1m = 10cm
```

**'**a = 5 m/s²**'** 是普通直流电机 + 电气制动的典型加速度**。

**10cm 刹车距离 > 5cm 容差** —— **意味着不能 1 m/s 速度下硬刹**。

**对策**：**接近等停标识前减速**：

```c
// 距离等停标识 30cm 时开始减速
if (distance_to_marker < 30cm) {
    set_speed(0.3 m/s);
}
// 距离 10cm 时进一步减速
if (distance_to_marker < 10cm) {
    set_speed(0.1 m/s);
}
// 触发标识立即停
if (detect_double_line()) {
    motor_brake();  // 电气制动
}
```

**'**距离等停标识 30cm**' 怎么知道**？——**测试人员"指定位置"** 是事先知道的——**测试时由测试专家放置**——**领头车看到第一条黑线就知道"标识来了"**。

**第二笔账：5 秒计时**

```c
case STATE_AT_STOP:
    static uint32_t stop_start = 0;
    if (stop_start == 0) stop_start = now;
    
    if (now - stop_start >= 5000) {  // 5 秒
        stop_start = 0;
        state = STATE_RESUMING;
    }
    break;
```

**'**5 秒误差 ≤ 1 秒**'** 意味着**精度 20%**——**MCU 计时器精度 0.001%**——**远超要求**——**满分**。

## 把题目逐条翻译一遍

### 任务那段话

> 设计一套小车跟随行驶系统，**采用 TI 的 MCU**，由**一辆领头小车和一辆跟随小车组成**，要求小车具有循迹功能，且**速度在 0.3 ~ 1m/s 可调**。

任务核心：

- **必须用 TI MCU**（**MSP432P401R 或 TM4C123 是 2022 年主流**）
- **双车**（**领头 + 跟随**）
- **循迹 + 跟随双任务**
- **速度 0.3 ~ 1 m/s 自适应**

**4 个测试任务 + 内外圈双跑道 + 等停指示** = **复合任务**。

### 任务 1：紧跟 + 0.3 m/s（20 分）

> 跟随小车放在其后 20cm 处，设定领头小车速度为 0.3m/s，沿着外圈路径行驶一圈停止。

**要求 (1)：领头平均速度误差 ≤ 10%**

```
0.3 m/s × ±10% = 0.27 ~ 0.33 m/s
```

**速度精度 ±10%** —— **简单**——**只要 PID 速度环带宽 > 5Hz 即可**。

**要求 (2)：全程不能碰撞**

**前面已经讲过双 PID + 多传感器融合**——**国一 ±2cm 精度**——**满分**。

**要求 (3)：1 秒同步停 + 距离 20±6cm**

**前面已经讲过预报 + 同步减速**——**国一 < 0.3 秒**——**满分**。

20 分稳拿。

### 任务 2：远距追上 + 0.5 m/s（20 分）

> 跟随小车放在路径上 **E 点所在边的直线区域，由测试专家指定的位置**，设定领头小车速度为 0.5m/s。

**初始情况**：**跟随车在领头车后面 1~3 米**——**距离很远**——**需要"快速追上"**。

**第一笔账：追上策略**

```c
// 远距追上模式
if (distance_to_leader > 100) {
    set_speed(MAX_SPEED);  // 用 1m/s 满速追
}
// 接近后切换跟随模式
if (distance_to_leader < 50) {
    enter_follow_mode();
}
```

**'**远距用满速 + 近距切跟随**'** 是车队追上的标准策略——**像高速公路上后车追前车**。

**第二笔账：何时减速**

```
追上速度 1 m/s
跟随速度 0.5 m/s
速度差 0.5 m/s
刹车距离 = 0.5² / (2 × 5) = 25 mm = 2.5 cm
```

**'**2.5cm 刹车距离**'** 远小于 50cm 切换距离——**绰绰有余**。

但**实际情况**——**测距传感器有 5~10cm 噪声**——**追上瞬间可能会"过冲"** 撞上**。

**对策**：**用一阶平滑滤波 + 提前减速**：

```c
distance_filtered = 0.7 * distance_filtered + 0.3 * distance_raw;
if (distance_filtered < 80) {
    set_speed(0.7);  // 提前减速
}
if (distance_filtered < 50) {
    set_speed(0.5);  // 同步速度
}
```

20 分稳拿。

### 任务 3：双超车 3 圈（30 分）

> 第一圈领头和跟随都沿外圈。第二圈**领头沿外圈，跟随沿内圈，实现超车领跑**。第三圈**跟随沿外圈，领头沿内圈，实现反超**。

**这是 2022 C 的核心难点**——**30 分**。

**前面已经讲过路径选择算法 + 状态机切换**——**国一 30 分稳拿**。

**第一笔账：超车后两车角色互换**

```
第 1 圈：car1 = leader, car2 = follower
第 2 圈：car1 跑外圈（速度 0.5），car2 跑内圈（速度 0.7）→ car2 跑得快 → 第 2 圈结束 car2 超过 car1 → 角色不变但 car2 在前
第 3 圈：car1 跑内圈（快），car2 跑外圈（慢）→ car1 反超
```

**'**领头 / 跟随**' 角色不变 → 用"标签"** 而非"位置"** 判断身份——**避免角色混乱**。

**第二笔账：行驶速度自主设定**

> 小车行驶速度可自主设定，但**不得低于 0.3m/s**，且**完成所规定的三圈轨迹行驶所需时间越短越好**。

**速度越快 → 时间越短 → 分越高**——**但速度太快 → 控制难度大 → 撞车扣分**。

**国一选择**：**外圈 0.6 m/s，内圈 0.4 m/s（弯道多，慢）**——**3 圈总时间约 60 秒**——**满分 30**。

### 任务 4：等停 + 1 m/s（20 分）

> 设定领头小车速度为 **1m/s**，沿着外圈路径行驶一圈，**遇到"等停指示"** 立即停车（误差 ≤ 5cm）+ 停 5 秒（误差 ≤ 1s）。

**前面已经讲过等停识别 + 提前减速**——**国一 20 分稳拿**。

**第一笔账：1 m/s 速度的挑战**

```
1 m/s = 100 cm/s
循迹反应时间需要 < 50ms（5cm 容差）
PID 控制循环 > 100Hz
```

**'**100Hz 控制循环**'** 是 1 m/s 高速循迹的最低要求——**TI MSP432 80MHz 远超**——**完全满足**。

**第二笔账：刹车距离**

```
刹车距离 = 1² / (2×5) = 10 cm
```

**意味着"看到等停标识第 1 条黑线就开始减速"** —— **第二条黑线（5cm 后）刚好刹住**——**精度 5cm**——**正好满足要求**。

20 分稳拿。

### 说明里的暗坑

**说明 (1)：尺寸限制**

> 小车尺寸不大于 **15cm（宽）× 25cm（长）**。

**比 2024 H（25 × 20 × 25）小一档**——**意味着双车并排时只占 30cm 宽**——**两条引导线（外 + 内）相隔 30cm 以上**——**测试场地够大**。

**说明 (2)：场地铺设**

> 行驶场地上铺设白纸，行驶路径用 **1cm 宽的黑色引导线**来标志。

**1cm 黑线** 比 **2024 H 的 1.8cm 黑线**窄——**5 路红外传感器（间距 12mm）只有 1 颗能压上线**——**循迹精度受影响**。

**对策**：**用 5 路高密度（间距 8mm）传感器** 或 **加权质心算法**——**精度提升**。

**说明 (3)：跟随车只有上电开关**

> 跟随小车**只有一个上电开关**，不得有其他启动和操作按键。

**意味着**：**跟随车上电后 = 待命状态**——**等领头车通过通信发"启动"** 指令。

**对策**：**跟随车上电后进入"等待模式"** —— **持续监听 NRF24 / ESP-NOW**——**收到启动指令立即响应**。

**说明 (4)：除车间通信外不得有外部辅助**

> 不得有车外**遥控**和其他通信指令辅助。

**禁止**：**手机、电脑、外部基站等任何"外援"** —— **两车必须完全自给自足**。

**说明 (5)：等停精度**

> 领头小车遇到"等停指示"** **需立即停车**，停车后**车身应在"等停指示"** 第二条横线以内**。

**意味着**：**车头不能超过第二条黑线**——**车头超出多少 = 停车位置误差**。

**说明 (6)：刻度尺辅助**

> 允许在制作行驶场地时，在路径的 **E 点和 A 点的旁边画上刻度尺**。

**'**画刻度尺**'** = 测试时方便测距——**评委用尺子读"间距"** —— **要求小车停车精确到刻度**。
