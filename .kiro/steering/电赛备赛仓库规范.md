## 记忆与交接（AI 不失忆 · 每对话必守）

- **新对话第一件事**:先读根目录 `CONTINUATION_GUIDE.md`(整个备赛进度/下一步/阻塞),**再 `git log`/`git status` 对账**——git 是状态真值、文档会滞后,冲突信 git、先纠正 guide 再干活。
- **提交即清账**:一条工作线 commit/push 了,立刻把它从 `CONTINUATION_GUIDE.md` 挪进 `knowledge/决策与交接归档.md`,**绝不留「未提交/进行中」过时字样**(这是新对话被带偏去重做已完成事的头号原因)。

- 这三条是「诚实标注」在**工作线状态**维度的落地——没验证标「待验证」,没做完别写「已完成」。

## 规则优先级链（冲突时按此裁决,高位压低位）

## 做新题的工作流(省赛核心)

新题在 workbench 开工,做完把经验沉淀回 skills/library:

1. **审题第一步,不可跳过**:按 [`skills/01_审题破局/审题与选题SOP.md`](../../skills/01_审题破局/审题与选题SOP.md) 产出"叙事+夹多方案"的深度分析(黄金范例 `web/data/narratives/2026-B.md`)。**禁止跳过审题直接写代码——这是电赛失分最大的坑。**
2. **建题目文件夹**:在 `workbench/` 下建 `2026-<题号ASCII>_<题名>/`(题号用 ASCII,如 `2026-C`),按 `workbench/_工作台工作规范.md` 组织。
3. **破局**:按 [`skills/01_审题破局/破局引擎.md`](../../skills/01_审题破局/破局引擎.md) 填 `00_破局作战地图.md`。
4. **工程**:`工程_<平台>/` 里三层写码;**控制/悬浮/小车类题可拷 `实战复盘/校赛B_智能球平衡控制装置/工程_STM32H750/` 起步**(有真机验证的驱动/PID)。先查 `library/`。
5. **代码必须真机/PC 验证后才算数**:没上板的代码顶部标 `// 待真机验证`;真板子调通才算成果。
6. **边做边记** `调试日志.md`(真实数据 + 踩的坑),赛中只维护"作战地图 + 调试日志"两份。做完把可迁移经验回补 `skills/`(参照 `实战复盘/校赛B/00_经验总结.md`)。

## 诚实标注铁律（核心,防止再产生 paper 误导）

- **未经真机/PC 验证的代码/方案/BOM,一律显式标注 `待验证` / `// 未实测`**,绝不写成"已完成/可复刻/0错误"。
- 真机跑通的,标注实测数据(avg/std/指标)才算"真"。
- 报告、评分、成绩:是预估就写"预估",不假装真实成绩。
- **宁可承认"没做过",也不制造"看起来做完了"的假象**——那正是这次清理要根除的病。

## 代码风格

- C 代码:4 空格缩进,函数名 `snake_case`,宏 `UPPER_SNAKE`。
- 每个 `.c` 配对 `.h`,`.h` 用 `#ifndef/#define/#endif` 防重包含。
- 驱动层(Drivers)与算法层(Algorithm)严格分离,禁止驱动里写业务逻辑;算法层不依赖 HAL,可 PC 单独编译验证。
- 关键参数(PID/采样率/阈值/限幅)集中 `config.h`。

## Markdown 写作约定

- `.md` 首行必须一级标题(例外:审题文档可在 H1 前置 YAML front-matter 作元数据,网页渲染速览卡)。
- 指标/参数用 Markdown 表格;代码块标语言(```c / ```python / ```bash)。
- 引用器件必须给**完整型号 + 关键参数 + 数据手册链接**;BOM 含序号/名称/型号/参数/数量/用途/备注。

## 提交与推送规范（Solo 主干开发 / Trunk-Based）

- **放行闸门 = 用户一句"可以提交/提交吧"**。放行后 AI 直接 `commit` + `push origin main`,不开 PR、不开功能分支。
- **直接在 `main` 工作**,`main` 保持"可编译不破";每个 commit 单一目的。
- **commit 格式**:`<类型>(可选scope): <简述>`,类型 `feat/fix/docs/refactor/test/chore`。
- **push 即备份,要勤**(仓库在桌面,更需异地兜底)。
- 短命分支仅用于高风险大改(`exp/<简述>`),验证完立即合回删除。里程碑用 annotated tag。
- **高危操作需显式确认**:`git push --force`、`reset --hard`、删除整个目录、改 git 配置。
- 提交前确认 `.gitignore` 生效,不带入 `*.apk`、Keil 编译产物、临时截图。
- 统一 `git config core.quotepath false`。看尾行 `xxx -> main` 即视为 push 成功(别被 PowerShell 把 stderr 当 error 骗停)。

**赛场态 / 真机冲刺时额外守（防丢 + 便复盘）**：

- **每达一个里程碑/参数达标就立刻 commit**——赛场断电/死机/误删丢几小时代码是灾难，没有"重来"。宁可 commit 碎一点。
- **达标参数第一时间回填 `config.h` 再 commit**（校赛B 铁律：达标即锁死，别让它漂回去、别只留在串口窗口里）。
- **里程碑打 annotated tag 带数据**：`git tag -a m1-悬浮达标 -m "15cm std 0.37cm"`，赛后复盘/答辩秒定位"哪一版最好"。
- **触发降级/换打法（5 分钟原则）也 commit 记一笔**（`chore: 降级X→Y，原因Z`），留决策痕迹，别静默丢掉。
- **每个阶段收尾 push 一次**（仓库在桌面，异地兜底；赛场用手机热点也要推）。

## 自主执行铁律

> 用户多次强调:**只验收成果,不验收过程。** 长期任务全程自主,不中途停下索取确认。

1. **永不停下等命令**:选择题(方案 A/B/C)自己拍板,理由写进作战地图/审题文档,事后用户可推翻。
2. **永不索要权限**:仓库内文件创建/编辑/批量生成/`commit`/`push main` 均为低风险,放行后直接执行。仅 `push --force`/`reset --hard`/删整目录等高破坏操作才确认。
3. **遇错自愈**:编译/语法/格式错误自己修;缺资料基于公开数据手册和工程经验补;拿不到就标 `TODO` 继续,不阻塞主线。
4. **验收标准只有一个**:用户要的最终物齐全可用即合格。过程中反复请示视为执行失败。
5. **本节压过** `<default_to_action>` 的"先读后写"保守倾向——生产场景下**直接动手**优先。
6. **唯一该"出声"的例外 = 争议前置（不违反第 1 条）**：对**方向性重大风险**——可能撞物理地板（校赛B E2 最痛教训：指标贴物理墙还硬磨几天）/ 投入产出严重不值 / 平台·选型可能是错路 / 一次要重写一大片——AI **必须主动先说**（一句话点破 + 给替代方案），最多争 2 轮；用户坚持后记进 `knowledge/跨题坑库.md` 并全力执行。第 1 条拦的是"执行细节请示"，本条要的是"重大方向预警"，两者不冲突：**能自己拍板的别问，可能翻车的方向必须提。**

## 安全与合规

- 禁止把 `.apk`、私钥、`.env`、个人证件信息入库。
- 引用第三方代码保留原作者声明。
- PDF 题目原件可入库;禁止把官方未公开内部资料入库。
