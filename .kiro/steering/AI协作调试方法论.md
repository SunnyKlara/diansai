# AI×人 协作调试方法论

> 本文沉淀自一次**真机把悬浮球 PID 从完全调不出来到稳定悬浮**的成功对话。
> 它定义的不是"某道题怎么做"，而是**调试硬件/控制类问题时，AI 和人怎么配合**。
> 后续所有"上板调试 / 整定 / 找参数 / 排障"类工作，**默认按本流程协作**。
> 这次之所以成功，靠的就是下面这套分工与纪律——不是靠运气，要可复现。

## 0. 一句话总纲

> **AI 负责"动手 + 量化"，人负责"看现象 + 定方向"，每轮只动一个变量，用数据裁决，AI 错了立刻自我推翻。**
> 闭门造车失败的根因是"在多维耦合空间里靠猜搜参数"；本流程把它降维成"一次一维 + 实测闭环"。

## 1. 角色分工（不要越界）

| 角色 | 负责 | 不要做 |
|---|---|---|
| **AI** | ① 驱动工具链(编译/烧录/串口收发) ② 跑一次测一次、解析出**定量指标**(avg/std/ptp/上升时间) ③ 解释机理、提出下一步**单一**改动 ④ 发现自己判断错时**立刻翻案** | 不要一次改一堆参数；不要在没数据时硬猜；不要嘴硬维护错误判断 |
| **人** | ① 看屏幕/看实物的**定性现象**(高频抖？跑高？卡顿？这些 AI 看不到) ② 拍板方向("加点 Kd"/"缩 slew") ③ 真机现象与数据矛盾时做裁决 | 不要替 AI 算具体数值；不要跳步同时改多项 |

> **关键互补**：AI 的 std/ptp 看不出"肉眼高频抖动"，人的眼睛看不出"0.3cm 的统计趋势"。两者缺一不可。

## 2. 铁律（这次成功的核心，违反必翻车）

1. **一次只动一个变量**。Kp、Ki、Kd、uh、带宽、slew……每轮只改一个，否则无法归因。
   （本次教训：同时改"带宽+Kd"时就分不清是谁的效果，且我还把"带宽"理解错成 PWM 上下限——
   单变量 + 跑完即对账，能立刻发现理解偏差。）
2. **先验证反馈可信，再碰控制器**。传感器/测量没确认干净前调 PID = 在垃圾数据上空转。
   工具要内置"反馈健康门"(如 stalled 帧占比、maxAge)，不绿不许往下走。
3. **用定量指标裁决，不靠"感觉好像好点"**。每轮输出 avg/std/ptp/上升时间，横向对比上一轮。
4. **整定顺序固定：先 D(阻尼) → 再 P(刚度) → 最后弱 I(消静差)**。不稳定对象尤其如此。
5. **AI 必须能自我推翻**。本次 AI 一度把 Kd 越加越大(60→80→90)使系统恶化，
   是"算了一下 Kd×球速峰值≈1600PWM 早已撞满量程"才掉头——**越加越差 = 立刻怀疑方向反了**。
6. **机理先于调值**。每次改动前用一句话说清"为什么"(物理/控制原因)，事后用数据验证机理对不对。
   说不清机理的改动 = 在猜，停。
7. **每个关键里程碑即时记调试日志**(真实数据+现象+结论)，达标参数立刻回填 config.h 锁死。

## 3. 标准协作循环（每一轮）

```
人：看屏幕，描述现象 + 给方向（"浮动有点大，加点 Kd"）
 ↓
AI：① 把方向翻译成"单一参数的一次改动" + 说清预期机理
    ② 跑一次（编译/已在线则直接发命令）→ 采集 N 秒
    ③ 解析出 avg/std/ptp/上升时间，和上一轮对账
    ④ 给结论：变好/变坏/中性，以及机理是否被验证；提下一步单一改动
 ↓
人：结合屏幕现象拍板下一步（确认/换方向/收手）
```

## 4. 工具要求（让上面的循环跑起来）

- **一次性事务式串口脚本**（发命令→采 N 秒→关口）优于常驻后台桥（后者句柄易僵、数据不新鲜）。
- **遥测要够用**：当前值/目标/误差/输出/速度(D)/原始测量/样本新鲜度，外加排障时临时加寄存器 dump。
- **"一键跑一轮"脚本**：setup 参数 → 预热 → 投入 → 采集 → 自动算 std/ptp + 反馈门 + 自动停。
  （本工作台的 `tune_step.ps1` 就是范例，新项目应照此造。）
- **AI 能自主编译+烧录**（headless），形成"改码→编译→烧录→在线调→读数"闭环，人只管接板子+看实物。

## 5. 反模式（这次踩过/差点踩，禁止重犯）

- ❌ 同一方向连猜 2 次没中还继续猜 → 立刻改"测量"(读寄存器/上探头/加遥测)，别线性烧时间。
- ❌ 一轮改多个参数 → 无法归因，等于没调。
- ❌ 在没验证可信的反馈上调 PID → 纯浪费(本工作台超声波时代血泪)。
- ❌ AI 嘴硬维护错误判断 → 数据/实物打脸就认，翻案越快越省时间。
- ❌ 把"看起来差不多"当达标 → 必须有数字。
- ❌ 改了源码不验证就往下走 → 先证"板上跑的是新固件"(加版本标签/新打印)。

## 6. 适用范围

PID/控制整定、传感器调试、外设点不亮、通信不通、时序问题——一切"真机不工作且需要反复试"的场景。
纯软件/无硬件在环的任务不强制，但"单变量 + 定量裁决 + 自我推翻"仍是好习惯。
