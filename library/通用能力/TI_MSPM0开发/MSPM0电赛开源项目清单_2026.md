## 1. 第一梯队：有比赛成绩背书 + 同款芯片

### 1.1 ZLC_MSPM0_Peripheral_Library —— 同芯片外设库，2024-H 国一

- 仓库：<https://github.com/ZhijianLi2003/ZLC_MSPM0_Peripheral_Library>
- 许可：**无 LICENSE**（⚠️ 不可抄码）· 山东大学（威海）团队 · 环境 = Keil + TI 官方 SDK
- 真机证据：`赛绩背书` —— 作者声明该库即其 **2024 年电赛 H 题参赛作品，获国家一等奖**。

**为什么对我们值钱**：全网找到的**唯一"同款 MSPM0G3507 + 明确国一 + 外设库形态"**的仓库。它不是玩具工程，是一整套按外设切分的驱动库，README 里直接给了**逐脚接线表**，覆盖的外设正好压在车题上：

| 它有的外设 | 我们的状态 | 对我们的用法 |
|---|---|---|
| 8 路灰度传感器（作者注明需配上拉） | ⬜ 无（等赛道才知道要不要） | **循迹真要上就照它的引脚组织方式抄思路**（注意它用 PB 口一整排，我们 PB 已被 LCD/IMU 占掉不少，见 SSOT §B） |
| 1024 线正交编码器 | ✅ 我们是软件采样 4x 解码（抗 EMI，比它更强） | **不要换**，我们这块是真机换来的（坑库"采样解码>上拉治EMI"） |
| DRV8701E 电机驱动（DIR + PWM 两线制） | ✅ 我们是 DRV8231（IN1/IN2 双 PWM） | 接口不同，**驱动层不可移植**，只能看它上层怎么封 |
| IMU660ra（SPI） | ✅ 我们是 ICM42688（已真机验活 `a808122`） | 看它的 SPI 时序封装当对照 |
| 舵机 PWM / 无线串口 / 蜂鸣器 / 按键 | ⬜ 无 | 舵机：2026 真清单**没给舵机**，低优先 |
| 设计报告 PDF（`Design_Report(2024_Question_H).pdf`） | — | ⭐ **这个比代码值钱**：一份拿了国一的报告实物，赛前给 `skills/03_报告答辩/` 当对照物 |

**⚠️ 引脚一律不抄**：它是 LaunchPad + 自制扩展板，我们是天猛星自制载板，引脚真值源永远是 [`工程事实SSOT.md §B`](../../../.kiro/steering/工程事实SSOT.md)。

### 1.2 2024-NUEDC-H-TI_CAR —— 2024-H 惯导+巡线车，给了实测秒数

- 仓库：<https://github.com/abcuer/2024-NUEDC-H-TI_CAR> · 30★ · 许可：**无 LICENSE**（⚠️ 不可抄码）
- 真机证据：`外部声明` —— README 首行给出**完赛实测：任务四总用时 35 秒**，并挂了 B 站演示视频 + 嘉立创 EDA 开源硬件
- 硬件：MSPM0G3507 + JY901S 陀螺（模块自带解算，串口出角度）+ MG513 电机 13 线霍尔 + TB6612 + 8 路灰度 + 三轮车模

**为什么对我们值钱**：这是**和 2024hVibe 同题的第二个独立实现**，两份对比着看，能把"哪些做法是这道题的必然、哪些只是某队的偏好"分开。它的架构思想和我们要走的路高度重合：

- **四个可复用动作原语**：陀螺闭环直行 / 灰度位置 PID 循迹 / 编码器定距 / 节点触发（声光确认）。
  → 直接对应我们 `04_备赛启示` 的阶梯 2.5~5。**我们的 `car_drive(v,w)` 就该是这四个原语的底座。**
- **两环并列而非嵌套**：航向环（陀螺→左右差速）+ 循迹环（8 路灰度→左右差速），靠 `line_flag` 在两者间切换——**进黑线区切循迹 PID，检测全白立刻切回角度闭环**。作者点明这是解弯道衔接失控的手段。
  → 这条思路我们可以零成本借鉴：**我们已有的差速层 `m7` 正是这两个环的公共出口**。
- **高速段用查表法补偿**：按圈数查 `d_angle` / `d_dis` 修正数组，调试时改数组不改逻辑。
  → 这是"参数与逻辑分离"的朴素版，和我们 P0-1 `config.h` 参数集中同一个思想。
- **防御性编程**：README 明确提到 `TimeLimit` 超时保护 + 统一 `Task_Reset` 清理函数。
  → ⭐ **正是我们清单里 🔴 优先级第 1 的"运动命令固件侧时限自停"**。第二个独立仓库佐证了"这不是可选项"。
- **静态校准纪律**：启动任务前车必须静止以标定陀螺零位。
  → 我们 `imu.c` 已有零偏标定，但**测试协议里要把"先静止再发指令"写死**（对应待拍板的"真机测试协议化"）。

### 1.3 mspm0g3507-car-kit —— 逐项标"实机验证"，且自带 skill 包

- 仓库：<https://github.com/2262727886-stack/mspm0g3507-car-kit> · 38★ · 许可：**无 LICENSE**（⚠️ 不可抄码）
- 真机证据：`外部声明` —— README 用表格把 7 项能力**逐项标注"实机验证"**（差速底盘 / IMU 姿态 / PID / K230 视觉 / 蓝牙调参 / OLED / 舵机云台）。**这是自评标注，无第三方复核。**
- 硬件：MSPM0G3507 + TB6612 + MG310（**和我们同款电机**）+ MPU6050 或 IMU601 + K230 庐山派 + SSD1306 + JDY-31 BLE

**为什么对我们值钱**：三点，按价值排序：

1. **它自己也做了 `.claude/skills/mspm0g-contest/` 技能包**（README 里指向该目录的 `tools.md` 讲烧录脚本与 BSL 串口烧录）。⇒ 又一个"用 agent skill 打电赛"的独立样本，和我们 `skills/00_AI协作备赛操作系统.md` 是同一物种。
2. **K230 视觉链路是完整的两端**：既有 MSPM0 侧的 UART 接收 + 舵机跟踪（`servo_k230.c`），也有 K230 侧的 MicroPython 脚本（色块追踪 / 形状检测）。
   ⇒ 我们最大短板"识别→串口→MCU 解析"这条链，**这里有个能照着搭的两端骨架**。但前置仍是"我们手上到底有没有相机模块"（`CONTINUATION_GUIDE §四` 三个待确认之一）。
3. **给了两条 IMU 路线的取舍**：MPU6050 走 I2C + DMP 硬件解算 / IMU601 走 UART 直接出角度，作者把后者标注为规避漂移问题的方案。

它还给了一条**渐进学习路径**（底盘 PID → IMU 转弯 → 蓝牙调参 → 视觉），结构上和我们 `04_备赛启示` 的阶梯序同构，可当交叉验证。

## 2. 第二梯队：单点打靶，正对我们当前堵点

### 2.1 2026TI_MPU6050_Yaw —— 🟢 **赛前唯一值得读代码的一个**

- 仓库：<https://github.com/monokumakuki/2026TI_MPU6050_Yaw> · 32★ · 许可：**无 LICENSE**（⚠️ 不可抄码，只读思路）
- 真机证据：`外部声明` —— 作者自报：静止约 10 分钟未观察到漂移；剧烈来回偏转有约 1~2° 误差但不累积漂移；缓慢移动误差极小。**作者本人明说只测了 10 分钟。**⇒ 证据强度=中，样本短。
- 方案：Mahony 互补滤波（四元数）算 roll/pitch + **yaw 走独立梯形积分**，不用官方 DMP 库（便于移植）

**为什么它正打我们的堵点**：我们的 `attitude.c` 是"陀螺 Z 积分 yaw + 互补滤波 pitch/roll"，**结构和它一模一样**，但它把工程细节写得更全。逐条对照我们缺什么：

| 它的做法 | 机理 | 我们的状态 |
|---|---|---|
| **yaw 必须独立积分，不能被加速度计修正** | 加速度计只感知重力方向，车绕重力轴水平旋转时重力在机体系的投影不变 ⇒ 修正量在该轴恒为零 | ✅ 我们也是这么做的，**但这条机理值得写进 `attitude.h` 注释**，防下一个对话"顺手给 yaw 加个加速度修正" |
| 陀螺量程选 **±2000 dps** | 直角转弯角速度可达 300~400 dps，±250 会削峰饱和 | ✅ **已查证一致（2026-07-27, PC 源码级）**：`imu.c` 的 `CFG_GYRO_CONFIG0=0x06`（FS_SEL=000 = ±2000dps, ODR=1kHz）+ `imu.h` 的 `IMU_GYRO_LSB_PER_DPS=16.4f`，与它的选择完全相同 ⇒ **无削峰风险，不用改**。旁证：同一配置路径下的加速度 ±4g/8192 已被真机验活（`a808122` 模长 0.995g）。**注意这只证明"量程配置正确"，静止读数无法独立证明陀螺标度因数，标度要靠转已知角度验（等定轴时一起做）。** |
| 角速度 **死区 0.25 dps** 以下直接置零 | 抑制静止量化噪声进积分 | ⬜ 待办清单第 3 条正是这个（PC 单测可全验、零回归） |
| **梯形积分** 替代欧拉积分 | 误差量级 O(dt³) vs O(dt²) | ⬜ **我们是矩形积分**，改成梯形是几行的事，PC 可单测 |
| 六道保护：dt 限幅 50ms / 角速度限幅 ±500dps / 单帧增量限幅 ±5° / ±180° 折返 / 死区 / 温漂自补偿 | dt 限幅治卡顿跳变；角速度限幅剔 I2C 野值；单帧限幅防异常跳 | ⬜ **我们基本没有**。其中"**dt 限幅**"对我们尤其相关——LCD 重绘拖慢主循环这个坑我们踩过两次 |
| **温漂自补偿**：检测到静止（重力模长≈1g 且三轴角速度 <0.5dps）时以 α=0.001 微调零偏，时间常数约 1000 秒 | 慢到不会把真实缓慢转动误判成温漂 | ⬜ 无。**赛后再说**（赛场单次任务 2~3 分钟，够不上温漂尺度） |
| 分**完整版 / 轻量版**两个更新函数（约 0.8ms / 0.15ms） | 静止校准时读全量，实时循迹只读陀螺 6 字节 | ⬜ 无。**M0+ 无 FPU、软浮点**，这个分档对我们比对它更有价值 |
| 明说 yaw **无绝对参考、仅短期可用**，需上电归零 | 无磁力计的必然结果 | ✅ 认知一致 |

**⚠️ 它不能解决我们的头号问题**：它是 MPU6050（I2C），我们是 ICM42688（SPI 共享总线 + 软片选）——**驱动层不可移植**。而且**它假定 yaw 用 gz**，我们实测重力主要落在 +Y、"Z 朝上"未证。**定轴这一步必须我们自己在板上做，谁的代码都替不了**（方法见 `CONTINUATION_GUIDE §四` 定轴两步）。

## 5. 汇总：这轮检索真正改变了什么

**没改变的（重要）**：我们的技术路线一条都不该动。速度环 / 位置环 / 差速层 / 编码器采样解码 / IMU 驱动全是真机达标的，外部仓库里**没有一个比我们这几块更强**——尤其编码器"定时采样 4x 解码抗 EMI"这一块，翻遍上面所有项目，**没人这么做**（都用边沿中断或硬件 QEI），这是我们的独有资产。

**改变的（可立即行动，全部零回归）**：

1. ✅ **陀螺量程已查证一致，无需动作**（2026-07-27 PC 源码级）：`CFG_GYRO_CONFIG0=0x06` = **±2000dps / 1kHz ODR**，`IMU_GYRO_LSB_PER_DPS=16.4f` —— 与参考项目的选择相同，**直角转弯不会削峰**。⇒ 本条从"待查"直接结案。（来源：2.1）
2. ⬜ **yaw 积分改梯形 + 加 dt 限幅**：几行代码，PC 单测可全验，`attitude` 尚未进任何控制环 ⇒ 零回归。dt 限幅对我们尤其相关（LCD 拖慢主循环踩过两次）。（来源：2.1）
3. ⬜ **`attitude.h` 补一条机理注释**：说明"加速度计无法观测绕重力轴旋转，故 yaw 必须独立积分、不受互补滤波修正"——防下一个对话画蛇添足。（来源：2.1）
4. ✅ **"运动指令固件侧时限自停"获第二个独立佐证**（1.2 的 `TimeLimit` + 2024hVibe 的每指令时限）⇒ 这条从"建议"升级为"两个独立跑通过车题的仓库都做了的必备项"，赛前必补。
5. ✅ **clone 到本地当赛场离线库 —— 已做，且从 2 个扩到全部 30 个**（2026-07-27，1376.5MB，见 [`vendor_ref/00_INDEX.md`](../../vendor_ref/00_INDEX.md)）。顺带结出 §0.5 的许可修正 + 2026 吉林真题 + 磁悬浮组。
