# 嵌入式中文与字体显示（MCU 屏上显示中文 / 大号数字 · 可复用方案）

> **来源**：方案骨架搬运并泛化自一套**真机验证过**的圆屏中文显示经验（GC9A01 240×240，效果被评「精致、不廉价」）。
> **诚实标注**：本目录的技术结论是验证过的；同目录 `gen_bitmap_font.py` 是**参考骨架**，用到你的屏时按屏改参数、跑一次、**生成物需真机验证**再算数（守北极星）。
> **什么时候读它**：任何题要在 OLED / 圆屏 / TFT 上显示**中文菜单/标题/单位/状态**，或显示**好看的大号数字**时。校赛B 就用了 GC9A01 圆屏，控制/仪表类题几乎都要显示东西。

---

## 一句话原理

STM32 / MSPM0 + 屏（OLED/圆屏/TFT）**没有内置中文字库**（不像 PC 有系统字体）。要显示中文，就在 **PC 上离线用 TrueType 字体把每个中文词渲染成位图数组**，编译进 flash，运行时把这段像素直接 blit 到屏幕。

**字形不在固件里，是在 PC 上"画"好再把像素搬进去的**——PC 有完整中文 TTF（覆盖全部 GB2312/GBK），想显示哪个词就渲染那个词的矢量字形（自带抗锯齿），把**像素结果**打包成 C 数组进 flash。所以固件**不需要中文字库**（省 flash、省移植），出来的是**真·矢量渲染的像素**（笔画圆润、边缘平滑），不是逐点手描的点阵——这就是"无中生有却毫不廉价"的根源。

**核心链路（彩屏）**：
```
PC Python + PIL + TTF字体
  → 灰度画布渲染中文（PIL 天然抗锯齿）
  → 紧密裁剪（getbbox 去空白边）
  → 灰阶 → 目标格式（RGB565 / 4bpp alpha / 1bpp）
  → 生成 C 数组 + extern 声明 + 宽高宏
  → 编译进 flash → 运行时 blit 上屏
```

---

## 三个"效果好"的关键（决定精致 vs 廉价）

1. **抗锯齿（灵魂）**：PIL 在灰度画布上画字天然带抗锯齿——边缘是 0~255 渐变灰阶。生成时把灰阶**线性映射**到目标格式（RGB565 / alpha），边缘就平滑过渡、没有锯齿。**这是效果好的头号原因**——电赛圈常用的取模软件出的 1bpp（非黑即白）就会锯齿难看。
2. **紧密裁剪**：`getbbox()` + `crop()` 只存"字本身"的像素，不存四周空白 → 省 flash + 宽高精确、屏幕定位不用猜。几个词组总共才几 KB。
3. **字体选型**：黑体（如思源黑体/文泉驿）规整清晰，小屏不糊；换 `FONT_PATH` 一行即可换楷体（有笔锋）/ 书法体——抗锯齿/裁剪/映射链路对任何 TTF 通用，**换字体 = 换一行路径 + 重跑**。

## 按屏型适配（同一套灰度渲染，只换"映射"这一步）

| 屏 | 典型芯片 | 目标格式 | 灰阶怎么映射 |
|---|---|---|---|
| **彩屏** | GC9A01(圆) / ST7735 / ILI9341 | RGB565（字节序看驱动，多为大端） | 白字 `g8→(r5<<11)|(g6<<5)|b5`；想要**语义色**（琥珀=警告 / 红=报警）把灰阶整体乘一个目标色即可 |
| **彩屏·大号数字** | 同上 | 4bpp alpha 变宽字体表 | 存 alpha，blit 时和底色混合，最平滑；数字是动态的 → 存 `0-9 . : % + 单位` 一张表，运行时按字符取 |
| **单色 OLED** | SSD1306 / SH1106 128×64 | 1bpp（按 page/列打包） | 灰阶 > 阈值 = 1 否则 0；抗锯齿会丢（OLED 本就单色），但比手描点阵省事 |

> 数字/单位（速度/频率/误差/电压）也可预渲染成大号字体表，比库自带 5×7 ASCII 好看很多，**答辩演示是加分项**。

## 现成轮子对比（电赛时间紧，先看有没有更快的）

| 方案 | 适合 | 代价 |
|---|---|---|
| **u8g2**（单色屏神库） | OLED 少量中文，最快 | 自带 `u8g2_font_wqy*_t_gb2312`（文泉驿中文），直接 `drawUTF8("目标")`；中文字库占 flash 大（几十~上百 KB） |
| **LVGL**（TFT GUI 框架） | 上了图形界面才值得 | `lv_font_conv` 把 TTF 转字体（可选子集/bpp），思路同预渲染但工具化；框架本身重 |
| **GB2312 字库文件 + 按码点取模** | 要显示**任意/动态**中文 | 存整个字库到 flash/SD，运行时按 UTF-8/GB2312 码点算偏移取字模；flash 大 + 要处理编码 |
| **PCtoLCD2002 等取模软件** | 临时手动取几个字 | 电赛圈经典，但 **1bpp 非黑即白有锯齿 + 逐字手动烦**；本目录 Python 方案 = 脚本化 + 抗锯齿，更优 |
| **本方案（离线预渲染位图）** | **彩屏固定少量词组要精致** | 只显示生成过的字；改字要重跑生成器 |

**决策树**：单色 OLED 少量中文 → **u8g2 内置**最省事；彩屏固定词组要精致好看 → **本方案预渲染**（抗锯齿是它的优势）；要显示任意/动态中文（如用户输入）→ **GB2312 字库文件** 或 LVGL。

## 局限（复用前必读）

1. **字号/颜色生成期固定**——运行时缩放位图会糊；换字号/颜色要重跑生成器。
2. **只有生成过的字能显示**——所以本方案**只适合固定少量词组**（菜单名/标签/单位/状态词），**不适合自由输入的动态文本**（那走 u8g2 内置或 GB2312 字库）。
3. **改字必重跑 + 同步接线**——符号名常带宽高后缀（如 `img_target_48_24`），字/字号一变宽高变、符号名变，引用处（extern、宽高宏）要同步，否则编译错或错位。
4. **字体版权**——微软雅黑/楷体是 Windows 随附字体；竞赛/开源发布建议换**开源中文字体**（思源黑体 `SourceHanSans` / 文泉驿 `WenQuanYi`），避免版权问题。

## 复用步骤

1. 改 `gen_bitmap_font.py` 顶部：`FONT_PATH`（选字体）、`FONT_SIZE`（字号，按屏分辨率）、`FORMAT`（`rgb565` / `1bpp`）、`LABELS`（要显示的词组）。
2. 跑 `python gen_bitmap_font.py` → 生成 `font_data.c` + 控制台打印 extern 声明/宽高宏。
3. 把生成的 `.c` 加进工程（Keil/CubeIDE/CCS 的源文件列表 或 CMake SRCS），extern/宏贴进你的显示头文件。
4. 用你显示驱动里的 blit 函数把位图贴到屏幕坐标（RGB565 一次性 blit；1bpp 按 OLED 库的 drawXBM/自定义 blit）。
5. **上屏跑一次确认**（字清晰、不锯齿、定位对），才把它当"已验证"。
