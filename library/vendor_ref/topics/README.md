### ⚠️ `control_code_21_25/` 里 3 个题目是空的 —— 上游仓库残缺，不是我们 clone 丢了（2026-07-27 查清）

| 目录 | 实测 | 说明 |
|---|---|---|
| `21 F Intelligent Medicine Car/` | **0 文件** | 智能送药小车（Keil G3507 + STM32F4 两套） |
| `22 C DoubleCarFollowing/` | **0 文件** | 双车跟随 |

| `24 H Automatic Driving Car/` | 132 文件 / 30 源码 / 1.4 MB | ✅ **第三份独立的 2024-H 实现**（另两份在 `../../car/2024H_abcuer/` 和 `library/通用能力/TI_MSPM0开发/参考工程_2024H电赛车_MIT/`） |
| `25 E Simple Self-aiming Device/` | 1231 文件 / 697 源码 / 71 MB | ✅ 2025-E 自瞄，含 **K230 CanMV 视觉伺服 PID**（`Code/untitled_daima.py`，385 行）+ MSPM0 工程 |

**根因**：那 3 个是 **git submodule 引用**（`git ls-files -s` 显示 mode `160000` gitlink），而上游**根本没提交 `.gitmodules`**。后果两层：① `git clone --depth 1` 默认不拉子模块 → 目录空；② **补也补不了** —— 没有 `.gitmodules` 就没有远端 URL，`git submodule update --init` 必然失败。**这是上游作者的仓库缺陷**（把别的 repo 当子目录 `add` 进来，git 记成 gitlink 却没登记 URL），任何人 clone 都一样。
**不可恢复**，除非能猜出那 3 个子模块原本指向哪个仓库（只有 SHA、没有 URL，猜不了）。

> 顺带澄清两件事：① **`topics/` 下真正 0 字节的文件 = 0 个**（全目录扫过），没有"clone 丢文件"；② `git ls-files` 里看到的 283 字符超长路径是 `core.quotepath` 把中文转义成 `\345\210\240` 撑出来的**假长度**，真实路径不超 MAX_PATH。

**许可**：题目 PDF 是官方公开文件，作素材引用没问题；`control_code_21_25/` 里的**代码无 LICENSE，只读思路不抄**。
