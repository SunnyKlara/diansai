# 竞赛备赛通用方法论（Competition Prep Meta-Framework）

> 本目录把电赛备赛仓库（`备赛系统/`）里"和电赛无关、和**任何**比赛都通用"的协作方法抽离出来，做成可拷贝模板。
> 适用：电赛、智能车、RoboMaster、ICPC/CCPC、数学建模、机器人大赛、Kaggle、CTF……任何"长周期 + 多人协作 + 有真题 + 要交付物"的比赛。

---

## 这个方法论解决什么问题

打过比赛的人都见过这种情形：

- 队员各自存代码，临赛找不到去年那版能用的工程
- 报告/论文最后两小时通宵糊弹幕，因为前期没沉淀模板
- 老队员经验只在脑子里，新人每年从零踩同样的坑
- AI 工具用了半天，每次都要重复解释项目背景

本方法论的核心主张：

> **比赛仓库不是代码仓库，是"团队作战手册 + 知识库 + AI 协作上下文"三合一系统。**

只要按这套结构铺开，就能拿到三个红利：

1. **结构红利** —— 任何人（含 AI）一进仓库就知道东西在哪、缺什么
2. **沉淀红利** —— 每场赛 / 每年的经验自动按格子归档，下届队伍直接复用
3. **AI 红利** —— Steering 文件让 AI 像"懂规矩的老队员"一样工作，不用反复布置任务

## 30 秒上手（拷贝到新仓库）

```bash
# 1. 拷贝整个目录到新仓库
cp -r _竞赛备赛通用方法论/ <新仓库>/

# 2. 选一份适配文档作为蓝本
cp _竞赛备赛通用方法论/11_适配_RoboMaster.md <新仓库>/RM26备赛系统/总纲.md

# 3. 把 02_steering模板.md 拷到 .kiro/steering/ 并改占位符
cp _竞赛备赛通用方法论/02_steering模板.md <新仓库>/.kiro/steering/<比赛名>仓库规范.md

# 4. 按 01_目录结构模板.md 建空骨架
# 5. 跟 AI 说"按本仓库 Steering 规范开始" —— 它会自己接管
```

| `备赛系统/E_赛场实战/` | 作战手册 | 赛中翻 |
| `.kiro/steering/` | AI 驯化书 | AI 进门第一课 |

## 适用前提

- 仓库托管在 Git（GitHub/Gitee/GitLab 都行）
- 团队用 Markdown 写文档（不要用 Word，要可 diff）
- 至少一个人愿意配 AI 协作（强烈推荐 Kiro/Claude/Cursor 这类有 Steering 能力的）
- 比赛周期 ≥ 1 个月（< 1 个月直接抄 ICPC 适配版的"赛后复盘"模板就够了）

---

## 不适用前提

- 一次性比赛（赛完就解散）—— 这套是为"传承"设计的
- 强保密项目（部分内容必须脱敏后才能入库）

## 你想拓展的方向

如果想加新的比赛适配：照 `1X_适配_*.md` 套路写一份，重点交代：

1. 这个比赛的"真题"对应什么单位（一场赛 / 一台机器人 / 一年规则）
2. "六件套"在这个比赛里映射成哪几样东西
3. 方向训练分什么类
4. 通用能力沉淀什么模板
5. 赛场实战流程怎么走
