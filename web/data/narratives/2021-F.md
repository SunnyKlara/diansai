## 第一个谜：为什么红线循迹比黑线循迹更难

电赛历年小车题——**90% 都是黑线循迹**（**2017 E、2024 H 都是黑线**）——**而 2021 F 偏偏选了红线**——**为什么**？

**第一笔账：黑线 vs 红线 vs 白底**

红外传感器（**TCRT5000 / ITR9606**）的工作原理——**发射红外光、接收反射光、判断"白底 / 黑底"**：

```
白色地面：红外光大部分反射 → 接收强 → 输出高电平
黑色地面：红外光大部分吸收 → 接收弱 → 输出低电平
红色地面：红外光部分反射、部分吸收 → 输出"中等"电平
```

**这个逻辑说的其实是**——**黑白对比度高（差 80%）→ 阈值好定、抗干扰**——**而红白对比度低（差 30~50%）→ 阈值难定、易误判**。

**实测数据（TCRT5000 + 5V 工作电压）**：

| 地面类型 | 接收电压 | 数字输出 |
|---|---|---|
| **白色喷绘布** | 4.8V | 1（高）|
| **黑色胶带** | 0.3V | 0（低）|
| **红色胶带** | 2.5V | **介于高低之间** |
| **环境光强干扰** | ±0.5V 漂动 | **不稳定** |

**问题**：**红色胶带的输出 2.5V 正好在阈值附近**——**环境光稍微变一下（开灯 / 关灯）→ 输出从 0 跳到 1**——**循迹失败**。

**第二笔账：怎么解决红线识别**

**对策 A：用更窄的阈值带 + 模拟量比较**

```c
// 不用数字输出，用 ADC 直接采模拟值
uint16_t adc_val = adc_read(IR_CHANNEL);
float voltage = adc_val * 3.3 / 4095;

// 三段判断
if (voltage > 4.0V)        type = WHITE;       // 白底
else if (voltage < 0.8V)   type = BLACK;       // 黑线（边墙）
else if (voltage > 1.8V && voltage < 3.2V) type = RED;  // 红线
else                        type = UNKNOWN;
```

**这段代码说的其实是**——**用 ADC 模拟量替代数字 0/1**——**精确识别"白 / 黑 / 红"三种颜色**。

**对策 B：用"颜色传感器"替代红外**

| 型号 | 类型 | 输出 | 价格 |
|---|---|---|---|
| **TCS34725** | RGB 颜色传感器 | I2C 读 R/G/B | 18 元 |
| **TCS230** | RGB 颜色传感器 | 频率输出 | 8 元 |
| **OPT3101** | 颜色 + 距离 | I2C | 35 元 |

**TCS34725 一颗能精确读出"R/G/B 三个值"**——**红色 = R 高 + G 低 + B 低**——**抗干扰强**。

**国一队伍**：**5 路 TCS34725 阵列**——**红线识别精度 ±2mm**——**抗光线变化能力强**——**循迹稳定**。

**国二 / 普通队伍**：**5 路 TCRT5000 + 模拟量阈值**——**红线识别精度 ±5mm**——**够用**。

**对策 C：摄像头识别（OpenMV）**

**直接用 OpenMV 看红线**——**HSV 颜色空间筛选 + 二值化 + 拟合直线**：

```python
# OpenMV 代码
import sensor, image
sensor.set_pixformat(sensor.RGB565)
sensor.set_framesize(sensor.QQVGA)  # 160x120
red_threshold = (0, 100, 50, 127, 0, 127)  # HSV 红色范围

while True:
    img = sensor.snapshot()
    blobs = img.find_blobs([red_threshold])
    if blobs:
        red_line = blobs[0]
        offset = red_line.cx() - 80  # 中心偏差
        uart.write(f"{offset}\n")
```

**这段代码说的其实是**——**OpenMV 拍一帧 → 找红色块 → 算出"红线在画面中的偏移"** → **传给主控**。

**优点**：**抗光线、抗污渍、能看远处的红线分叉**。  
**缺点**：**帧率 0.3s/帧** = **3Hz 循迹**——**远低于红外的 1kHz**——**车速必须降到 0.3m/s 以下**。

**国一选择**：**OpenMV 做"全局识别"（看 T 路口、看病房号）+ 红外 / 颜色传感器做"实时循迹"**——**两套传感器分工**。

**第三笔账：T 路口的处理**

**T 路口是循迹的难点**——**5 路传感器在 T 路口同时读到红色**——**车不知道"该左转还是右转"**。

**对策**：**进 T 路口前减速 + OpenMV 识别"该往哪走"**：

```c
// 主控代码
if (t_intersection_detected()) {
    // 1. 减速
    set_speed(0.3 m/s);
    // 2. 询问 OpenMV
    uart_send("CHECK_DIRECTION\n");
    // 3. 等待回复（1秒内）
    wait_response();
    // 4. 根据回复转弯
    if (response == "LEFT")  turn_left();
    else if (response == "RIGHT") turn_right();
    else continue_straight();
}
```

**OpenMV 怎么判断方向**？——**比对当前位置和目标病房号**——**用预存的"地图"查表**：

```python
# OpenMV 代码
target_room = 5  # 目标 5 号病房
current_node = "T1"  # 当前在 T1 路口

# 预存地图（节点 → 邻居）
map = {
    "T1": {"left": "Room1_2", "right": "T2"},
    "T2": {"left": "Room3_4", "right": "T3"},
    ...
}

# 用 BFS / Dijkstra 找最短路径
path = bfs(current_node, target_room)
direction = path[0]  # 第一步往哪走
uart.write(direction)
```

**这段代码说的其实是**——**OpenMV 维护一张"医院地图"**——**根据"当前位置 + 目标"查路径**——**告诉主控该左还是右**。

> **小白补课：BFS 是什么**
> - **BFS（Breadth-First Search，广度优先搜索）**：从起点出发，一层层扩展邻居——**找到目标时立刻停止**——**保证找到的是最短路径**。
> - **应用场景**：**地图导航、社交网络（六度空间）、电路布线**。

## 第二个谜：数字识别为什么这么难

发挥之前——**基本要求 50 分的核心**——**就是"识别 1~8 数字"**。

**8cm × 6cm 的纸贴在墙上 / 地上**——**OpenMV 摄像头拍下来 → 识别"这是几号"**——**听起来很简单**。

但**做过 OpenMV 数字识别的人都知道**——**这是一个"看似简单实则坑无数"的任务**。

**坑 1：拍摄角度变化**

OpenMV 装在小车上——**小车经过数字纸时**——**拍摄角度从 30°到 90°变化**——**数字会被"拉长 / 压扁 / 倾斜"**——**简单的模板匹配失效**。

**对策**：**'透视变换'校正图像**

```python
# OpenMV 代码
img = sensor.snapshot()
# 找到数字四个角点
corners = img.find_qrcodes() or img.find_rects()
# 透视变换矫正
img.rotation_corr(corners=corners)
# 现在数字是"正面看的"了
```

**坑 2：光照变化**

医院走廊光照——**白天阳光、晚上日光灯、夜班暗灯**——**亮度从 100 lux 到 1000 lux 变化 10 倍**——**摄像头 RGB 值跟着变**。

**对策**：**自适应阈值二值化**

```python
img.binary([(0, 64)], adaptive=True, block_size=20, c=10)
```

**'**adaptive=True**'** 让阈值随每个区域光照自适应——**不管光多亮多暗，都能稳定二值化**。

**坑 3：车辆运动模糊**

小车以 0.5m/s 速度经过数字纸——**OpenMV 0.3s/帧** = **每帧间隔 15cm**——**数字在画面里"模糊一团"**。

**对策**：**经过数字时减速到 0.15m/s 或停车 0.5s**

```c
// 主控代码
if (digit_zone_detected()) {
    set_speed(0.15 m/s);  // 减速
    delay(500);           // 给 OpenMV 足够时间
    uart_send("READ_DIGIT\n");
}
```

**坑 4：误识别**

数字 "**6**" 和 "**9**"、"**1**" 和 "**7**"——**容易混淆**。**单帧识别准确率 90%——但整体任务要求 99%——必须用"多帧投票"**：

```python
# OpenMV 多帧投票
recognition_history = []
for frame in range(10):
    digit = recognize_single_frame()
    recognition_history.append(digit)
    
# 取出现次数最多的
final = max(set(recognition_history), key=recognition_history.count)
if recognition_history.count(final) >= 7:  # 10 次中至少 7 次
    return final
else:
    return "UNKNOWN"  # 不确定，让小车再过一次
```

**这段代码说的其实是**——**10 次识别取多数**——**单帧 90% 准确率 → 多帧 99% 准确率**——**误识别率从 10% 降到 1%**。

**国一队伍的识别策略**：

1. **训练数据**：**自己拍 100 张照片**（不同角度 / 光照 / 模糊度）
2. **算法**：**Haar Cascade（OpenCV 经典）+ 多帧投票**
3. **识别速度**：**3 帧/秒**——**1 秒识别完成**
4. **准确率**：**99%+**

**国二队伍**：**OpenMV 自带的"模板匹配"+ 单帧识别**——**准确率 90%~95%**——**勉强够用**。

**国三队伍**：**没用 OpenMV，用普通摄像头 + STM32 自己处理**——**90% 翻车**——**直接 0 分**。

**这就是为什么 OpenMV 是"必修工具"**——**它把"图像识别难度"从博士级降到本科级**。

## 第三个谜：状态机怎么设计

**送药小车的"任务流"** 看起来简单——**装药 → 送药 → 卸药 → 返回**——**但写代码时**——**新手会发现"状态太多，转换关系复杂"**。

**朴素状态机**：

```
STATE_IDLE          // 等待复位
STATE_READ_DIGIT    // 识别病房号
STATE_WAIT_LOAD     // 等待装药
STATE_DELIVER       // 送药途中
STATE_AT_ROOM       // 到达病房，亮红灯
STATE_WAIT_UNLOAD   // 等待卸药
STATE_RETURN        // 返回途中
STATE_AT_PHARMACY   // 到达药房，亮绿灯
STATE_DONE          // 完成
```

**9 个状态**——**每个状态有"进入条件、动作、退出条件"**——**写起来 200 行**。

**进阶状态机**——**层次化设计**：

```
HIGH_LEVEL_STATE: PRE_LOAD / DELIVERY / RETURN / DONE
    │
    └── LOW_LEVEL_STATE: 
        - LOOKING_FOR_LINE        // 找红线
        - FOLLOWING_LINE          // 循迹中
        - APPROACHING_T_JUNCTION  // 接近 T 路口
        - TURNING                 // 转弯中
        - APPROACHING_DIGIT       // 接近数字
        - READING_DIGIT           // 识别数字
        - APPROACHING_ROOM_DOOR   // 接近门口
```

**两层状态机的好处**：**高层管"任务"、低层管"动作"**——**职责分离**——**代码 500 行也清楚**。

**第一笔账：状态切换条件**

每个状态切换都要明确"**触发条件**"：

| 当前状态 | 触发条件 | 下一状态 |
|---|---|---|
| IDLE | 用户按复位键 | READ_DIGIT |
| READ_DIGIT | OpenMV 返回数字 | WAIT_LOAD |
| WAIT_LOAD | 微动开关被压下 | DELIVER |
| DELIVER | 检测到目标门口 | AT_ROOM |
| AT_ROOM | 微动开关释放 | RETURN |
| RETURN | 检测到药房门口 | AT_PHARMACY |
| AT_PHARMACY | 自动 | DONE |

**关键**：**每个触发条件必须可靠**——**误触发就乱套**。

**'**微动开关检测装载**'** 的代码：

```c
bool is_loaded() {
    static int debounce = 0;
    if (digital_read(LOAD_SWITCH) == LOW) {
        debounce++;
        if (debounce >= 10) {  // 10ms 防抖
            return true;
        }
    } else {
        debounce = 0;
    }
    return false;
}
```

**'**10ms 防抖**'** 防止微动开关的"机械抖动"误触发。

**第二笔账：超时保护**

**任何状态都不能"卡死"**——**必须有超时退出**：

```c
case STATE_DELIVER:
    follow_line();
    if (door_detected()) {
        state = STATE_AT_ROOM;
    } else if (time_elapsed > 25 seconds) {
        // 超时——可能丢失红线了
        state = STATE_LINE_LOST_RECOVERY;  // 进入恢复状态
    }
    break;
```

**'**线丢失恢复策略**'**——**车原地左右扫描寻找红线**——**找到后继续**——**找不到则报错停车**。

**第三笔账：声光提示**

题目要求**红 / 绿 / 黄三色 LED**：

| 状态 | LED 状态 |
|---|---|
| 待机 | 全部灭 |
| 装药完成、送药中 | 全部灭（行驶中）|
| 到达病房 | **红灯亮** |
| 返回中 | 全部灭 |
| 到达药房 | **绿灯亮** |
| 双车协同等待 | **黄灯亮**（小车 2 暂停）|

**坑**：**说明 (7) 规定** —— "**有任何一个指示灯处于点亮状态的小车必须处于停止状态**"——**意思是 LED 亮 = 必须停车**——**不能边走边亮**。

**这一条非常隐蔽**——**90% 队伍误以为"红灯一直亮表示送药模式"**——**结果违规扣分**。

**正确做法**：**所有"行驶中"的状态 LED 全灭**——**只有"停下"的状态才亮**。

## 第四个谜：双车协同的真正难度

**发挥要求 (1)(2)** 是双车协同——**44 分**——**但 90% 队伍栽在这里**。

**为什么这么难**？

**难点 1：通信不可靠**

NRF24L01 工作在 **2.4GHz** ISM 频段——**和 WiFi（2.4GHz）、蓝牙（2.4GHz）、微波炉（2.4GHz）共用频段**——**电赛比赛场地里全是 WiFi**——**NRF24 丢包率 5%~20%**。

**对策**：

```c
// 自动重传
nrf24_set_auto_retransmit(15, 250);  // 15 次重传，250us 间隔

// 心跳包（每 50ms 一次）
if (heartbeat_timer > 50) {
    send_heartbeat(my_position, my_state);
    heartbeat_timer = 0;
}

// 接收超时检测
if (no_message_for_3_seconds()) {
    enter_safe_mode();  // 失联了，安全停车
}
```

**'**自动重传 + 心跳包 + 失联保护**'**——**三层防御**——**国一标配**。

**难点 2：优先级仲裁**

**两辆车进入同一段走廊**——**谁先走？**

**策略 A：固定优先级**

**永远车 1 先走**——**车 2 让路**——**简单**。

**缺点**：**车 1 故障时车 2 也会卡死**。

**策略 B：动态优先级**

**根据"任务紧急度"或"剩余距离"决定**：

```c
// 比较两车的"剩余距离"
if (my_remaining_distance < other_remaining_distance) {
    priority = HIGH;  // 我离终点近，优先
} else {
    priority = LOW;
}
```

**国一队伍**：**策略 B**——**灵活**。  
**国二 / 国三**：**策略 A**——**简单**——**勉强够用**。

**难点 3：互斥锁**

走廊段（**边**）作为"**资源**"——**一次只能一辆车占用**——**用"互斥锁"管理**：

```c
// 进入走廊前申请
if (request_corridor_lock(target_corridor)) {
    enter_corridor();
} else {
    wait_at_intersection();  // 等待
}

// 离开走廊时释放
release_corridor_lock();
```

**互斥锁的实现**——**用 NRF24 通信协商**：

```c
// 发送"我要进 C1"
send_msg("REQUEST C1");

// 收到对方回复
if (received_msg == "GRANT C1") {
    enter_C1();
} else if (received_msg == "DENY C1") {
    wait();
}
```

**死锁问题**——**两辆车都在等对方让路 → 永远卡死**——**用"超时回退"破解**：

```c
if (waiting_for_lock > 5 seconds) {
    // 主动让路 / 回退
    backtrack();
}
```

**难点 4：错车 / 超车禁止**

**说明 (7)** 明确：

> 两小车协同运送过程中**不允许在同一走廊上错车或超车**。

**'**错车**'**：两车面对面在同一走廊上 → **必须有一辆退到上个路口让路**。

**'**超车**'**：同方向行驶时后车超过前车 → **必须保持队列**。

**实现**：**走廊作为"单线程资源"**——**一次只能一辆车进入**——**互斥锁机制保证不冲突**。

**国一队伍**：**用"令牌环"算法**——**走廊的"令牌"在两车间传递**——**优雅且高效**。

## 把题目逐条翻译一遍

### 任务那段话

> 设计并制作智能送药小车，模拟完成在医院药房与病房间药品的送取作业。

任务定义里的关键词：

- **'**院区**'**——**模拟医院走廊 / 病房 / 药房**——**地面布置 4m × 2m 喷绘布**
- **'**红实线**'**——**循迹引导线**——**1.5~1.8cm 红色胶带**
- **'**黑色数字**'**——**1~8 病房号**——**8cm × 6cm 纸张**
- **'**门口区域**'**——**2cm 黑白虚线**——**告诉小车"到了"**

**任务流程**：

1. **手放到药房（车头朝向病房）**
2. **手举数字纸**——**OpenMV 识别病房号**
3. **放上 200g 药品**——**微动开关触发**
4. **小车自动启动**——**循迹 + T 路口转弯**
5. **到达病房**——**红灯亮、等卸药**
6. **卸药后返回**——**绿灯亮回到药房**

**这是一个完整的"任务流"** —— **所有动作都要"自动化"** —— **任何人为干预都视为失败**。

### 基本要求 (1)：近端病房（12 分）

> 单个小车运送药品到指定的**近端病房**并返回到药房。要求**运送和返回时间均小于 20s**，超时扣分。

**近端病房 = 1 号或 2 号**——**距离药房最近（约 2.5m）**——**简单**。

**第一笔账：往返时间**

```
单程：2.5m / 0.6 m/s = 4.2 秒
T 路口减速：0.5 秒
数字识别：1 秒
门口定位：0.5 秒
小计：6.2 秒
往返：12.4 秒
```

**12.4 秒 < 20 秒**——**留 38% 余量**。

**12 分稳拿**。

### 基本要求 (2)：中部病房（18 分）

> 单个小车运送药品到指定的**中部病房**并返回到药房。

**中部病房 = 3 / 4 / 5 / 6 号**——**距离 4~5m**——**比近端多一个 T 路口**。

**第一笔账**：

```
单程：4.5m / 0.6 m/s = 7.5 秒
T 路口减速：0.5 秒 × 2 次 = 1 秒
数字识别：1 秒（路口辨别走哪条分支）
门口定位：0.5 秒
小计：10 秒
往返：20 秒
```

**正好踩 20 秒**——**需要优化**——**速度提到 0.8 m/s 或减少 T 路口减速时间**。

**国一队伍**：**单程 8 秒，往返 16 秒**——**绰绰有余**。  
**国二队伍**：**单程 10 秒，往返 20 秒**——**压线**——**经常超时**。

**18 分**——**勉强能拿，但有压力**。

### 基本要求 (3)：远端病房（20 分）

> 单个小车运送药品到指定的**远端病房**并返回到药房。

**远端病房 = 7 号或 8 号**——**距离 6m**——**经过 3 个 T 路口**。

**第一笔账**：

```
单程：6m / 0.6 m/s = 10 秒
T 路口减速：0.5 秒 × 3 次 = 1.5 秒
数字识别：1 秒（多个分支辨别）
门口定位：0.5 秒
小计：13 秒
往返：26 秒
```

**26 秒 > 20 秒**——**超时**——**必须优化**。

**对策**：

- **直线段提速到 0.8 m/s**：**6m / 0.8 = 7.5 秒**
- **T 路口减速时间压到 0.3 秒**：**0.3 × 3 = 0.9 秒**
- **数字识别 + 门口定位 = 1.5 秒**
- **小计：9.9 秒，往返 19.8 秒** ← **压线**

**这一项是基本要求最难的**——**20 分**——**踩在 20 秒 vs 25 秒的钢丝上**。

**国一队伍**：**直线 1.0 m/s + T 路口加速过弯**——**单程 8 秒**——**满分**。

### 发挥 (1)：双车同房（23 分）

> **两个小车协同**运送药品到**同一指定的中部病房**。

**任务流**：

1. 车 1 装药、识别、运送、到病房等卸药
2. 车 2 装药、识别、运送、到自选暂停点亮黄灯等
3. 车 1 卸药完成、开始返回、通知车 2 继续
4. 车 2 继续到病房

**核心难点**：

- **两车在同一走廊不能错车 / 超车**
- **暂停点距离 ≥ 70cm**（**说明 (6)**）
- **总时间 < 60 秒**

**前面已经讲过**——**用 NRF24L01 心跳包 + 互斥锁 + 优先级仲裁**——**国一队伍 23 秒**——**满分**。

### 发挥 (2)：双车不同房（21 分）

> 两个小车协同到**不同的远端病房**送、取药品，**小车 1 送药，小车 2 取药**。

**任务流**：

1. 车 1 装药、识别、运送 → **到 7 号病房**
2. 车 2 在药房等待 → 车 1 发"开始取药"指令
3. 车 2 启动 → **到 8 号病房**
4. 总时间 = 车 1 返回 + 车 2 到病房

**核心难点**：

- **远端病房（6m）—— 单程更长**
- **两车一个去 7 号、一个去 8 号** —— **路径有交叉点（同一主走廊）**
- **错车避让** —— **关键节点同步**

**国一队伍**：**双车协同 28 秒**——**满分**。  
**国二队伍**：**45~55 秒**——**勉强**。  
**国三队伍**：**> 60 秒**——**0 分**。

### 说明里的暗坑

**说明 (1)：地面材质**

> 院区可由铺设**白色亚光喷绘布**制作。走廊上的黑线和红线由喷绘或粘贴**线宽约为 1.5cm~1.8cm 的黑色和红色电工胶带**制作。

**白色亚光喷绘布**——**漫反射** + **不刺眼**——**适合红外传感器**。  
**红线 1.8cm 宽**——**5 路传感器（间距 12mm）有 1.5 颗能压在线上**——**精度足够**。

**坑**：**自带的喷绘布如果是亮光面**——**红外传感器读数饱和**——**循迹失败**——**必须用哑光面**。

**说明 (2)：数字字模**

> 数字标号纸张可由无痕不干胶等粘贴在走廊上，其**边框距离实线约 2cm**。图 1 中标识远端病房的两个并排数字边框之间距离约 2cm。

**8cm × 6cm 数字 + 距离红线 2cm**——**OpenMV 安装位置很关键**：

- **离地高度**：**8~10cm**（**能看到地面数字**）
- **斜向下 30°**（**前方 30cm 内能拍到**）
- **测试时调整**——**比赛前一定要试拍**

**说明 (3)：尺寸限制**

> 小车长×宽×高**不大于 25cm × 20cm × 25cm**，**使用普通车轮**（不能使用履带或麦克纳姆轮等特殊结构）。

**和 2024 H 一样**——**禁用麦轮 / 履带**——**必须差速底盘**。

**两小车均由电池供电**——**外界无任何附加电路与控制装置**——**和 2024 H 一样的"自给自足"要求**。

**说明 (4)：照明环境**

> 作品应能适应**无阳光直射的自然光照明及顶置多灯照明环境**。

**意味着**：**早上、中午、下午、晚上都要能跑**——**红外传感器要抗光照变化**。

**对策**：**赛前用赛场实际光照校准红外阈值**——**前面已经讲过**。

**说明 (5)：复位键 + 自动启动**

> 每项测试开始时，**只允许按一次复位键**，装载药品后即刻启动运送时间计时，卸载药品后即刻启动返回时间计时。**计时开始后，不得人工干预**。

**复位键 + 微动开关 + 自动启动**——**全自动流程**——**和 2024 H 一样**。

**说明 (6)：暂停点距离**

> 发挥部分（1）中**自选暂停点处的小车 2 与小车 1 的车头投影外沿中心点的红实线距离不小于 70cm**。

**70cm 是两车安全距离**——**避免碰撞**。

**说明 (7)：LED 等于停车**

> **有任何一个指示灯处于点亮状态的小车必须处于停止状态**。

**前面已经讲过**——**90% 队伍栽在这一条**——**LED 必须只在"停车"时亮**。

**说明 (8)：扣分规则**

> 测试过程中，小车投影**落在黑实线上或两小车碰撞将被扣分**；小车**投影连续落在黑实线上超过 30cm 或整车越过黑实线**，**或两小车连续接触时间超过 5s**，**该测试项计 0 分**。

**'**黑实线**'** = 走廊两侧墙体——**车走偏 = 撞墙 = 扣分**。

**'**两小车连续接触超 5s**'** = 双车协同失败 = **0 分**。

**这一条让"压线"变得致命**——**勉强达标的队伍很容易触发 0 分**。

**说明 (9)：自带数字纸张**

> 参赛者**需自带 2 套数字标号纸张**，无需封箱。

**意味着**：**赛前要打印好 2 套 1~8 数字 + 训练 OpenMV 识别**。

**国一队伍**：**用赛前打印的数字训练 OpenMV**——**识别率 99.5%**。
