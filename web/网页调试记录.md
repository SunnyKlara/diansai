# 网页调试记录（系统级经验，可复用）

> 做校赛 B 时踩到的网页/系统坑 + 修复 + 通用经验。按北极星"双重产出"原则沉淀：每个真实 bug 都变成下次能避开的经验。

## 坑 1：改了内容，网页死活不更新（缓存死锁）

**现象**：给 `problem_briefs.json` 加了校赛 B 的题目解读，服务器侧确认数据正常发出（HTTP 200、含 2026-B、narrative 5539 字），但浏览器里右栏一直显示"题目解读尚未撰写"，反复 Ctrl+F5 也没用。

**排查路径（关键方法）**：
1. **先分清是"没写进去"还是"显示不出来"**：用 `Invoke-WebRequest` 直接从服务器拉 `problem_briefs.json` → 确认数据在 → 排除"没写进去"，锁定"前端没拿到新数据"。
2. **观察局部线索**：左栏题目原件（单独 fetch 的 .md）能显示，右栏（用 1MB json）不显示 → 说明路由/渲染没问题，是**那份 json 拿的是旧缓存**。

**根因（缓存死锁，先有鸡先有蛋）**：
- `index.html` 引用 `./assets/app.js` **没带版本号** → 浏览器永久缓存旧 app.js。
- 旧 app.js 的 fetch **没有 `no-store`** → 它又从缓存里拿旧的 `problem_briefs.json`。
- 于是新数据永远进不来，刷新也没用（刷新还是旧 app.js）。

**修复（两条一起上才彻底）**：
1. app.js 所有数据/markdown 的 fetch 加 `{cache:'no-store'}`（commit `5d905af`）。
2. `index.html` 给 `app.js`/`style.css` 加版本号 `?v=日期`，强制浏览器拿新 JS，打破死锁（commit `c7d6b30`）。

**通用经验**：
- **网页"改了看不到"，第一怀疑缓存，不是代码**。
- **验证用无痕窗口**（Ctrl+Shift+N）——绕开一切缓存，最快确认"到底是缓存还是真 bug"。
- 以后**每次改 app.js/css，把 `index.html` 里的 `?v=` 版本号 bump 一下**（如改日期），用户就不用手动清缓存。
- 数据类 json 已设 `no-store`，改数据立即可见，无需 bump。

## 坑 2：新题在网页打不开 / 404（中文题号）

**现象**：校赛 B 点进去"题目未找到"，错误信息里是 `%E6%A0%A1%E8%B5%9B`（=校赛）。

**根因**：路由用 `年份-题号` 拼 URL，题号是中文"校赛B" → 进 URL 被百分号编码 → 旧 app.js 没解码就比对，匹配不上。

**修复**：① app.js 路由加 `decodeURIComponent`；② 更稳的办法——**题号统一用 ASCII**（"校赛B"→"B"），从根上免疫编码问题（commit `d645eef`）。

**通用经验**：`problems.json` 的 `problem` 字段保持 ASCII（A/B/C…），中文信息放 `title`。

## 坑 3：题目 PDF 不显示，只有文字版

**现象**：校赛 B 左栏只显示 markdown 文字版，没有像其他题那样嵌入 PDF。

**根因**：app.js 标准是——`problems.json` 的 `pdf` 字段有路径就 iframe 嵌入 PDF，空就退回显示 `origin` 的 .md。校赛 B 的 `pdf` 是空的。

**修复（照搬其他题标准）**：把 PDF 放到约定位置 `赛题/原件/<年>/<题名>.pdf`，并把 `problems.json` 的 `pdf` 填上该路径。

**通用经验**：新增题目要在网页显示 PDF，**PDF 必须放在 `赛题/原件/<年>/` 下**（在仓库根、能被 http 服务到），`pdf` 字段填相对仓库根的路径。
