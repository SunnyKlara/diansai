# 独到经验总结：一次"屏不亮"的深度复盘

> 本文不是流水账（流水账见 `../调试日志.md`）。这里沉淀**可复用的根因与方法论**，
> 目标是：下次遇到"外设不工作"类问题，能少走我们这次走过的弯路。

## 0. 一句话结论

> **GC9A01 黑屏的真正根因是 SPI1 的 MODF（模式错误）把 MASTER 位自动清零**——
> 寄存器级初始化时"先置 MASTER、后拉高 SSI"的顺序错误，导致主模式下内部 NSS 为低，
> 硬件立刻报 MODF 并清掉 MASTER，于是 SPI 永不产生时钟、TXP 永不置位、每字节超时。
> **而我们前三次都在错误地猜"内核时钟选错"，全部跑偏。真正一击命中的是"读寄存器实测值"。**

---

## 1. 现象时间线（含我们犯的错）

| 阶段 | 现象 | 我们的判断 | 对错 |
|---|---|---|---|
| 初始 | 背光亮、全黑、串口心跳正常、`LCDto=577396` 巨大固定值 | SPI 没发数据 | ✅ 方向对 |
| 猜测1 | 同上 | 内核时钟选 `pll1_q` 可能=0，改 per_ck | ❌ 跑偏 |
| 猜测2 | 同上 | `SPI123SEL=011` 写错（其实 011=I2S_CKIN），改 `100=per_ck` | ⚠️ 修了一个真 bug，但不是病根 |
| 猜测3 | 同上 | per_ck 依赖 HSI，不保险，改 `000=pll1_q` | ⚠️ 更稳，仍不是病根 |
| **转折** | **读串口寄存器 dump** | `SPISR=0x200(MODF)`、`CFG2` 里 MASTER=0 | ✅ **一击命中** |
| 修复后 | 屏点亮、显示花屏 | 15MHz 杜邦线信号完整性问题 | ✅ 降速到 7.5MHz |

**关键教训先行**：从"初始"到"转折"之间，我们烧了 3 版固件、每版都在调时钟，
**全部无效**——因为时钟从一开始就是好的（实测 `CCIP1=0`=pll1_q、`APB2` SPI1EN=1）。

## 2. 绝对检测方法（本案最大价值）

> 当一个外设"不工作"且你开始**反复猜配置**时，立刻停下，改用下面的"绝对方法"。

### 方法 A：读外设寄存器实测值（首选，零成本）
板上跑着串口心跳，就在心跳里加一行寄存器 dump，把外设的真实状态打出来：

```c
printf("SPISR=%08lX CR1=%08lX CFG1=%08lX CFG2=%08lX CCIP1=%08lX APB2=%08lX\r\n",
       SPI1->SR, SPI1->CR1, SPI1->CFG1, SPI1->CFG2, RCC->D2CCIP1R, RCC->APB2ENR);
```
- **本案实测**：`SPISR=00000200 CR1=00001000 CFG1=30000007 CFG2=04020000 CCIP1=00000000 APB2=00001012`
- 逐位解码（见 §3），10 秒锁定 MODF + MASTER=0。比猜 3 次时钟省下几个小时。

### 方法 B：先证明"板上跑的就是你刚改的固件"（防伪造）
本案我们一度读到的是**旧 bridge 会话缓存**（时间戳比烧录还早），且**寄存器 dump 行根本没出现**。
> **铁证**：dump 行缺失 + `LCDto` 计数值一字不差 = **板上是旧固件，你的修改根本没跑过**。
- 排查"改了没效果"时，第一步永远是确认固件确实更新了：
  - 在遥测里加一个**构建标签/版本号**或一行新打印，烧录后它必须出现在串口上；
  - 不出现 = 烧录链路问题（编译没过、烧的是旧 hex、烧错工程），**先修链路再谈逻辑**。
  - 历史上本工作区曾有**两个同名 `STM32H750.uvprojx`**,极易烧错。经清理后现只剩唯一工程
    `实战复盘/校赛B_智能球平衡控制装置/工程_STM32H750/MDK-ARM/STM32H750.uvprojx`;
    但"确认烧的是哪个工程"这条排查纪律仍要保留。

### 方法 C：物理层兜底（前两者都不够时）
逻辑分析仪/示波器钩 SCK/MOSI/CS/DC：有没有时钟边沿是"SPI 到底动没动"的终极判据。
本案若早用，会立刻看到"SCK 一根脉冲都没有"，直接指向 MASTER 失效。

## 3. 根因技术解析（位级证据）

### 3.1 MODF 是怎么吃掉 MASTER 的
STM32H7 SPIv2，主模式 + 软件 NSS（`SSM=1`）时，**内部 NSS 电平 = `SSI` 位**。
- 错误顺序（旧代码）：
  ```c
  SPI1->CR1  = 0;            // SSI=0  -> 内部 NSS = 低
  SPI1->CFG2 = MASTER|...;   // 此刻置 MASTER，NSS 又是低 -> 硬件判定"多主冲突" -> MODF
  SPI1->CR1 |= SPI_CR1_SSI;  // 晚了：MODF 已把 MASTER 自动清零
  ```
- 硬件行为：MODF 置位 → **自动清 MASTER 和 SPE** → 不再是主机 → 不产生 SCK → `TXP` 永不置位。

### 3.2 实测寄存器逐位对照
| 寄存器 | 实测值 | 解码 | 含义 |
|---|---|---|---|
| `SPISR` | `0x00000200` | bit9=MODF | **模式错误已触发** |
| `CR1` | `0x00001000` | bit12=SSI；bit0(SPE)=0 | SPI 未使能为主机 |
| `CFG2` | `0x04020000` | bit26=SSM,bit17=COMM；**bit22(MASTER)=0** | **MASTER 被 MODF 清掉** |
| `CFG1` | `0x30000007` | DSIZE=7(8bit),MBR=3 | 帧宽/分频正常 |
| `CCIP1`| `0x00000000` | SPI123SEL=000=pll1_q | **时钟源正常**（证明前三次方向错） |
| `APB2` | `0x00001012` | bit12=SPI1EN=1 | 外设时钟已开 |

### 3.3 修复
**先拉高 SSI，再置 MASTER**；中间读一次 `SR` 配合写 `CFG2` 清掉历史 MODF：
```c
SPI1->CR1  = SPI_CR1_SSI;     // 内部 NSS 先拉高
SPI1->CFG1 = (7u<<DSIZE_Pos) | (MBR<<MBR_Pos);
(void)SPI1->SR;               // MODF 清除序列的一半（读 SR）
SPI1->CFG2 = MASTER | SSM | (1u<<COMM_Pos);  // 此时 NSS 已高，MASTER 写入即生效
```
预期修复后：`CFG2 -> 0x044x0000`(MASTER 置位)、`SPISR` 无 0x200、`LCDto` 归零、屏点亮。

### 3.4 收尾：花屏 = 信号完整性
点亮后花屏：杜邦飞线上 15MHz(MBR=3) SCK 振铃导致误码。
- 修复：`LCD_SPI_MBR` 3→4（240MHz/32 = **7.5MHz**），飞线上的稳定点。
- 上 PCB / 缩短线后可回到 /16 或 /8 提帧率。
- 旁证：本案早期软件 SPI 的单色 OLED 也因 >10MHz 出雪花，靠降速解决——**同一类病**。

## 4. 可复用检查清单（拿去直接用）

### 4.1 寄存器级 SPIv2 主机起不来 → 按此顺序查
1. **MASTER 是否保持**：读 `CFG2`，bit22 被清 = MODF。→ 软件 NSS 必须 **SSI 先于 MASTER**。
2. **MODF 标志**：读 `SPISR` bit9；置位则按"读 SR + 写 CFG2"清除并修正顺序。
3. **内核时钟源**：`RCC->D2CCIP1R` 的 `SPI123SEL`。H7 编码：
   `000 pll1_q / 001 pll2_p / 010 pll3_p / 011 I2S_CKIN(外部脚!) / 100 per_ck`。
   **想要 HSI 选 100，不是 011**；最稳是 `000 pll1_q`（随 CPU 必然在跑）。
4. **外设时钟**：`RCC->APB2ENR` 对应 EN 位。
5. **SPE/CSTART**：`CR1` bit0/bit9；发送前 TSIZE 写 `CR2`。
6. **TXP 不置位**：几乎一定是上面 1~3 之一（内核时钟域不动，SR 就不更新）。

### 4.2 "改了没效果"通用铁律
- 加版本标签/新打印，**先证明新固件真的在跑**，再 debug 逻辑。
- 警惕重复同名工程/旧 hex/旧串口缓存——**数据要新鲜**。
- 串口桥读到的时间戳要比烧录时间晚；缺新增遥测行 = 旧固件。

### 4.3 盲调止损铁律（本案最痛的教训）
> **同一方向连猜 2 次没中，立刻换"测量"而非"再猜"。**
> 有遥测就读寄存器，有仪器就上探头。猜配置是线性烧时间，测量是 O(1) 命中。

# 独到经验总结（二）：不稳定对象(悬浮球)的 PID 真机整定

> 配套流水账见 `../调试日志.md` 2026-06-11 M_PID 段；协作方法论已拔高为
> `.kiro/steering/AI协作调试方法论.md`（全仓库默认遵守）。本节沉淀**控制层面的可复用结论**。

## 0. 一句话结论

> **悬浮球是"不稳定平衡 + 极敏感执行器"对象：恒定 PWM 守不住任何中间高度。**
> 解法 = **前馈到工作点(uh) + 先D后P最后弱I**；Kd 有甜区(过头会自撞量程→高频抖)，Ki 必须小(防积分饱和冲高)。
> 最终 `Kp30 Ki0.5 Kd53 uh3400`，15cm 稳态 std≈1.25cm。

## 1. 对象特性（先认清，再调参）

- **升力曲线极陡**：手动扫 PWM(9600标度)实测 —— 3300 球落底、3500 球顶到 ~38cm、4000 钉顶。
  即 **~200 个 PWM 计数跨越整个管程**，执行器增益极高、悬停带仅 ±150 PWM 左右。
- **不稳定平衡**：3300 恒定 PWM 下，球从 38 一路平滑落到底、**穿过 15cm 仍在掉**——
  中间没有任何稳定驻点。这是"双积分类不稳定对象"的指纹：**必须实时反馈 + 强阻尼才能驻定**。
- **四线风扇冷启动**：静止→满速有死区+静摩擦+~3s 转速爬升 → 用"闭环前先怠速预热"消除。

## 2. 为什么必须有前馈 uh（推翻"删 uh"的直觉）

- 我方积分权限 = `Ki × PID_INTEGRAL_LIMIT`（如 0.5×200=100PWM），而悬停需 ~3400PWM。
- **删掉 uh，P+I+D 永远到不了悬停量 → 球趴底**（正是超声波时代"P380托不起球"的现象）。
- 开源同款 davidoises 能无前馈，是因其 Ki 自由无限幅积分能自己积出悬停量；我方积分有限幅，
  **故前馈是正解**。控制律 `u = uh + Kp·e − Kd·v + Ki·I` 已是教科书写法，不要瞎删。

## 3. 三个参数的真机表现（量化甜区）

| 参数 | 作用 | 真机现象 | 甜区 |
|---|---|---|---|
| **Kd** | 阻尼(不稳定对象稳不稳的关键) | 太小发散冲顶/落底；**太大(>60)D项自己撞满量程→高频抖+压死爬升** | **~53** |
| **Kp** | 刚度(拉回+追上升) | 太小上升慢/拉不回；太大过冲。**加大同时改善上升与稳态(误差变小)** | **~30** |
| **Ki** | 消静差 | =0 留静差(球停目标下方2.7cm)；**太大(>1)积分饱和→冲高超调** | **~0.5** |
| **uh** | 前馈到工作点 | 手动扫"球不快升不快降的刀刃点" | **3400@15cm** |

> **反直觉点(血泪)**：Kd 不是越大越稳。`Kd × 球速峰值(~18cm/s) ≈ 1600PWM` 早已超过整个悬停带 →
> D 项单独就把 PWM 甩到撞墙，形成 bang-bang 极限环。**"越加 Kd 越差 = 方向反了，立刻砍回"。**

## 4. 整定顺序（真机验证有效）

1. **标 uh**：手动扫 PWM 找悬停刀刃点（不快升不快降）。
2. **先 Kd**：kp0 ki0，从小加到"球速被压住、不撞顶底"。**别过头**。
3. **再 Kp**：加到能稳在目标±2cm，刚过冲就退一档（顺带把上升提速）。
4. **最后弱 Ki**：消静差，给 0.x 级小值，冲高就减半（Ki 加超调，不是减）。
5. **辅助项固定别乱扫**：EMA(f)/Dclamp(c)/slew(l)/ramp(r) 给合理定值即可，不是主旋钮。

## 5. 几个工程坑

- **PWM 带宽两义**："PWM 上下限范围(n/x)" vs "每拍变化量(slew/l)"——沟通时说清是哪个（本次踩过）。
- **天花板不能砍太狠**：维持 15cm 需峰值~3700，对称缩带宽把天花板砍到 3550 → 球塌到 9cm。
  要压浮动应**只抬 floor**(限下沉过冲)，**保留天花板**(保证够得到目标)。
- **ramp 不能设 0**：`r0` 会冻结软目标在起始高度，球永远到不了 target。
- **悬停 PWM 随高度变**：本组是 15cm 中心值，10/20cm 不通用，待验证（可能需按高度调度 uh/带宽）。
