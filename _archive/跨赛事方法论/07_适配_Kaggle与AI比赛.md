# 适配 · Kaggle / 阿里天池 / 飞桨星河 等数据竞赛

> 数据竞赛是"每天提交几次、几个月磨一个 leaderboard 名次"的长跑型比赛。
> 本框架对它的价值：把"跑过的实验"沉淀成可复现资产，避免最后半个月想不起来 5 周前那次 0.83 的方案。

---

## 1. 与电赛的核心差异

| 维度 | 电赛 | Kaggle/天池 |
|---|---|---|
| 周期 | 4 天 | 1~3 个月 |
| 提交 | 1 次 | 每天 5~10 次 |
| 队伍 | 2~3 人 | 1~5 人，可远程 |
| 关键资产 | 一份代码 | **几十次实验记录 + 数据流水线** |
| 输出 | 实物 | LB 分数 + 解决方案 PPT |

差异最大的点：**实验管理**。本框架要在 `04_调试记录/` 改造一个"实验日志"。

## 4. 实验日志格式（核心创新）

`04_调试记录/实验日志.md`：

```markdown
# 实验日志

| ID | 日期 | 模型 | 关键改动 | 本地CV | LB分数 | 备注 |
|---|---|---|---|---|---|---|
| 001 | 11-01 | lgb | baseline | 0.821 | 0.819 | 起步 |
| 002 | 11-02 | lgb | + 10 个统计特征 | 0.834 | 0.831 | ↑ |
| 003 | 11-03 | lgb | + target encoding | 0.831 | 0.823 | 过拟合，回退 |
| 004 | 11-04 | xgb | 替代 lgb | 0.829 | 0.826 | 不如 lgb |
| 005 | 11-05 | lgb | hyperopt 调参 | 0.838 | 0.835 | ↑↑ |
| 006 | 11-06 | nn | tabnet baseline | 0.812 | - | 没提交 |
| 007 | 11-07 | ensemble | lgb 0.7 + nn 0.3 | 0.842 | 0.839 | ↑↑↑ |
```

**铁律**：

- 每次提交都进表，不管多差
- 本地 CV 和 LB 分数都记，差太大要警觉（数据泄露/过拟合）
- 配置文件名必须和 ID 对应（`exp_001_*.yaml`），永远可复现
- 用 wandb / mlflow 自动同步更好

## 5. 量化指标

| 指标 | 目标 | 自检 |
|---|---|---|
| 实验数量 | > 30 次 | 实验日志计数 |
| baseline 建立时间 | < 比赛开始 7 天 | git log |
| 本地 CV 与 LB 相关性 | > 0.85 | 散点图 |
| 最终方案是否可复现 | 100% | 队友盲跑 |
| solution writeup 完整度 | 含数据/特征/模型/集成 4 节 | checklist |

## 6. AI 协作的数据竞赛特化指令

```markdown
## 数据竞赛特化规则

- 每个新实验必须新建 yaml，不允许直接改之前的（保留历史）
- 每次 train.py 跑完自动写入 `实验日志.md` 一行（提供脚本）
- 数据相关的代码必须在 `data/` 目录，特征工程函数必须可单测
- LB 分数 vs 本地 CV 差异 > 0.01 时，AI 必须警告"可能数据泄露"
- 比赛结束前 7 天进入"只集成不改特征"模式
- AI 自主决策实验方向，但每完成 5 个实验汇总一次趋势
```
