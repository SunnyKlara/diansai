# 天猛星 编译烧录操作手册（实验室速查，改完代码照着做）

> 目标：改完代码 → 一步烧进板子 → 看现象。三种方式任选，**方式 A 最省事**。
> 已真机验证：外置 CMSIS-DAP 接 SWD（DIO/CLK/GND），OpenOCD 烧录 `Verified OK`，板载 PB22 LED 闪。
> **🔴 代码位置铁律**：MSPM0 工程放在**仓库内的全 ASCII 路径** `workbench/mspm0/`（如 `workbench/mspm0/car`、`workbench/mspm0/tmx_blinky`）。**绝不能放中文路径**（如 `天猛星主板平台/01_代码/`）——GCC 工具链处理中文路径会乱码报 `device.opt ... not found`（2026-07-24 实测，见调试日志 M-坑）。`C:\ti` 只放工具(SDK/编译器/OpenOCD)。
> 下文命令里的路径示例：编译在 `workbench\mspm0\<工程>\gcc\` 下跑；输出名 = 工程名（`car` 工程出 `car.out`，`tmx_blinky` 出 `gpio_toggle_output.out`）。

## 0. 每次开工前 30 秒接线自检（分线后必查）

| 线 | 从 | 到 | 备注 |
|---|---|---|---|
| SWDIO | DAP 的 DIO | 板子 `DIO`(PA19) | 烧录数据 |
| SWCLK | DAP 的 CLK | 板子 `CLK`(PA20) | 烧录时钟 |
| GND | DAP 的 GND | 板子 GND | **必接**，否则连不上 |
| 供电 | — | 板子 5V 或 3V3 | 板子要**先上电**再烧 |

> 只烧录调试：SWD 三根线(DIO/CLK/GND) + 板子供电即可。DAP 一般不给板子供电，板子要自己有电。

## 3. 改引脚 / 加外设（电机、串口、ADC…）

1. 用 SysConfig 打开工程根目录的 `gpio_toggle_output.syscfg`：
   - CCS 里双击它；**或**命令行 `C:\ti\sysconfig_1.28.0\sysconfig_cli.bat`（GUI 用 `sysconfig_gui.bat`）。
2. 图形界面里加外设（GPIO/TIMER-PWM/ADC/UART/SPU…），按 **§10 定版表**填引脚（如电机 PWM = PA8/PA9/PB12/PB13）。
3. 保存 → 下次编译自动重生成 `ti_msp_dl_config.*`，代码里用生成的宏名即可。

## 4. 看串口输出（COM30）

板子 UART0(PA10 TX/PA11 RX) 接到 USB 串口后是 **COM30**。看打印用任一：
- VS Code 扩展 **Serial Monitor**，选 COM30、波特率对上（常用 115200）。
- 或任意串口助手 / PuTTY，端口 COM30。
> 注意：**COM30 是串口，不是烧录口**；烧录永远走 DAP 的 SWD。

## 6. 常见故障速查

| 现象 | 大概率原因 / 解法 |
|---|---|
| `Error connecting to target` / 连不上 | DAP 没插好 / SWD 的 DIO·CLK·**GND** 没接全 / 板子没上电；换根线；确认 DIO↔DIO、CLK↔CLK 没接反 |
| `startup...No such file` 编译报错 | 你（或谁）跑了 `make clean` 删了 SDK 共享 startup。**永远别用 make clean**，用 “clean(安全)” 任务；误删就从别的例程复制 `startup_mspm0g350x_gcc.c` 回 `C:\ti\mspm0-sdk\source\ti\devices\msp\m0p\startup_system_files\gcc\` |
| 烧进去了但没反应 | 看是不是烧的引脚没接你要的外设；LED/电机脚对不对；`Verified OK` 只保证烧进去了，不保证你逻辑对 |
| openocd 卡住不退 | 别在脚本里“边跑边读内存/反复 halt”；杀掉：`Get-Process openocd | Stop-Process -Force` 再重来 |
| 编译一堆 warning | driverlib 头文件的 `-Wreturn-type` 警告是正常的，不影响；只看有没有 `error:` |
| 改了 .syscfg 不生效 | 确认保存了；重新编译会重生成配置 |

## 8. 🆘 紧急救砖：`Could not find MEM-AP` / 板子锁死连不上

**症状**：烧录报 `Error: Could not find MEM-AP to control the core`（能读到 `SWD DPIDR` 但够不到核）；PB22 不闪、屏黑；**断电重启也不恢复**。
**原因**：内核陷入 **double fault 死锁(lockup)**——多半是**连续快烧 / 反复 halt / 中途打断 program** 把 flash 写成了无效镜像，上电执行非法指令→死锁，死锁的核把 SWD 的 MEM-AP 一起门控掉；空白/无效 flash 使每次上电立刻再死锁（所以断电没用）。

**救法（一条命令搞定，需手点 RST 键配合）**——在工程 `gcc` 目录里跑：
```powershell
openocd -s C:/ti/xpack-openocd-0.12.0-7/openocd/scripts -f interface/cmsis-dap.cfg -c "adapter speed 500" -f target/ti_mspm0.cfg -c "init" -c "mspm0_factory_reset" -c "flash write_image erase gpio_toggle_output.out" -c "verify_image gpio_toggle_output.out" -c "reset run" -c "shutdown"
```
1. 回车后**立刻"哒哒哒"连续点按板子 RST 键**（提供工厂复位需要的 NRST 脉冲；本 DAP 没接复位线，靠手点）。
2. **一看到 `Factory reset success!` 就立刻停止点按**（写 flash 阶段绝不能再复位）。
3. 自动 `wrote ... bytes` + `verified` + `reset run` → 完成。
4. 烧完**按一下 RST** 做干净冷启动（否则可能背光亮但黑屏——软复位后显示初始化没吃到冷启动，硬复位一下即好）。
> 换成别的工程时把命令里 `gpio_toggle_output.out` 换成你的 `.out` 名。

**预防（今天血泪铁律）**：
1. **绝不连续狂烧 / 反复 halt / 中途打断烧录**——这是把内核怼死锁的根。节奏永远：**烧一次 → 看现象 → 改代码 → 再烧一次**。
2. **每次烧完按一下 RST** 做冷启动再看现象。
