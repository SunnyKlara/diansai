## 1. 命令行 / VS Code 路线（推荐日常用，已验证）

编译链：`SysConfig 生成配置 → arm-none-eabi-gcc 编译 → 链接出 .out → objcopy 出 .hex/.bin`。

### 1.1 编译（两种方式）

**方式 A：VS Code（推荐）** — 用 Kiro/VS Code 打开 `workbench\mspm0\car`（或 `tmx_blinky`）文件夹：
- `Ctrl+Shift+B` → 跑 **build** 任务（已在 `.vscode/tasks.json` 配好，自动把 GCC/make 加进 PATH）。
- 终端任务里还有：`hex/bin`（转烧录格式）、`flash (OpenOCD/XDS110)`（烧板）、`clean (安全)`。

**方式 B：纯命令行** — 在 `tmx_blinky\gcc\` 目录：
```powershell
# 先把 make 和 gcc 放进本次会话 PATH（VS Code 任务已自动做）
$env:Path += ";C:\Users\Klara\AppData\Local\Microsoft\WinGet\Packages\BrechtSanders.WinLibs.POSIX.UCRT_Microsoft.Winget.Source_8wekyb3d8bbwe\mingw64\bin"
mingw32-make                     # → gpio_toggle_output.out
```
> `imports.mak`（在 `C:\ti\mspm0-sdk\`）已把 `GCC_ARMCOMPILER` 和 `SYSCONFIG_TOOL` 指向本机安装路径，所以直接 make 即可。

### 1.2 烧录（OpenOCD 走板载 XDS110，需连板）
```powershell
C:\ti\xpack-openocd-0.12.0-7\bin\openocd.exe `
  -s C:/ti/xpack-openocd-0.12.0-7/openocd/scripts `
  -f interface/xds110.cfg -f target/ti_mspm0.cfg `
  -c "program gpio_toggle_output.out verify reset exit"
```
- 天猛星板载调试器若是 **CMSIS-DAP** 而非 XDS110，把 `interface/xds110.cfg` 换成 `interface/cmsis-dap.cfg` 即可（两份配置 OpenOCD 都带）。
- OpenOCD 这个版本是 2025-10 的 dev 构建，**已含 `target/ti_mspm0.cfg`**（MSPM0L/G 通用），所以能认 G3507。

### 1.3 调试（VS Code 图形单步）
- 装 VS Code 扩展 **Cortex-Debug**（`marus25.cortex-debug`）。
- 按 `F5` → 用 `.vscode/launch.json` 里的 “Debug (OpenOCD + XDS110)”，OpenOCD 起 gdbserver、`arm-none-eabi-gdb` 连上，停在 `main`。

## 3. 开新题工程的标准流程

1. **复制**起步工程：`workbench\mspm0\tmx_blinky` → `workbench\mspm0\<新题名>`（**全 ASCII 路径**，GCC 不认中文路径）。
2. **配引脚**：用 SysConfig 打开工程根目录的 `.syscfg`（命令：`C:\ti\sysconfig_1.28.0\sysconfig_cli.bat` 或在 CCS 里双击），按 **`00_载板接线设计_天猛星平台.md` §10 定版表**添加外设、分配引脚，保存后自动重生成 `ti_msp_dl_config.c/h`。
3. **写代码**：按仓库规范分 `Core/Drivers/Algorithm` + `config.h`（引脚宏可直接抄 §10.11）。
4. **改工程名**（可选）：`gcc/makefile` 里 `NAME=` 和源文件名同步改。
5. `Ctrl+Shift+B` 编译 → 连板 flash 任务烧录。

> §10 的 `config.h` 引脚宏与本工程一一对应，抄过去即可无缝对接“载板接线设计”。

## 4. 关键坑（本次踩过，务必记住）

| 坑 | 说明 / 对策 |
|---|---|
| ⚠ **别用 `make clean`** | TI 的 GCC makefile 的 `clean` 会把 SDK 里**共享的 startup 源文件**（`source/ti/devices/msp/m0p/startup_system_files/gcc/startup_mspm0g350x_gcc.c`）一起删掉，导致之后所有工程编译报“startup...No such file”。**只用** VS Code 的 “clean (安全)” 任务或手动 `del *.obj *.out` 清本地产物。误删了就从别的例程或 SDK zip 恢复该文件。 |
| GitHub SDK zip 无 `imports.mak` | 官方安装器才生成；本机已手写好放在 `C:\ti\mspm0-sdk\imports.mak`。换机/重装 SDK 记得补这个文件。 |
| 工程拷出 SDK 目录后编译报路径错 | 例程 makefile 默认 `MSPM0_SDK_INSTALL_DIR ?= $(abspath ../../../../../..)`（相对 SDK 树）。拷到别处要改成绝对路径 `C:/ti/mspm0-sdk`（`tmx_blinky` 已改好）。 |
| TI 服务器下载极慢(~66KB/s) | SDK 改从 `codeload.github.com/TexasInstruments/mspm0-sdk/zip/refs/heads/main` 下（快）；GitHub release 资源(objects.githubusercontent.com)国内易被墙，走 `https://gh-proxy.com/` 前缀镜像。 |
| ARM 工具链未进某些 shell 的 PATH | bin 在 `C:\Program Files (x86)\Arm GNU Toolchain arm-none-eabi\12.2 mpacbti-rel1\bin`；VS Code 任务已在 `options.env.PATH` 里显式加好。 |
| 调试无寄存器视图 | GitHub 版 SDK 没带 `MSPM0G3507.svd`；要寄存器视图可从 CCS 装的 SDK 或 TI 单独下 svd，填到 `launch.json` 的 `svdFile`。 |
