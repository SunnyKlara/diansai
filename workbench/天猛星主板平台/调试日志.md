## 2026-07-24  M-事故  MSPM0 内核死锁(lockup) → 调试口 MEM-AP 消失 → 工厂复位救砖（真机 ✅ 已恢复）
- 现象链：LCD demo 本跑得好好的（计数跳）→ AI **连续快速反复烧录/openocd 连接压测** → 之后烧录一律报 `Error: Could not find MEM-AP to control the core`（DP 能读 `DPIDR 0x6ba02477`，但 AP 消失）→ PB22 不闪、屏黑、**断电重启也不恢复**。
- **根因（实锤）**：内核陷入 **double fault → lockup**（工厂复位过程刷出 `clearing lockup after double fault`）。触发链：连续快烧中某次 `program` 擦了 flash 又被打断 / 反复 halt 打断运行 → flash 留下**无效镜像** → 上电执行非法向量 → HardFault→双故障→**内核死锁** → 死锁的核**同时把 SWD 的 MEM-AP 门控掉** → 既连不上也跑不了；且无效/空白 flash 使**每次上电立刻再死锁**（所以断电重启无效）。
- **没用的救法**：① 按住 RST 再连（松手时机救不了）；② 单独 `mspm0_factory_reset` 成功后**再单独** `program`（两条命令之间核又死锁）；③ 单独 `program` + 点 RST（program 只 examine 一次，抓不到窗口）。
- **✅ 成功救法（可复现，记死这条）**：把"工厂复位 + 写固件 + 复位运行"**塞进同一条 openocd 命令**，中间不给它再死锁的机会：
  ```powershell
  openocd -s C:/ti/xpack-openocd-0.12.0-7/openocd/scripts -f interface/cmsis-dap.cfg -c "adapter speed 500" -f target/ti_mspm0.cfg -c "init" -c "mspm0_factory_reset" -c "flash write_image erase gpio_toggle_output.out" -c "verify_image gpio_toggle_output.out" -c "reset run" -c "shutdown"
  ```
  操作：回车后**"哒哒哒"连续点按板子 RST 键**；**一看到 `Factory reset success!` 立刻停手**（别在写 flash 时再复位）；随后自动 `wrote 11064 bytes` + `verified` + `reset run`。原理：工厂复位(DSSM 命令 0x020a，走 SECAP/AP2，不需要 MEM-AP)解锁并 halt 住内核 → 趁 AP 还开着一口气写入**有效**固件 → 复位跑新固件，不再死锁。`mspm0_factory_reset` 需要真复位 NRST，本 DAP 没接复位线 → 靠**手点 RST 键**提供。
- **烧后小 quirk（非故障）**：`reset run` 软复位后屏黑（背光亮）；**手动按一下 RST 硬复位 → 正常显示**。→ 烧完按一次 RST 做干净冷启动即可。
- **预防（铁律）**：① **绝不连续快烧 / 反复 halt / 中途打断 program**（今天死锁的根）——节奏永远是"烧一次→看现象→改→再烧"；② 遇 `Could not find MEM-AP` + 核不跑 + 断电无效 = 死锁，用上面那条组合命令 + 点 RST 救；③ 烧完按一次 RST 冷启动再看现象。

## 2026-07-24  M-串口  car 加 UART0 调试打印 + DAP VCOM 读通（真机 ✅）

- **目标**：小车要串口 log。天猛星"默认调试串口"= **UART0**，丝印 `A10`/`A11`（§10.1）：**PA10=UART0_TX、PA11=UART0_RX**，接 DAP 的 VCOM。
- **接线（交叉！）**：天猛星 `PA10(TX)`→DAP `RX`、`PA11(RX)`→DAP `TX`、`GND` 共地。DAP 的 VCOM 在本机枚举为 **COM30**（设备名"USB 串行设备"）。
- **代码**：`car.syscfg` 加 UART 模块（`$name=DBG_UART`→UART0，`rxPin=PA11`/`txPin=PA10`，115200，enableFIFO）；新增 `uart_dbg.c/.h`（`DL_UART_transmitDataBlocking` 逐字节阻塞发，不用 printf 省 flash）；`car.c` 每次动作切换打一行 `[car] #n NAME M1=.. M2=..`。固件 text 12784→13504B。
- **真机验证**：openocd `reset run` 后，PowerShell 开 COM30@115200 读 6s，收到 `[car] #14 TURN M1=40 M2=-40` / `#16 REVERSE M1=-40 M2=-40` … 连续正常 → **串口通路 + 波特率 + 接线方向全对**。开头几个字节乱码 = 开串口瞬间抓到半个字节，正常，丢弃即可。
- **API 名坑**：发送是 `DL_UART_transmitDataBlocking(inst, byte)`（**不带 Main**）；接收是 `DL_UART_receiveDataBlocking`。而填 FIFO 的是 `DL_UART_Main_fillTXFIFO`（带 Main）。命名不统一，先 grep `dl_uart.h` 确认再用。
- **🔴 烧录 verify 坑**：`program car.out verify reset` 在 verify 阶段报 `timed out while waiting for target halted` + `error executing cortex_m crc algorithm` → **Verify Failed 且不 reset**。根因：verify 用 CRC 要 halt CPU 跑校验程序，@1000kHz SWD 时序抖动偶发超时。**flash 其实已写入成功（Programming Finished）**，不是固件坏。
  - **解法**：烧录降速 **500** + **去掉 verify**：`program car.out reset exit`（写完直接复位跑）。开发调试看 log/看现象即可判对错，不必每次 CRC 校验。或烧后手动按 RST。
