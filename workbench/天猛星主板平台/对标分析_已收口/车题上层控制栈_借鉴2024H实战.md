## 1. 六条可直接落地的技术点

### 1.1 速度环：前馈是主力，PI 只修残差（+ 目标斜坡 + 停车清积分）

他们 `update_wheel()` 的结构：

```text
out = FF·target + Kp·err + ∫Ki·err        // FF 单位 = PWM per (count/10ms)
if (target == 0) { integral = 0; return 0; }   // 停车指令下强制清积分、输出 0
target 每拍只向请求值走一小步（slew）         // 阶跃→斜坡，减冲击/超调
积分限幅 + 输出限幅
```

落到我们平台：FF 系数**用我们已有的开环标定反推**（开环扫 PWM→稳态转速的线性增益在 `config.h`，取其倒数即"每单位目标需要多少 %PWM"），PI 只补残差。**这正是校赛B「C2 前馈到工作点」**——我们在悬浮题上守了，小车速度环上漏了（见 §3.1）。

### 1.2 航向环：P 作用在误差、D 直接取陀螺角速度；原地转另设一套增益 + 最小转向量破静摩擦

```text
直行段： turn = -(yaw_err / 40) + (gyro_z / 400)      // 全整数, 毫度/毫度每秒定点
原地转： turn = -(yaw_err / 30) + (gyro_z / 150)      // 增益更硬
        若 |yaw_err| 还很大、但输出偏小且角速度很低 → 强制给一个最小转向量
yaw 全程 wrap 到 ±180000 mdeg
```

三个要点值得抄：① **D 项取自陀螺原始角速度**（不是对误差求导）= 校赛B「C5 微分作用在测量」同源；② **直行 / 原地转两套增益**（负载性质完全不同，一套调不好两件事）；③ **最小转向量破静摩擦**——这和我们位置环"死区前馈按误差方向"是同一个思想的航向版，**互相印证我们那条做法是对的**，可直接平移到转角闭环。④ 全部用 **mdeg / mdps 整数定点**，不碰浮点（见 §3.2）。

### 1.3 循迹：线误差要滤、丢线要"熬"、弯道要前馈

```text
误差一阶平滑：  e_f = (e_f + e_raw) / 2
微分再平滑：    d_f = (3·d_f + (e_f - e_prev)) / 4
转向量 = 曲线前馈 curveBias + Kp·e_f + Kd·d_f，然后限幅
丢线：计数累加，连续 N 帧才判定停车；**未确认前保持最后一次有效误差**、不推进状态
左右目标 = 基速 ± 转向量；基速限定在一个窄区间（他们 8~20）
```

- **曲线前馈 `curveBias`**：已知半径的圆弧给一个固定差速偏置，PD 只修残差 → 又是"前馈 + PID 修残差"这个母题（第三次出现了）。
- **编码器差当角速度阻尼**：`yaw_err = (leftΔ - rightΔ) - 2·期望转向`，用左右轮增量差与期望转向的偏差做阻尼项。**没有 IMU 也能抗歪**，我们陀螺没到货时可以先用这招把循迹跑起来。
- **丢线不立刻停**：这是防抖关键。我们所有"到位/丢失/触发"判据都该照此加"持续 N 拍"。

### 1.4 灰度传感器：MUX 八通道 + 现场标定流程

他们 `bsp_gray.c` + 串口 `cal start`/`cal stop`/`gray`/`line`：74HC4051 八通道轮询进单路 ADC → **`cal start` 开 8 秒，人手持车把黑线扫过每个传感器**，记 per-channel min/max → 归一化成 blackness → 加权求线误差 + 线强度 + 丢线 flag。

我们没有灰度模块（清单里是光电），但**这套"上场前现场标定 + 归一化 + 加权"的流程照样适用**任何多通道模拟传感器阵列（光电/反射/ADC 阵列）。赛场光照会变，**没有现场标定的循迹一定翻车**。

### 1.5 状态跳转要"多传感器合议 + 持续确认"，不靠单一信号

他们 route3 的端点判定：**至少走够 5000 编码器计数** AND **IMU yaw 在期望出口航向 ±35° 内** AND **连续 12 帧（120ms）丢线** → 才认到达。原地转到位：**|yaw 误差| < 3.5°** AND **角速度连续 5 拍已稳**。

我们位置环到位只判 `|err| < tol`（实测够用），但**任务状态机一定要按合议来**——单信号跳转在赛场必误触发。

### 1.6 工程安全与可观测（三条便宜且有用）

1. **测试命令固件侧自带时限自停**：`motor` 1 秒、`speed` 3 秒、`follow` 2 秒、长跑给 15 秒 guard timeout。→ PC 掉线/脚本崩了车也会停。我们现在靠 PC 端补发 `z`，**不如固件自保**。
2. **遥测单行 key=value**：`t=..,state=..,mode=..,line=..,lost=..,vl=..,vr=..,pl=..,pr=..,event=..` + `log on/off`。加字段不破解析——正对我们"固件改格式→脚本静默失效"那条坑。
3. **运动测试用串口日志，不用调试器 halt**（他们 AGENTS.md 明写）——和我们 `dbg.ps1` 的安全提醒一致，互相印证。

## 3. ⚠️ 因为读它才发现的两个我们自己的问题

### 3.1 我们的速度环没有前馈——校赛B 的铁律没跨题迁移过来

`grep feedforward|ff|slew|ramp` 在 `control.c`/`car.c` 里只命中**位置环的死区前馈**；速度环是纯 PI。这解释了修完时基 bug 后为什么"环发软、要把 Kp 抬 5 倍、靠积分硬顶"。

**改法（低风险、不改结构）**：速度环输出加一项 `FF = target / 线性增益`（线性增益已在 `config.h`，开环标定过），PI 只修残差；同时 target 加 slew。**预期**：同样超调下响应更快、Ki 可以更小、掉压时更稳。
**状态：`待真机验证`**，且**要不要在省赛前动，等你拍板**——速度环现在是真机达标锁死的（`4bbaae5`），改它要重跑阶跃+抗扰验证。

### 3.2 我们的控制/姿态代码全用 float，而 MSPM0G3507 是 Cortex-M0+，**没有硬件 FPU**

**实测证据**（不是推断）：`arm-none-eabi-nm gcc/car.out` 里链进了软浮点例程 `__aeabi_fadd / fsub / fmul / fdiv / f2iz` + 一组 `fcmp*`。`control.c`/`attitude.c`/`imu.c`/`car.c` 共上百处 `float`。他们那边**全程 int32 定点**（x100 / mdeg / mdps），一处浮点都不用——在 M0+ 上这不是风格问题，是 CPU 预算问题（软件 fdiv 上百周期，整数运算 1~几周期）。

**诚实边界**：我**没有实测**我们当前的 CPU 占用，速度环/位置环现在是达标的 → **这不是现存故障，是余量风险**。但我们刚被"LCD 重绘吃满主循环 → 时基虚高 5×"咬过一次，等上层再叠循迹/航向/视觉解析，float 的成本会咬第二次。
**建议**：省赛前**不动**（改数值类型 = 全面回归）；一旦发现 CPU 吃紧，优先把**热路径**（5kHz ISR 里的采样/PID）改定点，而不是先去砍功能。**跨平台教训**：校赛B 是 STM32H750（有 FPU、480MHz），那套"随便用 float"的习惯搬到 80MHz 无 FPU 的 M0+ 上不成立——已入坑库。

## 5. 不照搬的部分

- **器件全不同**：TB6612 / 74HC4051 灰度 / ICM-45686(I2C) / ST7735S ↔ 我们 DRV8231 / 无灰度 / ICM42688(SPI 共享) / GC9A01。引脚一律看我们的 `工程事实SSOT.md §B`，**别用他们 `docs/hardware_*.md` 的引脚**。
- **编码器解码**：他们左轮硬件 QEI + 右轮边沿中断；**我们两路软件定时采样 4x 正交解码更抗电机 EMI**（真机结论，见坑库），别倒过来学。
- **工程与构建**：他们 CCS Theia 工程 + `tools/build.ps1`；我们 GCC + `gcc/makefile`。
- **他们的具体增益值**（Kp/Ki/FF/除数）是他们车的质量、轮径、编码器线数、控制周期下的值，**只抄结构与比例关系，不抄绝对值**（校赛B「M4 只抄结构不抄数值」）。

## 6. 深挖第二轮（2026-07-27 · 已完整 clone + 读完 bring-up 全流水）

工程已**完整**存进 `library/.../参考工程_2024H电赛车_MIT/`（57 文件，含 `tools/`、`module_manuals/`、CCS 工程、**2024-H 题目原件截图**、以及我们提炼的 `01_人类提问序列_提炼.md`）。读完 `docs/logs/bringup_log.md`（他们的真机 bring-up 全流水）后，挖到下面这些——**其中好几条是我们现在就能用的**。

### 6.1 ⭐"低频左右摆"的根因不是 PID，是**目标量化分辨率不够**

他们循迹跑弧线一直有"走直线→偏了→突然回正→再走直线"的**离散步进式**运动，调了好几轮增益（35/120 → 40/220 → 试软的 20/80 更差）都只是减轻。**真根因**：轮速目标是整数 `count/10ms`，**一个转向单位就让左右轮速差跳 2 个整数 counts** → 车只能在"近似直行"和"猛纠正"之间跳。**解法不是调增益，是把目标定点化到 0.01 count/10ms**（`followfine`）→ 一次就"几乎没有近似直走再突然回正的感觉"。

对我们：速度环目标现在是整数、位置目标是整数 counts。**以后循迹/航向出现"步进式纠正"，先查目标量化分辨率，别一头调增益**（已入坑库）。

### 6.2 ⭐编码器解码要带"非法状态转移计数"当**反馈健康门**

他们 `bsp_encoder.c` 每路维护 `invalidTransitions` 计数，每次真机测试都报 `0,0` 当"解码干净"的证据。我们 `encoder.c` 的 4x 正交解码**没有这个计数**（已核实）——而我们自己的 `AI协作调试方法论` 明写"工具要内置反馈健康门，不绿不许往下走"。**这是我们方法论要求、但代码没提供的东西。** 补法见 §8.1。

### 6.3 多通道 ADC 轮询采样的四件套（我们只做了其中一件）

他们 `bsp_gray.c` 每通道：**切通道 → `delay_cycles(800)` 建立时间 → 丢弃第一次转换 → 4 次平均 → 一阶 IIR `(3×旧+新)/4`**。
我们的双通道电流采样只做了"16 次平均"，**没有切换后建立延时、也没有丢弃第一次转换**。→ **新假设（`待验证`）**：我们电流反馈残余 ±40~100mA 噪声，除了斩波纹波，**通道切换后采样保持电容未充满**可能也是一部分。这条便宜、可单独验证（先只加"丢第一次 + 建立延时"，看噪声降不降）。

### 6.4 线位置加权用 **blackness 的平方**，有效性判据用双条件

`weight = blackness²/1000`（0..1000 归一化后平方）→ 强化中心强信号、压低边缘弱通道对加权位置的拉扯；`valid = 最强通道 blackness ≥ 650 AND 总强度 ≥ 300`（又是合议）；标定有效性判据 = **每通道黑白跨度 ≥ 100，八通道全过才算标定 ready**。

### 6.5 死区阈值是**上下夹逼**出来的，不是拍一个数

全白误判有线（白底波动被标定极值映射到 61% blackness）→ 加 60% blackness 死区 → 全白干净了，**但弧线上摆动变大**，因为死区太高**破坏了相邻传感器插值**（分辨率丢了）→ 降到 50% 才两头都满足。**"死区/阈值"这类参数天生有上下界，要两个反向测试夹逼**（误报测试 + 精度测试），只做一边一定翻车。

### 6.6 两轮机械不匹配 → **同 PWM 不可能走直，必须双轮独立闭环**

他们实测同 PWM 下左右编码器计数比 **1.11**，据此直接判定"必须独立轮速闭环才能走直"。我们也已知两轮不对称（M2 明显快）。**⇒ 我们的差速层必须建在"左右各一个独立速度环"上，别指望"同一个目标喂两边"能走直。**

### 6.7 环嵌套边界：**快变的参考不能喂给速率环**

他们两次尝试把陀螺 Z 角速度反馈塞进循迹弧线跟随环，**两次都更差**（振荡增大、终止航向更偏）。根因：灰度线的瞬时转向请求变化太快，不能当陀螺速率环的参考。**结论：陀螺 yaw 用于"路线状态决策 + 无标线直行保持"，不进循迹内环**——除非另外生成一个平滑的航向参考。

### 6.8 陀螺零偏之后还要**角速度死区**

他们 400 样本/2 秒静止标定 + **0.25 dps 死区** → 静止 50 秒 yaw 只漂 0.003°。（**IMU 已真机验活 `a808122`**）我们 `attitude.c` 只做了零偏减除、**没有死区**（已核实）→ 残余噪声会被积分成漂移。补法见 §8.2（**可 PC 单测验证，不需要陀螺到货**）。

### 6.9 烧录 verify 的更彻底做法（我们踩过同一个坑）

他们也遇到 CRC helper 不可靠（`checksum mismatch`）→ `tools/flash.ps1` 的做法是：**写前写后显式 reset-halt + 另起一个会话做直接字节比对 + 关掉 OpenOCD work area**（不往目标 RAM 上传 CRC helper）。我们的对策是"不带 verify + 必要时 `mdb` 证伪"——他们的更主动，可作为我们 flash 流程的备选。另：他们用**无线** DAPLink，实测**距离远会导致 1000kHz verify 失败、拉近后连 UART 都变稳**（我们是有线，但"链路质量→降速"这条一致）。

### 6.10 从"人类的 75 句话"里学到的协作法（`01_人类提问序列_提炼.md`）

- **现象回报极短但形态具体**："已居中"/"左侧好了"/"特别稳"/"感觉变差了，我已放回"。**关键的一句是"走直线-偏了-回正到中心-走直线的离散过程"——正是这个形态描述让 agent 找到了 §6.1 的量化根因**。AI 看得到 std，看不到"步进形态"；**人必须描述形态，不只说好/坏**。
- **每轮把车放回同一起点再测** = 初始条件可重复（单变量的物理前提）。
- **人主动解除安全约束提高自主度**："我把轮子架起来了，你以后可以直接发命令让轮子转，不用考虑安全问题"。
