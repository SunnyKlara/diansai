## 0. 一句话评判

**差距不在算法，在架构分层和上层栈。** 算法层我们不弱（位置环精定位、抗 EMI 采样解码、电流链他们都没有），但我们把 **main + 命令解析 + 遥测 + LCD + 探针 + 控制调度 + 差速混合** 全塞进一个 526 行的 `car.c`；他们是 **40 行 main + 13 个各管一件事的模块（~2900 行）**。真正的空白是三件：**航向环、循迹、任务状态机**——而这三件正是车题从"电机会转"变成"能拿分"的部分。

## 2. 五个**真差距**（结构级，逐条给机理与后果）

### 2.1 🔴 单体 `car.c` vs 40 行 main + 分层模块

他们的 `empty.c` 全文就是：

```c
SYSCFG_DL_init();
bsp_motor_init(); bsp_encoder_init(); bsp_gray_init(); bsp_imu_init();
bsp_uart_init(); bsp_user_init(); bsp_timebase_init(); app_bringup_init();
while (1) {
    app_bringup_poll();                      // 高频 drain UART RX
    while (bsp_timebase_take_tick()) {       // 消费所有欠的 1ms tick
        app_bringup_tick_1ms();
        app_bringup_poll();                  // tick 内再 drain 一次
    }
    __WFI();                                 // 睡到下一个中断
}
```

**我们的后果不是"不好看"，是已经付过学费**：`car.c` 里 LCD 逐像素重绘和控制调度住在同一个函数里 → 重绘把主循环拖到 ~5ms/拍 → 报的 RPM 虚高 5×、环退化到 ~4Hz（`4bbaae5` 修的就是这个）。**分层不是洁癖，是把"慢操作"和"控制节拍"在结构上隔开。** 另外 526 行单文件在赛场改参数/加功能时，找代码本身就是成本，而且 `car.c` 是本仓库标记的高冲突文件（多人协作时同时只能一人改）。

### 2.2 🟠 时基模型：**欠账补跑** vs **错过跳过**

- 他们：ISR 每 1ms `g_pendingTicks++`；主循环 `while (take_tick()) { tick_1ms(); }` → 被阻塞 5ms 后，**一次补跑 5 拍**，控制器仍按"每拍固定 1ms"的模型推进，`dt` 恒定。
- 我们：`if ((now - last_spd) >= SPEED_MS*ST_PER_MS)` → 被阻塞时**这一拍直接跳过**，然后用实测 `dt_ms` 修正 scaling（`4bbaae5` 的修法）。**scaling 对了，但控制周期本身在变**（50ms 名义可能实际 60~80ms），等效积分/微分增益随之漂。
- **判定**：两种都能工作，他们的模型对定步长离散控制更严格。我们现在这套已真机达标（`4bbaae5`+`3a4c6f5`），**省赛前不要改时基模型**——但赛后（或上层叠循迹后主循环变忙时）值得换成欠账消费，并保留"pendingTicks 积压量"当**超时探针**（积压 >2 说明主循环喂不上，比现在只能靠"遥测变慢"间接判断强）。

### 2.3 🟠 单位抽象：他们全程与硬件解耦，我们混用

| 量 | 他们 | 我们 |
|---|---|---|
| 电机命令 | **千分比 ‰**（`bsp_motor_set(±1000)`，内部换算成 compare） | **百分比 %**（`motor_set(±100)`，内部换 `MOTOR_PWM_PERIOD`） |
| 轮速 | `count/10ms` 定点 **×100** | RPM **float** |
| 角度/角速度 | **mdeg / mdps** 整数 | 度 / 度每秒 **float** |
| 控制器内部 | 全 int32 定点 | 全 float（M0+ 无 FPU，实测链进 `__aeabi_fmul/fdiv` 软浮点） |

千分比比百分比多一位分辨率，这在**低速段**很关键（我们死区就在 ~10%，百分比只有 10 档可用；千分比有 100 档）。**这条和 §2.5 的 slew、以及"目标量化导致步进"那条坑是同一个主题：分辨率不足会伪装成控制问题。**

### 2.4 🟠 姿态：他们定点+死区+余数，我们 float+互补滤波

他们的 yaw 积分（**值得逐字理解**）：

```c
int32_t yawRate = apply_deadband(gyroMdps[2] - biasMdps[2]);       // 死区 250 mdps
accumulated = g_yawRemainder + yawRate * 5;                        // 5ms
g_yawMdeg   += accumulated / 1000;
g_yawRemainder = accumulated % 1000;                               // ★ 余数留到下一拍
```

**★ 余数保留**是定点积分的命门：不留余数则每拍丢掉 <1mdeg，200Hz 下一分钟能丢掉几度。我们用 float 天然没这个问题，**但一旦按 §2.3 改定点，必须同时抄这条**。
**我们更强的一点**：我们有加速度互补滤波出 pitch/roll，他们只做了 yaw。
**我们缺的一点**：**角速度死区**（他们 0.25 dps → 静止 50 秒只漂 0.003°）。我们只减零偏，残噪会被积分。这条改动 **PC 单测可全验、不在已达标控制链上 = 零回归**，是性价比最高的一个补丁。（⚠️ 2026-07-27 更新：**IMU/陀螺已真机验活**（`a808122` WHOAMI=0x47、accel 模长 0.995g）→ 航向闭环已解阻塞，死区改完可以直接上板验 L5。）

### 2.5 🔴 速度环缺三件：前馈、目标斜坡、双轮

他们的 `update_wheel()`：

```c
err  = target - measured;
ff   = target * FF / 10000;              // FF=8.50 PWM/count，主力项
p    = err * Kp / 10000;                 // Kp=3.00
if (target == 0) { integral = 0; return 0; }   // ★ 停车即清积分
integral += err*Ki/100;  clamp(integral);
out = clamp(ff + p + integral/100, ±400);
target 每拍向请求值走一小步（slew，1 count/拍）
```

我们是纯 PI + 单轮。**后果有实证**：修完时基 5× bug 后我们不得不把 Kp 从 0.03 抬到 0.15（5 倍）"补力气"，本质是**没有前馈、只能让 P/I 去扛工作点**。这和校赛B 立的「C2 前馈到工作点」是同一条铁律——我们在悬浮题守了，在车上漏了。

## 3. 我们**更强**的六处（别被"照搬"冲掉）

1. **编码器抗 EMI 采样解码**：他们用 GPIO 边沿中断；我们实测边沿中断被电机 EMI 打成中断风暴（ISR 计数虚高 ~50×、CPU 吃满），改定时采样后 `I≈4×E` 干净。**我们这条是在更恶劣的电磁环境里挣出来的，不能倒过来学。**
2. **位置闭环 + 精定位**：他们**没有位置环**——"走多远"靠航向环 + 编码器距离阈值（open-loop 距离 + guard）。我们有位置 PD + 死区前馈（按误差方向）+ 到位容差，真机 ±9counts。**做"精确到位/搬运对准"类要求时，我们的能力比他们强一档。**
3. **电流反馈链**：双路 IPROPI + 平均 + mA 定标（他们车上完全没有电流感知）。电流环虽暂缓，但"堵转/过流保护"这类现场保命功能我们有硬件基础。
4. **无头 SWD 调试**：`dbg.ps1`（halt 读 PC/SP/LR、符号断点）。他们全靠 printf + openocd probe。
5. **屏当调试通道**：我们真用 GC9A01 直显编码器计数绕开串口时序（他们有 TFT 但 bring-up 日志里没用它调试）。
6. **记忆/交接体系**：`工程事实SSOT.md` + 坑库 + 归档 + hook。他们靠 `AGENTS.md` + 三个 docs（下面 §4 讲他们这套更强的地方）。

## 5. 他们的**数值**一律不抄（这条要硬守）

`Kp=3.00 / Ki=0.10 / FF=8.50 / 线 PD 0.0035·0.0120 / 弧线 bias −1.66 count·10ms⁻¹ / 灰度 min-max / 死区 50% / 各段 yaw 目标 38.660°·−141.340° / 距离 guard 7500·11000 counts` —— 这些绑死在**他们的**轮径、减速比、编码器线数、车重、10ms 周期、赛道几何、传感器安装高度上。**抄结构、抄判据、抄整定顺序；数值必须我们自己在真机上标。**（校赛B「M4 只抄结构不抄数值」）

## 6. 施工顺序（我们的车题上层栈 · 每步给签名与验收判据）

> 前置：`config.h` 真机复验已通过（`7f41dcc`）；`car_drive_mix` 并发线在做。**每步单变量、达标即回填 `config.h` + commit + 记 `调试日志.md`。**

| 步 | 文件/签名（建议） | 内容 | 验收判据 |
|---|---|---|---|
| **0** | `encoder.c` + `encoder.h` | 加 `uint32_t encoder_invalid(uint8_t ch)`（非法转移计数）+ `encoder_sample(int32_t *total, int32_t *delta, uint32_t *invalid)` 一次性快照（临界区） | 手转两轮 `invalid` 保持 **0**；快照两路一致无撕裂 |
| **1** | `attitude.c` | 陀螺角速度死区（阈值进 `config.h`） | **PC 单测**：静止 60s yaw 漂移 < 阈值（不需硬件） |
| **2** | `control.c`/`car.c` | 速度环加 **FF**（`FF = 目标 / 开环线性增益`，增益在 `config.h`）+ 目标 **slew** + `target==0` 清积分 | 同超调下上升更快、Ki 可减小；松手抗扰不劣化 |
| **3** | 新 `drive.c/.h`：`void drive_set(int16_t v, int16_t w)` | 差速层：`(v,w)` → 左右轮速目标，两轮**各自独立**速度环（他们实测两轮同 PWM 差 1.11 倍 → 同目标喂两边走不直） | 落地走 2m 侧偏可量；`(0,w)` 原地转 |
| **4** | 新 `heading.c/.h`：`void heading_start(int16_t v, int32_t yaw_mdeg)` / `heading_start_pivot(int32_t)` / `void heading_update(int32_t yaw, int32_t gyro_z)` | 航向环：直行/pivot **两套增益** + **最小转向量破静摩擦** + wrap；D 项取陀螺角速度 | 直行段偏航自纠；原地转 N° 到位不来回蹿（**到位判据 = 角度到 AND 角速度连续 N 拍稳**） |
| **5** | `config.h` | 里程标定 `ENC_COUNTS_PER_MM`（现在是 `0.0f` = 未标定） | 走固定距离卷尺对，误差 <5% |
| **6** | 新 `mission.c/.h`：`mission_event_t mission_update_10ms(...)` | 任务状态机：**每段一个状态 + 每段一个 guard（距离/超时/丢线确认）+ 返回事件**；参考 `app_route3.c` 骨架 | 单圈不误触发；每个 guard 都能人为触发到 FAILED |
| **7** | 新 `cmd.c`/`telemetry.c`（把 `car.c` 拆薄） | 命令解析 + 分视图遥测（key=value 单行）+ **运动命令固件侧时限自停**；同步写 `docs/serial_protocol.md` 契约 | 脚本按 key 解析不再因加字段而失效；PC 断开车自停 |

**若题目给了循迹线**：在第 3 步之后插入"传感器阵列 + 现场标定 + 线误差（平方加权 + 双条件 valid）+ 丢线熬 N 帧 + 曲线前馈 + 编码器差阻尼"，参考 `bsp_gray.c` / `app_line_control.c`。**注意我们没有八路灰度硬件**——清单里是光电，通道数少，**加权插值分辨率会低一档**，`curveBias` 前馈与航向环的权重要相应提高。

## 7. 结论（评判，不含客套）

- **算法与硬件层面我们不差，甚至在位置控制、抗 EMI 反馈、电流感知、调试链路上更强。**
- **差距集中在两处**：① **架构**——单体 `car.c` 已经让我们付过一次真机学费（时基被 LCD 拖慢）；② **上层栈**——航向/循迹/任务状态机三件空白，而这三件是车题从"电机会转"到"能拿分"的全部距离。
- **他们真正的过人之处不是代码，是"每一步都有可验收判据 + 每个判据都有 guard + 每次真机都记数字"**。490 行状态机里 5 类 guard、866 行命令层里 20 个遥测视图——这是"跑得完一整圈不翻车"的成本，而不是聪明算法的成本。**我们要补的正是这部分工程量。**
