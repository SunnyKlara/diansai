## 一、验收标准（这块板"做完"= 什么样）

不是竞赛分数，是**一块经真机复验、可复用的底座**：
1. SysConfig pinmap 定版并导出。**纸面定版已完成**（§10 逐脚表按手册 PINCM 排完冲突，`†` 已全部落实为确定 PAxx）；剩下用 SysConfig 工具复核一遍无冲突即可。
2. 四路电源实测达标（尤其 3.3V 真 2A、K230 的 5V 带载不跌）。
3. 七个外设逐个点亮通过（见 G1 的 M1~M7）。
4. 每个外设留一份 driver 积木（`motor_drv8231` / `imu_icm42688` / `esp01s` / `k230_uart` / 显示），三层规范、标注实测。
5. 成板复验全绿 → 毕业成 `library/` 底座。

## 四、kill-criteria + 降级触发表（清醒时写死，疲劳时照执行）

| 触发条件 | 动作 |
|---|---|
| SysConfig 引脚冲突解不开 | 砍外设：4电机→2电机 / 2×ESP→1×ESP / 去掉 MCU 侧 OLED(屏归 K230) |
| 电源板改版来不及 | G1/G2 先用成品 DC-DC 模块飞线顶，主板留焊位，回板后再换自制 |
| K230 的 5V 供不动 | K230 单独一路 5V(独立 DC-DC / 独立电池)，只与 MCU 共地 |
| 某外设点不亮超 timebox 1.5× | 停止线性猜，**加测量**(读寄存器/上逻辑分析仪/加遥测)，按方法论反模式办 |
| 飞线某项始终不过 | 该外设标 ⬇️降级/暂缓，不阻塞其余 M，先把能过的固化 |

## 六、坑库（G1 起每个失败里程碑记一条：现象/根因/解法/下次预防）
- **[M0] 千万别用 `make clean`**：TI 的 GCC makefile 的 clean 会把 SDK 里**共享的 startup 源文件**（`startup_system_files/gcc/startup_mspm0g350x_gcc.c`）删掉，之后所有工程编译报 "startup...No such file"。→ 只删本地 `*.obj/*.out`（VS Code "clean(安全)"任务）；误删就从别的例程复制回来。
- **[M0] 本板烧录用外置 CMSIS-DAP**（非板载 XDS110）→ OpenOCD 用 `interface/cmsis-dap.cfg`；SWD 只接 DIO/CLK/GND 即可，1000kHz 稳。OpenOCD **别边跑边读内存/反复 halt-resume**（会卡），验证以 flash 的 Verified OK + 板载现象为准。
- **[M0] 天猛星板载用户 LED = PB22**（PWR 旁），后续状态指示直接用。
