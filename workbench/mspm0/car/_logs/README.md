# `car/_logs/` —— 真机采集产物的唯一落脚点（本目录内容不入库）

> 建立于 2026-07-28。**在此之前，122 个采集文件（53 csv + 69 txt）与 85 个源码/脚本平铺在 `car/` 根目录**，
> 其中 41 个 `.txt` 没被任何 gitignore 规则盖住 ⇒ `git status` 里 93 条 untracked 有 68 条是噪声（73%），
> 直接妨碍本仓库的「提交即清账」纪律（噪声一多，就看不出哪条是真该提交的资产）。

## 规矩（三条，照做就不会再堆）

1. **脚本的 `-Out` / `-Csv` 若自定义名字，一律写到本目录**（**从 `car/` 跑**，脚本 2026-07-28 已移入 `tools/`）：
   `.\tools\nav_test.ps1 -Turn 90 -Out _logs\brk_w10_j90.txt -Csv _logs\brk_w10_j90.csv`
   不传 `-Out` 时脚本默认写 `<脚本名>_out.txt` 落在 `car/`，那些名字被 `*_out.txt` 规则盖住、不产生
   git 噪声，但仍会让目录变脏 ⇒ **能带 `_logs\` 就带**。
2. **agent shell 的重定向落脚点写 `_scratch\xxx.txt`**（`_scratch*` 天生被忽略），
   **别再用 `_b7.txt` / `_j1.txt` 这种 `_两三个字母.txt`** —— 2026-07-28 实测这样在仓库根积了 25 个。
3. **有意义的数字必须当场 curated 进 [`天猛星主板平台/调试日志.md`](../../../天猛星主板平台/调试日志.md) 的表里。**
   本目录是过程数据，随时可清；**调试日志里的表才是资产**（答辩要用的就是那些表）。

## 现在为什么还留着这些文件（而不是删掉）

`调试日志.md` 多处写着「原始证据：`xxx.csv/.txt`」（`brk_w10_*` / `floor20_*` / `floor30_*` / `w0_*` /
`w10_*`~`w15_*` / `phys_w10_*` / `nav300*` / `straight2` 等）。**文件名没改、只是挪进本目录**，
按文件名仍能搜到。⚠️ 但它们**不在 git 里**（`*.csv` 与本目录整体被忽略）⇒ **换机/重装即蒸发**，
这是本仓库既有的「纸面不 commit 即蒸发」那条坑的又一处 ⇒ 别把它们当长期证据依赖，
**该进调试日志的表就当场进表**。

## 目录布局

| 路径 | 是什么 |
|---|---|
| `_logs/*.csv` | 逐拍原始遥测（`run_log/nav_test/run_straight` 的 `-Csv` 产物） |
| `_logs/*.txt` | 各脚本的三态成绩单（`RESULT: PASS/FAIL/INCONCLUSIVE` 那种） |
| `_logs/shell_dumps/` | agent shell 被吞输出时的重定向转储（原在仓库根的 `_*.txt`，零文档引用、可随时清） |
