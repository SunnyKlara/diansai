> **无陀螺降级（别干等到货）**：直行时轮子不打滑、编码器可信 → **用左右轮位置环同步做"走直 / 走 N mm"**。只有**原地转的角度精度**必须靠陀螺（打滑会骗编码器）；没陀螺时**别磨"转 90°±3°"**，改用几何约束（贴地标 / 撞墙对正 / 循迹路口）更实在。
>
> **第 1 层是主战场**：`02` 说得清楚，车类场景 B/C/D 无论哪个中，**编码器速度环 + 航向闭环 + 循迹**都要。**时间砸这里，命中率 100%。**

## 三、相机这条最大短板，怎么用最少时间补？

真清单的视觉是"摄像头(可带处理器)"——不指定型号。目标是"能用现成模块跑通一条端到端链"：

1. **选一个带处理器、能出结果的摄像头模块**（K230 / OpenMV / 树莓派类都行，清单不锁型号），跑通它的**颜色/形状/编号识别**例程，能稳定出"目标类别 + 中心坐标"。
2. **定死一个 UART 协议**：每帧发 `类别,cx,cy,半径` 一行。MCU 端写解析 + **超时判空**（视觉帧率慢，别当实时）。
3. **做最小闭环 demo**：桌上放个色块/球，车（靠运动）把它怼到画面锚点——**视觉伺服，把像素偏差当误差喂 PID，不用标定相机**。
4. **这条链打通 = 场景 B/C/D 视觉部分全解锁**。

> **性价比排序**：时间紧到只能补一样，补**摄像头出结果 + UART 解析**——它是"从没有到有"的质变（0→1），比电机环的"从好到更好"（1→1.2）优先。
