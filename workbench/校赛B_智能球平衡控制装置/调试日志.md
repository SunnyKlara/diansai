## 2026-06-10  OLED 黑屏定位（SH1106 vs SSD1306）

- 现象：1.3" OLED 烧录后整屏不亮（全黑）。
- 判断：1.3" OLED 多为 SH1106 控制器，原驱动按 SSD1306 初始化。两者电荷泵/升压命令不同——
  SSD1306 用 `0x8D/0x14`，SH1106 用 `0xAD/0x8B`。SH1106 收到 0x8D 不认 → 升压未开 → 整屏黑（全黑而非花屏，正是此特征）。
- 解法：config.h 加 `OLED_IS_SH1106` 开关；oled.c 按宏切换电荷泵命令 + 列地址 +2 偏移。默认 SH1106。
- 待验证：烧录后是否点亮；若仍黑则查 串口是否仍在心跳(MCU是否活)→ 接线(RES/CS/3.3V) → 切回 SSD1306 试。

## 2026-06-10  坑：源文件编码（UTF-8 注释被 armclang 当 GBK 解码）→ 编译崩

- 现象：Keil(AC6/armclang) 编译报 `config.h(84): unexpected character <U+FF0C>`、`character <U+3002> not allowed in identifier`、`cn16 redefinition as int`，并级联到 oled.c(OLED_GRAM 未声明)、hc-sr04.c(capture_start 未声明)、main.c(cn16) 等一堆“未声明/重定义”——**全是假错，根因一个**。
- 根因：本机 armclang 默认按 **GBK(代码页936)** 解码源文件。新加的注释是 **UTF-8 中文**，当某行出现 **中文字符紧贴块注释结束符 `*/`**（如 `…函数。*/`）时，GBK 把中文末字节和 `*` 拼成一个字，**吃掉了 `*`**，`*/` 失效 → 注释没闭合 → 后面全被当代码解析 → 第一个错点之后全部级联崩。
- 为什么别的中文行没崩：是否触发取决于从文件头累积的字节对齐奇偶，且行注释/`*/`独占一行的写法基本安全。原有 config.h 的中文（块注释 `*/` 独占行、`==== 中文 ====` 有 ASCII 垫底）都没事，**只有我新加的内联 `。*/` 那一行崩**。
- 解法：**我新建/编辑的所有参与编译的源码一律 ASCII-only**（config.h 新增段、gc9a01.c/.h、main.c 我改的注释全部英文）。GBK 老文件(oled.c 等)不动（编译器按 GBK 读它们是对的）。
- 下次预防：① 给编译的 .c/.h 写注释只用英文/拼音；② 真要用中文，块注释把 `*/` 单独放一行、行注释结尾别紧跟中文；③ 或在 Keil Misc Controls 加 `-finput-charset=UTF-8` 并确保无 GBK 文件含中文字符串字面量（本仓库混合编码，未采用此法）。
- 结论：纯编码问题，逻辑代码无错。修完 getDiagnostics 0 错，待重新 Build。

## 2026-06-10  GC9A01 黑屏（只亮背光）→ DC/CS/RES 三脚错位

- 现象：编译烧录后**背光亮、供电正常，但屏幕全黑无显示**。

- 结论：纯接线映射问题。下次换屏先核对 DC/CS/RES 物理脚 vs 代码宏，别想当然按"同名脚"。重新 Build+烧录验证。

## 2026-06-10  GC9A01 黑屏根因锁定：SPI1 内核时钟选错 mux（011=I2S_CKIN 而非 per_ck）

- 现象：编译0错、烧录成功、串口心跳正常，但屏全黑、R/G/B 自检不闪；心跳 `LCDto`(SPI 轮询超时计数)=577396 这种巨大固定值 → `spi1_tx` 每个字节都等不到 TXP，SPI1 根本没发数据。
- 静态分析定位（无需上板即可判）：`gc9a01.c::spi1_init()` 里
  `RCC->D2CCIP1R |= (3u << SPI123SEL_Pos)`，注释写「011 = per_ck (HSI)」。
- **根因**：STM32H7（RM0433）`SPI123SEL[2:0]` 编码为
  `000 pll1_q / 001 pll2_p / 010 pll3_p / 011 I2S_CKIN(外部引脚) / 100 per_ck`。
  `011` 是 **I2S_CKIN 外部时钟输入脚**，板上没接 → SPI1 内核时钟 = 0。
  TXP/SR 属内核时钟域，内核时钟=0 则 SR 永不更新 → TXP 永不置位 → 每字节超时 →
  `LCDto` 累加成巨大固定值 → 整屏黑。`per_ck` 正确值是 **100（4u）**，不是 011。
- **per_ck 源确认有效**：`SystemClock_Config` 的 `OscillatorType=RCC_OSCILLATORTYPE_HSE`，
  HAL 不动 HSI → HSI 保持复位默认 ON；`CKPERSEL` 默认 00=HSI → per_ck = HSI 64MHz，活的。
- **解法**：`3u` → `4u`（100 = per_ck）。getDiagnostics 0 错。
- **判读（烧录后看串口）**：
  - LCDto 归零 / 不再暴涨 = SPI1 开始发数据，时钟问题解决。
  - 心跳 dump 里 `CCIP1` 的 [14:12] 应为 100；`SPISR` 应能看到 TXP/EOT 翻转。
  - 屏先用 `GC9A01_FillScreen(LCD_RED)`（或临时开 `LCD_BOOT_SELFTEST=1` 看 R/G/B）当通路判据。
- 下次预防：写寄存器 mux 值时对照 RM 的编码表，别靠记忆/注释；per_ck 在 H7 一律是 100。

## 2026-06-10  GC9A01 黑屏（续）：内核时钟改用 pll1_q（已证 240MHz 在跑）+ 对照参考工程

- 背景：上一版把 SPI123SEL 从 011(I2S_CKIN, 死时钟) 改成 100(per_ck/HSI)，但 per_ck=HSI
  只在「HSI 没被关」时才有效——本工程 SystemClock 只配 HSE，HSI 理论上保持 ON，但无法
  上板前 100% 证明。烧录后仍黑，怀疑 HSI 状态或别处。
- 关键复盘 SystemClock_Config：HSE=25MHz，PLLM=5 PLLN=192 → VCO=960MHz；PLLP=2→SYSCLK=480MHz；
  **PLLQ=4 → pll1_q=240MHz**。而 `HAL_RCC_OscConfig` 配 PLL 时会无条件使能 DIVP1/DIVQ1/DIVR1
  三个输出 → **pll1_q 一定在跑（240MHz）**。即当初「pll1_q 输出没使能=0」的假设是错的，
  pll1_q 从来都是好的；真正的祸首只是 011=I2S_CKIN 那一下。
- **解法（最终）**：SPI123SEL = 000 = pll1_q_ck（`RCC->D2CCIP1R &= ~SPI123SEL`）。
  这是唯一「随 CPU 一起必然在跑」的源，不依赖 HSI。SCK = 240/16(MBR=3) = 15MHz，
  正好对上 config.h 原注释假设。getDiagnostics 0 错。
- 对照参考工程 `参考项目文件/f4_26_1.1`（F4 + HAL_SPI 驱动同款 GC9A01）：
  - **初始化序列逐字节一致** → 我们的 init 字节没问题，排除 init 嫌疑。
  - 差异只在「它用 CubeMX 的 HAL_SPI(hspi2)，我们寄存器级直驱 SPI1」。
  - 它复位：RES=0 100ms → RES=1 100ms（比我们更长更稳，必要时可加长我们的复位延时）。

## 2026-06-10  GC9A01 黑屏【真正根因锁定·用实测寄存器】：MODF 把 MASTER 清掉

- **绝对检测方法**：起 `serial_bridge.ps1` 读板上心跳里的寄存器 dump（之前一直读到的是
  旧 bridge 会话的 22:01 缓存——发现 dump 行根本没出现 = 板上是旧固件）。重启 bridge 后
  读到当前固件(22:18 build)真值：
  ```
  SPISR=00000200  CR1=00001000  CFG1=30000007  CFG2=04020000  CCIP1=00000000  APB2=00001012
  ```
- **解码**：
  - `SPISR bit9 = MODF（模式错误）= 1` → 硬件检测到主模式下 NSS 被拉低。
  - `CFG2 bit22(MASTER)=0`（SSM/COMM 都在）→ **MASTER 被 MODF 自动清零**。
  - `CR1=0x1000`：只有 SSI，SPE/CSTART=0 → SPI 根本没作为主机使能。
  - `CCIP1=0`：SPI123SEL=000=pll1_q → 时钟源没问题（之前的时钟修复已生效，时钟不是病根）。
  - `APB2 bit12=1`：SPI1EN 已开 → 外设时钟没问题。
  - → MASTER 被清 → 不产生 SCK → TXP 永不置位 → 每字节超时 → LCDto 巨大。**这才是从一开始的真根因。**
- **根因**：`spi1_init()` 写顺序错。先 `CR1=0`（SSI=0 → 内部 NSS=低），再写 `CFG2` 置 MASTER=1
  —— 主模式 + NSS 低 = 立即触发 MODF → 硬件自动清 MASTER+SPE；之后才 `CR1|=SSI` 已经晚了。
- **解法**：调换顺序——**先 `CR1=SPI_CR1_SSI`（内部 NSS 拉高），读一次 SR（MODF 清除序列的一半），
  再写 CFG2 置 MASTER**。这样 MASTER 写入时 NSS 已是高，MODF 不触发，MASTER 保持；
  SR 读+CFG2 写也清掉历史残留的 MODF。getDiagnostics 0 错。
- **经验沉淀**：
  1. 寄存器级 SPIv2 主机：SSI/NSS 必须在 MASTER 之前拉高，否则 MODF 吃掉 MASTER。这是 H7 经典坑。
  2. **盲调三次时钟全是错的方向**——真正省时间的是直接读寄存器 dump。教训：有自检遥测就先读真值，别靠推理。
  3. 排查时务必确认「板上跑的就是刚改的固件」：dump 行缺失 / 计数值一字不差 = 旧固件，先解决烧录链路再谈逻辑。
- **待烧录验证（预期）**：CFG2 → 0x04420000(MASTER 置位)、SPISR 不再有 0x200(MODF)、能看到 TXP/EOT 翻转、
  LCDto 归零、上电 R/G/B 自检闪。

## 2026-06-11  战略复盘：根因是测高不可信(被我提采样率搞坏)，非PID

- **用户真机裁决**：闭环时"球的高度一直在变化"，但串口 H=0.0 / RAW≈41 / D=0 卡死不动 → **测高完全没跟随球**。之前在垃圾反馈上调了几小时 PID = 纯浪费。
- **根因定位（关键）**：
  1. 早期 `m4000` 球升顶，H 平滑 0→34、RAW 40→2，**干净可信**——那时 `ULTRA_TRIG_PERIOD_MS=80ms`(原始值)。
  2. 我为"治快对象采样不足"把触发 80→40→20ms。**HC-SR04 在窄管(~45mm)里回波混响/余振 20ms 散不掉**，下一次 ping 撞上残响 → 读数冻结在固定反射(~41cm)或乱跳。**提采样率反而弄坏了唯一可信反馈。**
  3. 叠加风扇高速(7500RPM)声学噪声可能进一步干扰 40kHz 接收。
- **另一真机事实**：四线风扇**冷启动有死区+惯性**——P3900 从静止要 ~3s 才转到 7500RPM(R 慢爬)，且 7500RPM 下球仍可能不被吹起(与早期 4000 吹起矛盾，叠加了测高失真)。→ 控制要让风扇**保持怠速旋转**(min PWM)避免冷启动滞后/静摩擦。
- **战略结论**：先修反馈，再谈控制。
  1. 测高触发回到 **≥60~80ms**(混响散尽)验证 fan-on 下能跟随手持球 ±1cm；不行则换 **ToF 激光(VL53L1X，I2C，抗声学干扰，原始计划的±1cm升级路径)**。
  2. 控制架构改 **串级**：内环转速(tach,快)线性化风速+吸收风扇滞后/非线性；外环高度(慢传感器即可)给定转速。这是"慢传感器+滞后非线性执行器"的标准解，正是原计划的"风速串级"。
  3. 风扇保持怠速旋转，消除冷启动 3s 滞后与静摩擦。
- **教训**：①反馈未验证可信前禁止调 PID；②改采样率这类"传感器物理时序"参数前，先验证传感器在新时序下仍可信；③真机现象与数据矛盾时，第一时间找用户用眼睛裁决，别在数据上空转。

## 2026-06-12 悬浮工况 +3cm 补偿（按评分点统一测量与控制基准）

**问题**：静态 2 点标定几何上准（卡死球 ±0.5cm），但悬浮时显示比真实球底**低 3cm**（显示 20.5 / 尺子 23.5）。反复只调零点治不好，因为静态和悬浮是两种工况。

**根因**：激光未严格在管轴线上。静态手卡球时球被推到激光正下方（垂直测距，准）；悬浮球居中停在气流轴线，激光斜射到球面 → 斜距偏大 → H 偏低。这也解释"不同高度不同误差""碰一下又漂"。

**按评分点定方向**（题目评分表）：
- 定高控制分：评委设 target，量球**真实**高度对比 target；
- 高度测量分：评委看 LCD 对比尺子**真实**高度。
- 两者都要求 `current_height == 真实高度`。控制器把 current_height 拉到 target，LCD 也显示它——只有它=真实，才能同时拿两个分。

**所以是 +3（不是 −3），且连控制一起改**（current_height 本身）。−3 会让显示更低（测量分丢）+ 控制把球推更高（控制分丢），两头崩。

**验证**：target15 悬浮，显示中心 15.0，尺子量真实球底中心 ~15.5（14~17 飘动是 std 未压下，非偏差）→ 真实≈显示≈目标，<1cm。**+3 正确**。

**固化**：`config.h` `TOF_ZERO_CM` 47.81 → **50.81**（=47.81 静态几何 + 3.0 悬浮补偿），scale 仍 1.0331。已编译烧录（0 Error，Verify OK）。代价：底部静止球显示 2.3（非评分区，可接受）。

**经验**：标定要在**评分工况**（悬浮）做，不是静态；显示与控制必须同源同基准；方向之争用"评委量什么"来裁决，不靠手感。机械治本＝把激光对正管轴线（待硬件改）。

**起飞暂态问题(未达 ≤5s,待优化)**：
- 现象：从底启动,球冲到目标附近后又掉回再波动,总收敛 ~15-20s。
- 根因①：四线风扇 **0→6600转冷启动要 ~6s**(实测 RS=7200 满请求下 R 才慢爬),是物理瓶颈。
- 根因②：起飞 boost(hover+600=7200)冲过头,EXIT=10 交接时球带向上速度,过冲后欠冲,来回振荡。
- 试过：mode2 跳过预热→风扇从0硬爬更慢(更糟);预热吹悬停PWM 3919→3s 只爬到6155,球没预浮。
- **待优化方向**：① 预热给满PWM(4100)让风扇最快爬升越过冷启动;② boost 改渐进交接(降boost量到hover+300、EXIT抬到~13)减小过冲;③ 演示策略:先启动让风扇转起来、球稳后再正式计时。
- **稳态不受影响**：稳态配方已验证 10/15/20 三点 ±2cm 100%、±1cm 大部分(std 0.4~0.8)。

## 2026-06-12 起飞预热修复(解决稳态偏高)+ 开机停止定稿

**问题链**：把达标配方固化为开机默认后,为 mode2 内环把 `PWM_RUN_MIN` 3300→3800,但预热也用 g_pwm_min=3800,**预热阶段就把球吹到高位**→投入后球从高处稳定→稳态偏高(实测停 16.8/目标 15)+ 上漂。

**修复**：预热 PWM 与闭环地板解耦,新增 `FAN_PREHEAT_PWM=3300`(~5000转<悬停6600,球不起),预热只暖机(让风机越过冷启动),预热后球仍在底,由 mode2 起飞 boost 从底干净冲到目标。

**验证(COM9,预热3300)**：
- 含暂态(tail0.4)：std 0.94、±1cm 67%、±2cm 100%、中心 15.3
- 纯稳态(tail0.3)：**std 0.56、±1cm 88%、±2cm 100%、中心 15.5(居中)** ✅
- 中心回到 15,不再 16.8 偏高。

**开机策略定稿**：`control_enabled` 开机=0(停止态)。理由：开机自动启动(=1)会让上电即风扇全速→EMI 把 USB(CH340/ST-Link)冲下线→烧录死循环。改回开机停止后,**曲线页按 K3 启动**(→预热→boost→自动悬浮),评委只多按一下 K3,但根治了 EMI 死循环、也更安全(上电不突然吹球)。

**EMI 教训**：CH340 换 USB 口(COM10→COM9)后启动瞬间易丢数据;风扇全速 EMI 是反复掉 USB 的根因,需给 USB 线+风扇线套磁环根治。静态(风扇停)读串口稳定。
