## 2. 进 Docker（所有功能程序都在容器里跑）

出处：`8.4 Docker容器介绍及进入.pdf`（原文："产品出厂的时候已配置进入容器"）

```bash
docker ps -a                                              # 拿容器 ID
docker exec -it -u ubuntu -w /home/ubuntu <ID前4位> /bin/bash
```

退出：`exit`（停止容器）或 **`Ctrl+P+Q`**（退出但容器继续跑）。

跑自己的程序前必须先让出资源，玩完必须还回去：

```bash
~/.stop_ros.sh                                   # 关 APP 自启服务
# ... 跑自己的东西 ...
sudo systemctl restart start_node.service        # 恢复（等蜂鸣器"嘀"一声才算好）
```

## 3. 网络：⭐ 建议直接切 STA，不要用 AP 直连

出处：`19.机器人网络配置课程\01 机器人网络配置课程.pdf`

| 模式 | 含义 | 对我们的影响 |
|---|---|---|
| AP 直连（出厂默认） | Pi 自己开热点 | 🔴 **不通外网** ⇒ Pi 上装不了任何 apt/pip 包；笔记本连它就断网 |
| STA 局域网 | Pi 主动连指定 WiFi | ✅ 两边都有网，能装包、能同时用别的工具 |

**切 STA**（在 Pi 的终端里，不在容器里）：

```bash
cd ~/hiwonder-toolbox/
vim wifi_conf.py
#   HW_WIFI_MODE = 2          # 1=直连  2=局域网  3=直连共享
#   HW_WIFI_STA_SSID / HW_WIFI_STA_PASSWORD  填路由器的名和密码（优先 5G 频段）
sudo systemctl restart wifi.service
```

切回 AP：把这些行**全部注释掉**，再重启 `wifi.service`。

⭐ **一举两得**：让 Pi 连你自备的路由器/手机热点、笔记本也连同一个。那台路由器**正是答疑 Q14「现场不提供 WiFi、自己按通信模式准备」要求你带的**，顺手把图传基础设施立起来了。Q59 说现场**可提供 220V**，路由器供电无忧。
⚠️ Q61：多队同时用 2.4G 图传会撞信道，官方说"技术问题自己解决" ⇒ **优先 5GHz + 能手动选信道的路由器**。

## 4. 图传（第 1 项 6 分）—— 走出厂那套，别自己写取流

**为什么必须走 `ascamera`**：深度相机 Nuwa-HP60C **实测不是标准 UVC**（见文首证据表）⇒ `cv2.VideoCapture` 那条零成本路线不通，只有厂家驱动能出图。

已确认的事实：
- 出厂 web 视频服务由 **`start_node.service`** 拉起，浏览器 **`http://<Pi的IP>:8080/`** 看画面（出处：教程 `11.5 网页实施监控.pdf`）
- `src.zip` 里有 **`peripherals/launch/depth_camera.launch.py`** 与 `peripherals/launch/include/ascamera.launch.py`
- ⚠️ `src.zip` 里**没有** `web_video_server` 的 launch ⇒ 它是系统里已装好的 ROS 包，不属于这套源码

**候选命令（现场核，先按这个试）**：

```bash
# 容器内
ros2 launch peripherals depth_camera.launch.py      # 起相机
# 若 :8080 没画面，再确认 web 视频服务在跑
sudo systemctl restart start_node.service
```

**过判据（Q23 要求实时 + 回放，Q17 只要"清晰即可"）**：
1. 场外笔记本浏览器打开 `:8080` → **实时**看到槽内钢球滚动
2. 🔴 **画面里必须同时有球和槽边刻度，且清晰到能判 ±1cm** —— 判分介质就是这个画面（审题"补 2"）。"能看到球"不够
3. 用 OBS/系统录屏**完整录一次测试并当场回放**（Q16 明确"允许录屏、无需车载端存储"）

⚠️ 分辨率账：深度相机 RGB 实用档是 **640×480@20fps**（1080p 是厂家文档自相矛盾，USB2.0 带宽也装不下）⇒ 640px 覆盖 250mm 摆杆只有 **2.56 px/mm**，一格 0.1cm 刻度约 2.6px，**勉强能读**。若评委看不清，把画面裁到摆杆附近再放大，或换一路普通相机/旧安卓手机做图传（Q12 允许摄像头自带 WiFi 直接当发送端）。

⚠️ **Q62：正式测试期间只允许图传工作** ⇒ 车上 ESP-01S 遥测测试时必须关（调试期照用）。这条同时消掉了自家 2.4G 互相干扰。
⚠️ Q18/说明 6：图传接收端设备**赛后与作品一起封存** ⇒ 别用主力笔记本/私人手机。

## 5. RRC Lite 的外设：用 Pi 侧 Python，别装 MDK

出处：`6.1 初识树莓派扩展板.pdf` + `6.10 串口控制.pdf`

板上 STM32F407VET6 管着：**蜂鸣器 · 2×LED · 2×RGB · 2×按键 · 4 路编码电机 · 4 路 PWM 舵机 · 2 路总线舵机 · QMI8658 IMU · IIC · GPIO**。
Pi 通过 **串口 1 + CRC8 协议**（包格式 `0xAA 0x55 Length Function ID Data Checksum`）指挥它，SDK 出厂就在容器里：

```bash
cd RRCLite_demo/
python3 ros_robot_controller_sdk.py        # 例：board.set_led(0.1,0.9,1,1) / board.set_buzzer(1900,0.05,0.01,1)
```

⇒ **想用它的外设，零编译零烧录。** 只有"改 STM32 固件本身"才需要 MDK，而**赛中不装**，三条理由：
1. 我们不改它 —— 电机/编码器/摆杆舵机全在 MSPM0 上，且那套是真机达标的（里程 0.11% / 转角 0.3° / 方形闭合 12mm）
2. 一改，它管的电机/编码器/IMU 全要重新验证 = 开第二条平台线，撞 D7「84h 内换平台等于自杀」
3. MDK 830MB + CubeMX 467MB + JLink，装 + 建工程 ≥2h

**只保留救砖能力**（不需要 MDK）：出厂固件 `RRCLite小车控制器\4.附录\6.出厂固件\RosRobotControllerLite_ros_250814.hex`，用 `4.附录\3.软件\USB串口下载\FlyMcu`（或 ATK-XISP）经 Type-C 串口一键刷回。

### 明确不要做的
- ❌ 不用 Pi 驱摆杆舵机（`6.9 控制PWM舵机.pdf` 那个例程能做，但控制环必须留在 MSPM0，Linux 非实时 + 串口往返延迟不可控）
- ❌ 声光提示不要只挂 Pi（判分件不该压在 Pi 的启动链后面）；主用 MSPM0，Pi 的蜂鸣器当备份
- ❌ 不用摄像头循迹（说明 5：循迹只能用红外光电模块）
- ❌ 不装雷达（本题无得分点，只增重耗电占地方）

## 6. 四个会咬人的坑

1. 🔴 **串口 1 才是通信口；串口 2 是那个 5V5A 供电输出口、本身没有串口功能**（原文如此）—— 接错会白查半天
2. 🔴 **AP 模式不通外网** ⇒ Pi 上任何 apt/pip 都会失败，装东西前先切 STA
3. ⚠️ 扩展板电源输入 **DC 5~12.6V**；**禁止带电插拔除 USB/HDMI 之外的设备**
4. ⚠️ 跑完自己的程序**必须** `sudo systemctl restart start_node.service`，否则 APP 玩法与按键功能起不来
