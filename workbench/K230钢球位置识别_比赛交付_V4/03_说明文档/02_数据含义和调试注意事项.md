# 数据含义和调试注意事项

## 状态行

```text
BALL_UART_V4 valid=1 raw=+5.181 filtered=+5.163 fps=23.79 uart_hz=23.79 tx=1500 heap_kb=3723 uart_ms_max=2
```

- `valid=1`：当前钢球位置有效。
- `valid=0`：当前没有可靠识别到钢球。
- `raw`：模型中心点换算出的原始厘米位置。
- `filtered`：滤波后发送给控制板的位置。
- `fps`：AI识别频率。
- `uart_hz`：UART数据包发送频率。
- `tx`：累计发送的数据包数量。
- `heap_kb`：K230剩余堆内存。
- `uart_ms_max`：最近一组统计中，单次UART写入的最大耗时。

## 正常范围

- 第一组FPS较低属于模型预热，不作为判断依据。
- 稳定后`fps`约23～24。
- `uart_hz`应与`fps`接近。
- `heap_kb`允许小幅上下波动，但不能不断下降。
- `uart_ms_max`通常约0～5ms。
- 钢球移动时`raw`和`filtered`暂时不同属于滤波过渡。

## 关闭预览后的现象

当前比赛版本默认：

```python
PREVIEW_ENABLE = False
```

右侧预览会停留在最后一张旧图，这是正常现象，不代表程序卡死。判断程序是否运行，应查看：

- 终端状态行是否继续增加`tx`。
- 控制板是否继续收到UART数据。
- K230是否发生重新启动。

## USB断开与程序卡死的区别

USB/IDE断开：

- CanMV提示“已断开连接”。
- 控制板可能仍然持续收到UART数据。
- 通常与Type-C线、USB口、网页USBDBG连接或供电有关。

程序异常：

- 终端出现Traceback。
- 出现`PIPE_BALL_UART_STABLE_V4_STOPPED`。
- 控制板UART同时停止。

底层复位或供电掉电：

- UART停止。
- 重新连接后启动计数从0开始。
- 再次出现传感器初始化和`CALIBRATION_LOADED`。

## 常见故障

### Kmodel file not exist

检查模型是否位于：

```text
/sdcard/steelball/fixed_pipe_480_v1/fixed_pipe_ball_480_v1.kmodel
```

### CALIBRATION_REQUIRED

校准文件不存在。按照画面提示先把钢球放到画面左端，再放到画面右端。看到`CALIBRATION_SAVED`才算成功。

### calibration points are too close

左右两次采集到了几乎同一个位置。重新运行，并确保两次分别紧靠管子的画面左端和画面右端。

### valid=0

控制板应忽略该位置，不得把它当成0cm。检查：

- 钢球是否被手、支架或反光遮挡。
- 钢球是否超出管子可视范围。
- 摄像头是否移动。
- 光照是否与采集数据差异过大。

## 长时间测试

比赛前建议至少连续运行10分钟，并记录：

- 是否出现USB断开。
- 控制板UART是否仍连续。
- `heap_kb`是否稳定。
- `uart_ms_max`是否持续低于约10ms。
- 固定钢球时位置是否稳定。
