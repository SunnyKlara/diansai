# 技能：题目深度分析与选题（做题第一步 · AI 即用 SOP）

> **这是任何一道题的第一步，也是赛场前 2 小时定生死的环节。**
> 用法：把题目 PDF（或文字）丢给 AI，AI 按本 SOP 立即产出"深度分析内容"。
> 赛场多道题时，AI 还要产出"选题分析"，帮我们在 4 天 3 夜里选对那一道。
> 黄金范例：`web/data/problem_briefs.json` 的 `2026-B`（校赛 B），结构/风格照它。

---

## 0. 什么时候用 / 产出什么

| 场景 | 输入 | AI 产出 |
|---|---|---|
| 训练（单题） | 一道题 PDF | **① 单题深度分析**（叙事 + 多方案穿插）|
| 赛场（多题，6~8 道） | 全部题 PDF | 每道先出**①**（快速版），再出 **② 选题分析**（决策矩阵 + 推荐）|

**铁律**：深度分析先行，不审完不动手；赛场限时——每道题快速版分析 ≤ 15 分钟，全部选题决策 ≤ 开赛后 2 小时。

## 1. 产出① 单题深度分析 —— 既要叙事，又要夹方案

**风格**（基准 = 57 万字 narratives，但要**比它更强**）：高中物理水平能看懂；从真实场景讲起；短句；不堆未解释的术语；**读着读着就懂了，还顺手知道怎么做**。

**"无敌好"的硬标准 = 五层，缺一层不合格**（57 万字只强在 L1-L2，我们要补齐 L3-L5 的工程硬功夫）：

| 层 | 让读者… | 必含内容 | 57万字 |
|---|---|---|---|
| **L1 动机** | 想做这题 | 真实生活场景开篇 + 工业应用表 + 出题人三层意图 + 控制/题型系谱 | ✅强 |
| **L2 本质** | 看懂这题 | 物理/数学本质 + 公式拆解(带数字) + **点破真假难点**(往往不是表面那个) + 每个难点当场给解法方向 | ✅强 |
| **L3 方案** | 知道怎么做 | 关键量算一笔账 → **指标拆解表**(容差/隐含约束/分数) → **误差预算**(量化每个误差源+RSS+裕量) → **多方案打分**(每个决策点2~3方案5维表+推荐+兜底) → 软件架构(分层+状态机+时序) → 硬件难点 | ❌**新增** |
| **L4 拿分** | 做得比别人好 | **评分预估**(保底/期望/冲刺分项) + 高频坑+解法表 + **降级方案**(翻车救命) + 评委隐性加分点 | ❌**新增** |
| **L5 关联** | 系统越用越强 | 题型判定 + 同型历史题链接(查`index/题型图谱.json`,具体到题号+能复用啥) + 可复用积木清单 + 真实开源参考(找到补,带出处) | ❌**新增** |

**方案分析必须穿插在叙事里**（不是单独堆表格）：L2 点难点时当场给解法方向，L3 用小表格打分选型。

**配套结构化字段**（喂网页右栏 / AI 速查，照 problem_briefs 七字段）：
`oneline` · `why` · `tasks`[{title,score}] · `metrics`[{name,spec,plain}] · `traps`[{what,fix}] · `checklist` · `narrative`(上面 L1~L5 正文)。

> **合格判据（双重）**：① 读完不仅"懂这题干嘛"，还能"说出有哪几条路、推荐走哪条、为什么、翻车怎么救"；② 五层齐全、L3 有量化(误差预算+评分预估)。做不到 = 不合格，重写。
>
> **标准会进化**：每做完一题，复盘"这次分析哪还能更好"→ 回填本表。当前旗舰范例 = **校赛 B**（`web/data/narratives/2026-B.md`），新题对标它。

## 1.5 自动流程：PDF 进 → 分析出 → 上网页（AI 照此执行）

用户发 PDF + 说"这是题目"时，AI 立即按此 pipeline 跑，不用再问：

```
① 提取 PDF 文本：python 调 pypdf 读出题目原件文字
② 判题型：查 index/题型图谱.json → 拉同型历史案例 + 可复用积木 + 已知坑
③ 按 L1~L5 rubric 写深度分析（叙事夹方案），同时填七字段
④ 落地（单一事实源）：
     - 源：web/data/narratives/<year>-<problem>.md（题号用 ASCII，如 2026-B）
     - 题目原件：cases/<年>/<题>/00_题目原件.md
     - PDF：放 赛题/原件/<年>/<题名>.pdf
     - problems.json 加一条(path/origin/pdf)；problem_briefs.json 补七字段
     - 跑 web/tools/sync_narratives.py <key> 把 .md 灌入 briefs.narrative
     - index/题型图谱.json 把本题挂到对应题型的"适用题"
⑤ 网页验证：无痕窗口开 /web/ → 该题左栏PDF + 右栏故事解读都正常
⑥ [赛场多题] 每题出快速版后，追加选题决策矩阵(见 §2)
```

避坑（来自 `web/网页调试记录.md`）：题号用 ASCII；PDF 放 `赛题/原件/`；改了看不到先疑缓存、用无痕验证。

## 2. 产出② 选题分析 —— 赛场只能选一道

> 详细打分框架见 `skills/选题决策流程.md`，本节是它的"AI 输出规范"。


AI 对每道候选题出**一张选题决策矩阵**（在各题①分析完成后）：

| 维度 | 权重 | 题A | 题B | … |
|---|---|---|---|---|
| 基本要求有把握做完（底线，最重要）| ×3 | | | |
| 手头有现成硬件/模块 | ×2 | | | |
| 有相关代码/经验/同型历史题可抄 | ×2 | | | |
| 发挥部分能做 ≥1 项 | ×2 | | | |
| 报告好写 / 评分点清晰 | ×1 | | | |
| **加权总分** | | | | |

AI 给出**明确推荐 + 理由 + 风险提示**，格式：
> **推荐选「题X」**：基本要求我们有 XX 把握；复用 20XX-X 的 YY；最大风险是 ZZ（缓解：…）。
> **不建议「题Y」**：虽发挥分诱人，但 基本要求卡在 WW，做不完=白忙。

**选题铁律**：① 基本要求做不完的题一票否决；② 不被发挥高分诱惑；③ 选最熟方向；④ 2h 内定；⑤ 选定不换题。

## 3. AI 执行步骤（时间紧时照此跑）

1. 读题 PDF → 抄全部指标与约束（含隐含约束）。
2. 查 `index/题型图谱.json` 定题型 → 拉同型历史案例 + 可复用积木 + 已知坑。
3. 按 §1 顺序写①（叙事夹方案）；填七字段。
4. 多题场景：每道①出快速版后，按 §2 出选题矩阵 + 推荐。
5. 产物落位：训练→`cases/<年>/<题>/00_深度审题…` + 同步 `web/data/problem_briefs.json`；赛场→直接对话输出，选定后再落工程。

---

## 4. 风格铁律（别写成自嗨）

- ✅ 真实场景开头、短句、白话、有数字。
- ✅ 方案必须"多选一 + 给理由"，不能只有一种思路。
- ✅ 联想到的同型题要**具体到题号 + 能复用什么**。
- ❌ 不堆术语不解释；不写"国二保底"之类口号；不下未经验证的"已完成/可复刻"结论。
- ⚠️ 一切方案在上真机前都是"待验证"，分析里如实标注。
