> **这是什么**：把我们已有的东西（steering 记忆体系 / skills 01–04 / SSOT / 各类脚本）+ 从 [mspm0-skill](https://github.com/mc3545dada/mspm0-skill) 与 [2024hVibe](https://github.com/mc3545dada/2024hVibe) 学到的架构，**组织成一套可执行的协作操作系统**。
> **它不重复任何下游文档**：审题看 `01_`，赛场排程看 `02_`，报告答辩看 `03_`，现场速查看 `04_`，行为纪律看 `.kiro/steering/`，工程事实看 `工程事实SSOT.md`。**本文只讲"这些东西怎么咬合、缺哪一块、按什么判据取舍"。**
> **状态图例**：✅ 已在用（有真机/PC 证据） · 🟡 部分 · ⬜ 待建（设计已给，未实施）
> 建立于 2026-07-27，源自对范本工程的四轮深挖与架构级反思（留痕见 `knowledge/决策与交接归档.md` 2026-07-27(三)~(九)）。

## 0. 中心命题

**电赛 + AI 协作的核心难题不是"不会做"，是"错误是隐形的"。**

嵌入式的反馈链有五个断点，每个断点都能让"看起来对"通过：

```
代码写对 ≠ 配置生成对 ≠ 编译链接过 ≠ 烧录成功 ≠ 芯片在跑新固件 ≠ 硬件行为对
```

LLM 天生产出"合理的文本"，在这条链上**合理但错误的东西直到板子出问题才暴露，且暴露时你不知道是哪一层撒的谎**。所以整套体系的目标只有一个：

> **让每一个断言都能被一条可执行命令当场取证；让每一个"不确定"都有一个明确的名字。**

其余所有条款都是这句话的推论。

## 1. 四层结构

### 层 0 · 真值层（每类事实唯一落点 + 复验命令）

| 事实类别 | 唯一真值源 | 状态 |
|---|---|---|
| 引脚 / 已标定参数 / 环境命令 / 禁忌 | [`工程事实SSOT.md`](../.kiro/steering/工程事实SSOT.md) | ✅ |
| 控制参数当前值 | `workbench/mspm0/car/config.h` | ✅ |
| 「某事做没做完 / 提没提交」 | **git**（`log`/`status`/tag） | ✅ |
| 「现在进行到哪 + 下一步 + 阻塞」 | `CONTINUATION_GUIDE.md` | ✅ |
| 可迁移的技术坑 | `knowledge/跨题坑库.md` | ✅ |
| 决策史 / 被推翻的方案 | `knowledge/决策与交接归档.md` | ✅ |
| 芯片上跑的是哪版固件 | 固件 boot 打印的 `build <DATE> <TIME>` | ✅ |

⬜ **待补的一列：复验命令。** 现状是"记了事实、没记怎么当场再验一次"。例：SSOT 写着「电流通道 M1=`PA26`（实测映射，与 syscfg 假设相反）」，但复验方法（`m5 DUAL` 独立驱动看哪路读数动）只存在于归档里。**格式建议**：

```markdown
| 事实 | 值 | 复验命令 | 校验于 |
|---|---|---|---|
| 电流通道映射 | M1=PA26 / M2=PA27 | `.\xtalk.ps1`（m5 独立驱动，看哪路 I 动） | 2026-07-26 |
| ENC_CPR | 见 config.h | 手转 8 圈读增量 ÷8 | 2026-07-25 |
```

⬜ **验证标注升级：二元 → 六级。** 现在只有"待验证 / 已验证"，装不下"参数纯搬移·编译过·待真机复验"这类真实状态（`27227f6` 就卡在这）。改成分级，**低级不得冒充高级**：

```
L1 源码/静态检查 → L2 SysConfig 生成 → L3 编译链接 → L4 烧录成功
→ L5 板上行为（串口/现象）→ L6 仪器观测（示波器/逻辑分析仪/卷尺）
```

写法：`速度环 Kp=0.15 [L5 实测 std~3%]`、`陀螺死区 [L3 编译过 + PC 单测 PASS，L5 待上板]`。**答辩时"哪一级验证过"比"验证过"可信得多。**

### 层 1 · 约束层（三级下沉，能下沉就下沉）

**可靠性阶梯**：`规则文本 < 工具行为 < 硬机制`

| 级别 | 载体 | 为什么更可靠 | 我们的状态 |
|---|---|---|---|
| ① 规则文本 | `.kiro/steering/*.md` | 靠执行体自觉；会被注意力预算/上下文压缩/"这次特殊"稀释 | ✅ 4 份 |
| ② 工具行为 | 脚本里"根本没有这个功能"或"此情况必然失败" | 代码不会忘 | 🟡 部分（`dbg.ps1` 不做自动救砖） |
| ③ 硬机制 | `.kiro/hooks` PreToolUse **调用前真拦 + ask** | 不依赖自觉 | ⬜ **完全没用** |

⬜ **最未兑现的杠杆 = ③**。参考对象**没有这一层**，我们有却没用。血泪禁忌目前全停在①，候选下沉清单：

| 禁忌（现在只是文字） | 下沉方式 |
|---|---|
| 绝不 `make clean`（会删 SDK 共享 startup） | PreToolUse 匹配 `make\s+clean` → ask |
| 绝不连续快烧 / 中途打断 program | PreToolUse 匹配 flash 类命令 + 检查上次时间戳 < N 秒 → ask |
| 烧录别放进会超时 kill 的命令 | 脚本内固化长 timeout（②级）+ hook 提示（③级） |
| 别把循环 spawn openocd 的脚本留后台 | Stop hook 检查残留后台进程 → 提示 |

**规则层写什么的判据（这条能省下大量注意力）**：

- **能从 SDK / 数据手册 / 生成文件查到的 → 不写进规则层**，给检索工具（`sdk_find.ps1`）。
- **查不到的才必须写**：板级土规矩（某板哪些脚特殊，只存在于 wiki 图片里）、真机实测数值、失败模式与判据、被否决的方向。

### 层 2 · 工具层（每个断点一条取证命令，统一三态）

**取证矩阵**（症状 → 用哪条命令取证，而不是靠猜）：

| 症状 | 先取证（不是先改代码） | 工具 | 状态 |
|---|---|---|---|
| 「改了没效果」 | 芯片上是不是新固件 | boot 打印 `build DATE TIME` | ✅ |
| 「烧不进 / 连不上」 | 探针在不在 → 芯片活不活 → 是不是锁死 | `dbg.ps1 probe`；串口是否仍有遥测；`Could not find MEM-AP` | 🟡（真机 halt 待验） |
| 「烧进去了没反应 / 屏黑」 | PC 落在哪（app / BOOTROM / HardFault） | `dbg.ps1 registers` | ⬜ 真机待验 |
| 「反馈可疑」 | 反馈健康门 | ⬜ `encoder_invalid` 计数（待加） | ⬜ |
| 「改了 .syscfg」 | 生成是否干净（warning ≠ clean） | `syscfg_check.ps1` | ✅ L2 |
| 「要加新外设」 | 官方例程怎么配 | `sdk_find.ps1 <MODULE>` | ✅ |
| 「环整不动」 | 反馈的**幅值/符号/线性/分辨率**先各查一遍 | 开环标定 + `tune_step.ps1` | ✅ L5 |
| 「校验失败」 | 是不是假警报 | `mdb` 直读比对 | ✅ L5 |

⬜ **三态约定（所有真机脚本统一）**：

```
最后一行固定输出： RESULT=PASS|FAIL|INCONCLUSIVE  <一句话理由>
退出码：           0        1      2
```

`INCONCLUSIVE` 是关键——**它把"我没能测"和"测了没问题"分开**。缺这一态我们真踩过：给输入脚开内部上拉后静止读到 `1`，一度当成"信号线接好了"（其实浮空也读 1）。

**命令即测试用例**（范本 866 行命令层的真正含义）：每条串口命令都是**一个带时限、可重复、结果可量化的最小实验**。这是"5 分钟一个迭代"的前提——实验成本被压到"发一行命令"。
🔴 **我们缺的第一项是安全**：`grep` 证实固件**没有任何运动超时自停**，停车全靠 PC 端补发 `z`。落地前必须补（进模式设 `deadline`，超时回 IDLE 并打印原因）。

### 层 3 · 记忆层（规则与事实分离 + 交接）

**收敛信号**：范本是「通用 skill + 项目 `AGENTS.md`」，我们是「steering + `工程事实SSOT`」——两边独立演化出**同构的二层分离**，说明这类协作的稳定解就是**规则与事实分开**。

我们的记忆三件套 ✅：`CONTINUATION_GUIDE`（现在+下一步）/ `跨题坑库`（可迁移坑，append-only）/ `决策与交接归档`（历史与被推翻的决策）+ 三个 hook。**比范本强**（他靠人读四份文档）。

⬜ **缺项：项目事实卡模板**。SSOT 是**天猛星专用**的；赛场换题、换板、换平台时没有"5 分钟填完就能让 AI 接手"的项目层模板。开赛第一小时这是真实成本。模板（照抄即用，约 40 行）：

```markdown
# 项目事实卡 · <题号-题名>（填完即可让 AI 接手）
## 环境
MCU / 封装 / SDK 路径 / 编译器路径 / SysConfig 路径 / 构建命令 / 烧录命令 / 探针型号 / 串口号+波特率
## 工程
工程路径（**必须全 ASCII**）/ 配置真值源（.syscfg）/ 生成头位置 / 参数集中处（config.h）/ 入口文件
## 硬件（每条标 L1~L6 验证级别）
电源与母线电压 / 执行器型号+额定电压 / 传感器型号+输出电平+接法 / 引脚表（含"已实车验证/工程已配置/仅预留"三档）
## 安全
上电默认态 / 急停方式 / 运动命令时限 / 已知禁忌（本板特有）
## 里程碑阶梯（每级带验收判据 + timebox）
M1 … M5
## 当前状态
在攻哪一级 / 阻塞 / 下一步
```

## 2. 三方分工（人 / AI / 工具，各有不可替代项）

| 角色 | 不可替代的能力 | 不该做的事 |
|---|---|---|
| **AI** | 驱动工具链、量化指标（avg/std/ptp/上升时间）、解释机理、**自我翻案** | 一轮改多个变量；无数据硬猜；嘴硬维护错判 |
| **人** | **形态描述**（台阶/高频抖/慢漂——AI 只看得到 std）、物理动作、方向拍板、器材事实 | 替 AI 算数值；跳步同时改多项 |
| **工具** | 硬约束、取证、**三态结论** | 在不确定时返回"成功" |

**范式天花板（必须承认）**：**AI 能自动化"到烧录为止"，板上行为永远人在环。** 范本把"人的口令协议"做得极细，不是风格，是这条天花板的必然结果。

⬜ **协议化（成本 0，但必须固化成纪律）**：凡需要人配合的真机测试，AI 发起时必须给齐四件——**① 放置/体位 ② 保持要求 ③ 开始口令 ④ 结束口令**，并**先留基线秒数**；被测状态若静默（电机锁着不转）要显式说明"窗口是活的"。
反例代价：位置环手推刚度测试**连续 3 次拿不到干净数据**。范本里人类 75 句有 20+ 句只是 `已居中` / `左侧好了` / `已放回`——**人的负担被压到最低，实验却完全可复现。**

## 3. 数字刻度（排时间用，来自实测统计）

来自范本会话记录（4245 条）的统计，**是"有平台、有工具链"前提下的刻度**：

| 刻度 | 值 | 对我们的含义 |
|---|---|---|
| 一道车题全程 | **13 个活跃小时**（跨 3 天） | 赛场 T+0~T+72 的工作量参考 |
| 跑完前 3 个要求 | **约 5 小时** | 剩下时间应花在稳定性与交付 |
| 每个里程碑 | **20~40 分钟** | ⬜ **timebox 纪律**：超 40 分钟不达标 → 降级或换打法 |
| 一个真机迭代（改码→编译→烧录→串口验） | **烧录间隔中位 5.1 分钟** | 我们受 brick 风险约束**不能这么连烧** → 必须把在线调参比例做得更高 |
| 在线调参 : 重烧 | **3.4 : 1** | 运行时命令（`m/t/p/i/d/w/e/f`）是主战场，继续加厚 |
| 编译 : 烧录 | **1.3 : 1** | 改动颗粒要小，不攒批 |
| 上下文压缩 | 13 小时内 **3 次** | 交接体系不是洁癖，是必需品 |

## 4. 失败分类法（把散落的判据统一成一张表）

**铁律：先分类，再动手。不该重试的类别硬重试，正是把小故障升级成 brick 的那一步。**

| 类别 | 典型信号 | 对策 | **禁止** |
|---|---|---|---|
| **探针/链路** | `unable to find a matching CMSIS-DAP`、`CMD_CONNECT failed`、超时 | 查 USB/线/换物理口；降速梯（500→1000）；确认无其它进程抢探针 | 改代码；硬重试（会拖死 DAP USB） |
| **芯片锁死** | `Could not find MEM-AP`（但能读 DPIDR） | 人工救砖 `unbrick_flash.ps1`（解锁+烧录同会话，响铃停点 RST） | 让脚本自动 mass-erase |
| **固件没跑起来** | 串口静默；`registers` 显示 PC 在 BOOTROM `0x0100_xxxx` | **物理按 RST**（MSPM0 软复位起不来） | 反复重烧 |
| **反馈脏** | PWM 正而速度负；I≫E；该忙时遥测反而变慢；`invalid`≠0 | 先修反馈（符号/采样时基/分辨率/健康门），**别碰 PID** | 调增益 |
| **量化不足** | 低频摆、台阶式纠正，对增益不敏感 | 提目标分辨率（定点化） | 继续调增益 |
| **控制器** | 反馈四项（幅值/符号/线性/分辨率）都干净后仍不好 | 才允许整定：**先 D → 再 P → 最后弱 I**；前馈扛工作点 | 在脏反馈上整定 |

## 5. 执行循环（赛中一天怎么过）

```
审题(01_ SOP，不可跳) → 破局作战地图(01_) → 填项目事实卡(层3 模板)
  ↓
里程碑阶梯，每级：
   ① 开工前明确验收判据与 timebox(20~40min)
   ② 单变量改一处 → 编译 → 烧录 → 物理 RST
   ③ 取证（层2 矩阵）→ 定量指标 → 与上一轮对账
   ④ 达标 → 回填 config.h + commit + 打 tag（带数据）；日志边做边写
   ⑤ 超 timebox 未达标 → 降级(04_ 降级清单) 或换打法，并 commit 记一笔原因
  ↓
收官：报告(03_) + 赛后复盘(04_) + 可迁移坑回补 knowledge/
```

**已验证的三条硬纪律**（校赛B + 天猛星真机代价换来的）：**鲁棒方案必须是默认上场态**（别留在开关后面）；**达标即锁死回填源码**（别只活在串口窗口）；**选题先看物理地板**（估「控制器完美时的误差极限」，贴墙就换打法）。

## 6. ⬜ 缺失件清单（本总纲的行动面，按"不做会怎样"排）

| # | 缺什么 | 不做会怎样 | 成本 | 需拍板 |
|---|---|---|---|---|
| 1 | **运动命令固件侧时限自停** | 🔴 车落地后脚本崩/串口断 = 车一直跑（撞墙/冲出去） | 小（纯增量） | 由哪条线改 |
| 2 | **三条纪律入 steering**（协议化 / 日志边做边写 / timebox+达标即 tag） | 纪律留在待办里 = 永远不执行 | 0 | ✅ 要（改 always 层） |
| 3 | **禁忌下沉到 hook 硬机制** | 血泪禁忌全靠自觉，压缩后就忘 | 中 | ✅ 要 |
| 4 | **脚本统一三态 + 退出码** | 「没测到」被当「没问题」 | 中 | 否 |
| 5 | **SSOT 加"复验命令"列 + 六级验证标注** | 事实指向历史而非可执行命令；状态装不下 | 小 | 否 |
| 6 | **项目事实卡模板落地** | 换题/换板第一小时全靠口头交接 | 小 | 否 |
| 7 | **反馈健康门**（`encoder_invalid` 计数） | "反馈干不干净"永远只能吵间接证据 | 小 | 否 |

> 本清单与**车题施工序**（`workbench/天猛星主板平台/02_逐层差距评判_对标2024H.md` §6）是两条线：那条是"这道题要做的功能"，本清单是"体系本身的缺件"。**别混排，混排会让体系件永远被功能件挤掉。**
