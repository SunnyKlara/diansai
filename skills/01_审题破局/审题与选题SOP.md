# 审题与选题 SOP（做题第一步 · 合并:深度审题 + 选题决策 + 多角度评审）

> **任何一道题的第一步,赛场前 2 小时定生死。** 把题目 PDF 丢给 AI,按本 SOP 产出深度分析;
> 赛场多题再出选题决策;做完用多角度评审自检。黄金范例:`web/data/narratives/2026-B.md`。
> **铁律:审完才动手;赛场每题快速版 ≤15 分钟,选题决策 ≤ 开赛后 2 小时。**

---

# A. 深度审题（单题分析)

## A.0 产出什么
- 训练(单题):**深度分析**(叙事 + 多方案穿插)。
- 赛场(6~8题):每题先快速版分析,再出选题决策(见 B 部分)。

## A.1 叙事三铁律(违反不合格)
- **多用生活化比喻**:每个抽象概念配一个生活类比(如"微分先行=开车提前松油门")。
- **叙事连贯一条主线**:L1→L5 像讲故事顺下来,段间有承接。
- **先问后答**:抛"为什么…?"再解答,带读者想。

## A.2 五层 rubric（缺一层不合格）

| 层 | 让读者… | 必含内容 |
|---|---|---|
| **L1 动机** | 想做这题 | 真实场景开篇 + 工业应用 + 出题人意图 + 题型系谱 |
| **L2 本质** | 看懂这题 | 物理/数学本质 + 公式拆解(带数字) + **点破真假难点**(往往不是表面那个) + 每个难点当场给解法方向 |
| **L3 方案** | 知道怎么做 | 关键量算一笔账 → 指标拆解表(容差/隐含约束/分数) → **误差预算**(量化每误差源+RSS+裕量) → **多方案5维打分**(每决策点2~3方案+推荐+兜底) → 软件架构(分层+状态机) → 硬件难点 |
| **L4 拿分** | 做得比别人好 | 评分预估(保底/期望/冲刺) + 高频坑+解法 + **降级方案** + 评委隐性加分点 |
| **L5 关联** | 系统越用越强 | 题型判定 + 同型题思路(见 `web/data/narratives/`) + 可复用积木(`library/`) + 真实开源参考(带出处) |

> **方案穿插在叙事里**:L2 点难点当场给方向,L3 用小表格打分选型。缺 L3 量化(误差预算+评分预估)= 不合格。

## A.3 PDF 进 → 分析出 pipeline(AI 照跑)
```
① 提取 PDF 文本(pypdf),抄全部指标与隐含约束
② 判题型:凭经验 + web/data/narratives/ 同型题 → 方法起点 + 可复用积木(library/) + 已知坑
③ 按 L1~L5 写深度分析(叙事夹方案)
④ 落地:workbench/ 下新建 2026-<题号ASCII>_<题名>/,分析写进 00_深度审题与方案论证.md;PDF 放 赛题/原件/2026/
⑤ (可选上网页) web/data/narratives/<年>-<题号>.md + 跑 web/tools/sync_narratives.py
```

## A.4 风格铁律
- ✅ 真实场景开头、短句、白话、有数字;方案"多选一+给理由";同型题具体到"能复用什么"。
- ❌ 不堆术语、不喊"国二保底"口号、**不下未验证的"已完成/可复刻"结论**。上真机前一切标"待验证"。

# B. 选题决策（赛场多题,只能选一道）

## B.1 流程(开赛前 2 小时)
```
拿到 6~8 道题 → 全队 30 分钟扫一遍 → 排除明显不擅长的
→ 剩 2~3 道各深入 30 分钟(每道出 A 部分快速版)
→ 打分矩阵比较 → 选定(≤ 开赛后 2 小时) → 分工
```

## B.2 选题决策矩阵

| 维度 | 权重 | 题A | 题B | 题C |
|---|---|---|---|---|
| 基本要求有把握做完(底线,最重要) | ×3 | | | |
| 手头有现成硬件/模块 | ×2 | | | |
| 有相关代码/经验/同型历史题可抄 | ×2 | | | |
| 发挥部分能做 ≥1 项 | ×2 | | | |
| 报告好写/评分点清晰 | ×1 | | | |
| **加权总分** | | | | |

**输出**:明确推荐 + 理由 + 风险提示。格式:「推荐题X:基本要求 XX 把握;复用 YY;最大风险 ZZ(缓解:…)」。

## B.3 选题铁律
① 基本要求做不完的题一票否决;② 不被发挥高分诱惑;③ 选最熟方向;④ 2h 内定;⑤ 选定不换题。

## B.4 各方向 30 秒判断(全打勾才选)
- **电源题**:有全/半桥逆变经验? 有 MOSFET 驱动板? 会 SPWM/SVPWM? 有功率分析仪?
- **仪表题**:会 FFT? 有高速 ADC? 会信号调理?
- **智能车**:有底盘? 会循迹 PID? 有摄像头/OpenMV?(接校赛B控制经验)
- **无人机**:有飞控+飞行调试经验? 有视觉方案? → 没有**绝对别选**。

# C. 多角度评审自检（做完后逐角色过一遍）

每道题做完,用 5 个角色的清单审查,不通过就回去改。

**① 评委(定分数)**:基本要求每项都有测试数据? 每项指标标"达标/未达标"? 报告结构全(摘要→方案→理论→电路→测试→总结)? 图表有编号? 测试点有标识?
> 血泪扣分点:没摘要(-2~3)、没方案比较(-2~4)、测试数据不全(-3~5)、图表无编号(-1~2)、要评委自己接线(印象分)。

**② 资深工程师(技术深度)**:每个技术决策有"为什么选/为什么不选其他"? 有误差预算表(量化)? 代码模块化? 边界情况有处理? 会被追问"ADC采样率为何这值?奈奎斯特够吗?""PID参数怎么整定的,有理论依据吗?"

**③ 带队老师(可复现)**:从零到完成步骤清晰? BOM 能一次采购齐? 调试顺序合理(先易后难)? 标了"容易卡住的地方+解法"?

**④ 参赛学生(实用)**:代码有注释? 有引脚定义表? 有配置说明? 有调试步骤? 有"XXX不工作怎么办"?

**⑤ 系统架构师(系统思维)**:有架构图(模块+接口+数据流)? 模块低耦合? 有状态机图? 资源有预算? 异常有处理(过压/看门狗/恢复)?

**终极标准**:评委给满分 + 工程师认可方案 + 老师能直接用 + 学生照着能做 + 架构师说设计合理。
